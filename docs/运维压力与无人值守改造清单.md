# 运维压力与无人值守改造清单

> 日期：2026-11-07
> 背景：实机跑通后暴露出一批「必须有人盯着」的问题。这些不是理论风险，是实测遇到的。
> 目标：让客户端在客户电脑上 7×24 自己活着，不需要我们远程连进去。

---

## 零、当前实际发生过的故障

| 时间 | 现象 | 根因 | 是否可自愈 |
|---|---|---|---|
| 2026-11-07 23:31 | 两个 `autopilot.py --watch` 同时跑 | 没有单实例锁 | ❌ 必须人工发现 |
| 2026-11-07 23:32 | 发送失败「抢不到前台」 | 用户在前台用 VS Code | ❌ 只重试 2 次就放弃 |
| 2026-11-07 23:32 | 发送失败「焦点未落在输入框」 | 输入框比例点打偏 | ❌ 同上 |
| 2026-11-07 23:31 | 企微掉登录，程序静默不发 | 只在看板显示红条 | ❌ 需人主动看 |
| 2026-11-07 23:25 | 回复成功但日志写「未回读」 | 回读时机早于 WAL 落盘 | ✅ 下轮自然修正 |

**共同点：全部依赖人发现、人处理。** 这就是运维压力的来源。

## 一、问题清单（按处理优先级）

### P0：不做会直接导致「客户没人管」

#### 1. 没有单实例锁

**现象**：两个进程同时运行，同时抢前台、同时发消息 → 客户收到两条重复回复。

**实测**：2026-11-07 23:31 出现过一次，两个 PID 都是 `autopilot.py --watch`。

**修法**：命名互斥体（Windows `CreateMutex` / Python `msvcrt`），第二个进程直接退出并提示。

```python
# 伪代码
mutex = CreateMutexW(None, True, "Global\\CityRecruitAgent")
if GetLastError() == ERROR_ALREADY_EXISTS:
    log("已有实例在运行，本进程退出")
    return 0
```

**验收**：连点两次 `.bat`，第二个窗口打印「已有实例在运行」后退出。

---

#### 2. 没有 watchdog

**现象**：进程崩了就是没了，没人知道，直到客户投诉。

**修法**：主循环包一层，异常退出后自动重启并计数。

```python
# 伪代码
while True:
    try:
        run_once()
    except Exception:
        log(traceback.format_exc())
        restarts += 1
        time.sleep(min(60, 5 * restarts))   # 退避，避免疯狂重启
```

**验收**：手动 `taskkill` 后，进程在 1 分钟内自己回来。

---

#### 3. 只在登录时启动一次

**现象**：`注册开机自启-客户端.bat` 用的是 `schtasks /sc onlogon`，只跑一次。电脑重启、休眠恢复、进程被系统回收后都不会再起。

**修法**：加一个独立的守护脚本，每 10 分钟检查一次进程是否存在，不在就拉起来。

**验收**：杀掉进程后 10 分钟内自动恢复。

---

### P1：不做到会让「每个问题都要人远程连进去」

#### 4. 心跳上报的诊断信息太少

**现在上报的**（`agent/client.py:54`）：

```
agent_version, wecom_state, queue_size, last_error
```

**需要补充**：

| 字段 | 用途 |
|---|---|
| `uptime_seconds` | 进程活了多久（频繁重启能看出来） |
| `restart_count` | 自愈重启次数 |
| `send_attempts` / `send_failures` | 最近 1 小时发送成功率 |
| `last_success_at` | 最后一次成功发送的时间 |
| `window_visible` | 企微窗口是否可见（隐藏时发不出去） |
| `foreground_blocked_count` | 抢前台失败次数 |
| `pending_depth` | 待发队列深度（堆积说明卡住了） |

**效果**：客户说「没回」，我们先看网页，而不是先远程连进去。

---

#### 5. 掉登录没有主动告警

**现在**：`login_required` 只写进心跳，网页看板显示红条。没人看就没人知道。

**修法**：状态从 `online` 变成 `login_required` 时，推送告警到你们的企微群/钉钉：

```
[设备 pc-xxxx] 企业微信已退出登录，需人工扫码
```

**注意**：只在状态**变化**时推一次，不是每 30 秒推一次。

---

#### 6. 更新要人工拷贝

**现在**：改一次代码要跑到每台机器上重装。

**修法**：客户端启动时检查版本（服务器返回最新 commit / 版本号），有新版就提示或自动拉取重启。

**最低程度**：网页设备列表显示每台设备的版本号，能看出哪台是旧的。

---

### P2：产品形态层面

#### 7. 官方客服 API 才是真正的无人值守

**为什么重要**：键鼠自动化必须独占前台，注定是「一台机器换一个人」。

**现状**：`kf/send_msg` 已实现（`src/modules/wecom/wecom-channel.ts:57`），但生产未配置（`wecom_connections = 0`）。

**限制**：

| 限制 | 值 |
|---|---|
| 回复窗口 | 客户最后发言后 48 小时 |
| 单窗口条数 | 5 条 |
| 适用入口 | 仅微信客服（客服链接/二维码），不能用于好友私聊 |

**结论**：如果业务入口能改成「客服链接」，这条路是唯一 7×24 无人值守的方案。

## 二、优先级与工作量

| 优先级 | 项目 | 工作量 | 收益 |
|---|---|---|---|
| P0-1 | 单实例锁 | 0.5 天 | 消灭重复回复 |
| P0-2 | watchdog 自愈 | 0.5 天 | 进程崩了自动回来 |
| P0-3 | 定时拉起 | 0.5 天 | 重启/休眠后自动恢复 |
| P1-4 | 心跳诊断字段 | 1 天 | 排查从「远程」变「看网页」 |
| P1-5 | 掉登录告警 | 0.5 天 | 第一时间知道 |
| P1-6 | 自动更新 | 1-2 天 | 不用逐台部署 |
| P2-7 | 官方客服 API | 3-5 天 | 真正无人值守 |

**P0 三条加起来约 1.5 天，能消灭这类事故：**

- 客户收到重复消息
- 进程崩了没人管
- 重启后一整天没在工作

## 三、关于「网页上点按钮启动」

**这个问题需要说清楚：网页按钮启动不了本地程序。**

浏览器有沙箱限制，网页无法启动本地进程。能做的只有两种：

### 做法 A：协议唤起（`custom-uri`）

网页按钮 → `cityrecruit://start` → 唤起已注册的本地程序。

**前提**：本地程序必须先装好、注册过协议。首次安装仍需人工一次。

**限制**：Chrome/Edge 会弹「是否允许打开外部应用」，用户要再点一次确认。

### 做法 B：本地程序常驻 + 网页下发指令（推荐，已实现）

```
客户端 7×24 常驻（开机自启 + watchdog）
   ↓ 每 10 秒轮询
POST /api/v1/bridge/devices/{code}/claim   ← 取指令
   ↓
网页点按钮 → 写入 bridge_commands → 客户端领取并执行
```

网页按钮控制的是「**发什么消息**」，不是「**要不要启动程序**」。程序必须一直在跑。

**验证过的证据**：`src/modules/messaging/device-bridge.ts:169` 的 `bridge_commands` 队列，就是为这个设计的。

### 结论

- 「网页启动本地程序」——**技术上做不到**（除非接受协议唤起 + 二次确认）
- 「网页控制本地程序发什么」——**已经实现了**
- 正确的产品形态是：**本地程序常驻（无人值守），网页是控制台**

## 四、常驻方案（客户机器上）

现在项目里已有：

```
deploy\client\客户端模式.bat          双击启动，含各项检查和防重复
deploy\client\注册开机自启-客户端.bat   注册登录自启（schtasks /sc onlogon）
deploy\client\停止全部.bat            停止
```

**缺**：定时拉起（P0-3）。补上之后，客户机器上的形态才是完整的：

```
开机 → 自启 → 常驻 → 崩了自愈 → 掉线告警 → 网页远程控制
```

## 五、给客户安装时的最小步骤

目标：客户只看一份说明就能装完。

1. 装 Python（或提供打包好的 exe，免装）
2. 装企业微信并登录
3. 解压客户端包到固定目录
4. 双击 `客户端模式.bat`
5. 看到「已注册 device_code=pc-xxxx」即成功
6. 双击 `注册开机自启-客户端.bat`（管理员）
7. 打开网页确认设备在线

**当前卡点**：第 1 步需要客户装 Python，第 3 步需要解压到固定路径。打包成 exe 能省掉这两步（P2 范畴）。
