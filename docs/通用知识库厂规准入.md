# 通用知识库厂规准入

## 生效范围

`kb_faq.lookup()` 对 global、city、vertical 三层增加招聘政策检查。已精确匹配的 employer、position 条目仍按运营原文使用。原数据不被自动改写，不执行数据库迁移。

检查发生在关键词命中之后、同层选优之前。因此高优先级的不适用通用条目不会盖住低优先级的安全模板；全部不适用时返回未命中，后续走原有确认话术和未知问题记录。

## 内容约定

涉及工价、工资、体检、纹身、录用、年龄、食宿、社保、转正等常见招聘条件时，共享问答必须使用已知岗位事实占位符，不得包含字面政策承诺、默认政策或共享媒体。检查结合客户原话、FAQ 问题、关键词和正文，不以是否出现数字作为唯一条件。

可用示例：

```text
{medical}
{tattoo_policy}
这边工价是{wage}
{medical}。{tattoo_policy}
```

不适用示例：

```text
体检免费，有纹身都能进
转正后175元/班
{medical|免费体检}
{medical}，另收200元
{medical}，纹身都能进
```

模板只允许渲染器已知的招聘条件短名或字段全名，如 `{medical}` / `{medical_text}`。除标点和代码列出的中性字段标签外，不允许附加文字；需要自由组织的专属厂规应放到雇主/岗位作用域。

岗位字段为空时模板不会生成默认厂规。通用问答附带的图片或视频也可能承载其他工厂的承诺，因此敏感共享问答携带媒体时整条不参与命中。正常岗位话术和当前岗位媒体按原有白名单发送；普通通用问候、非政策类媒体介绍保持可用。

## 旧知识库

flow 接口启用的严格模式同时检查 `kb_entry` 回退：没有 `factory_name` 的招聘政策正文不参与命中；带厂名且匹配当前工厂的正文继续使用。旧知识库不具备同样的事实模板渲染流程，不能通过放一个占位符绕过校验。其他旧调用未启用严格模式时保持兼容。

## 运营处理

已有通用正文并不会被删除。具体工厂的政策迁到 employer 或 position 作用域；可复用模板使用上述占位符，把真实取值维护在岗位字段。普通聊天文字可以继续放通用层。新增未知字段要更新渲染器和准入字段列表，并补回归。

本规则是覆盖常见招聘条件的确定性约束，不是对任意自然语言或图片内容的语义审核；运营仍需确保厂规内容和归属正确。本次不检查资源文件中的文字，也不自动迁移历史数据。

## 联调补充：未预约客户明确换城

本地页面联调发现，模型缺席时客户说新城市会继续旧岗位邀约。现在短句「广州」「我想去广州」「换到广州」等明确表达由代码切换城市、重发新岗位，并清除旧岗位的同意和面试状态，保留姓名、手机。

新城市没有岗位时清空旧岗位身份和快照，回到问城市/确认岗位；不会继续用旧厂资料。朋友所在城市、否定句不按明确换城处理。已完成预约的会话不适用这个自动切换分支，复杂城市意图仍由原有路径处理。

## 配置写入与内容盘点（2026-11-15）

后台“知识库配置 → 场景问答”的新增、编辑、删除统一使用 `/api/v1/kb-faqs`，修复原来写入 `/faqs` 的错误地址。编辑会持久化品类、作用域和对应关联编号，切换作用域时清空其他作用域遗留的编号。启用条目必须关联有效且启用的品类及目标；招工方与限定品类不一致时拒绝保存。

global/city/vertical 的启用问答统一做共享政策准入，新增、部分更新、重新启用与模板导入都不能绕过。共享模板还会拦截未知字段、默认兜底和不完整括号。模板导入返回 `blocked` 问题清单；已存在的问答继续跳过，不覆盖运营修改。同厂统一政策应选招工方，工种或基地不同的政策应选岗位；不要猜测编号或工厂归属。

列表“内容检查”列提示历史问题，支持单条停用和导出 JSON 审计清单。停用保留原文；目标丢失的旧条目也能通过仅含 `status: disabled` 的更新隔离，重新启用仍需修正完整配置。历史内容不自动迁移、改写或批量停用。

旧 Python `/api/v1/kb/entries` 的 script 新增、修改和重新启用，同样拒绝无 `factory_name` 的工资、厂规正文或文本片段。job 结构化岗位入口维持原有行为。未知问题“转知识库”被此规则拒绝时，返回具体校验原因并保持 pending；政策内容请先在配置台建立明确归属，而不是填一条无归属通用答案。

管理员只读审计接口：

- Node：`GET /api/v1/kb-faqs/audit`，返回 `items` 问题清单和 `faq_inventory` 完整对比字段。
- Python：`GET /api/v1/kb/governance/audit`，返回 FAQ、旧 script 的问题清单和 FAQ 对比字段。旧 script 的媒体文件内容不做 OCR 或语义判断。

**双库限制：** 4222 的配置保存在 Node SQLite；8090 的实际回复读取 Python 数据库。现有 `backend/scripts/sync_kb_from_node.py` 只增不改，后台保存并不等于覆盖真实回复库的旧条目。审计接口仅用于盘点，不同步数据。需要先对照两侧的内容与归属，明确冲突处理，再执行受控同步；不能按两库数字 ID 相同推定是同一工厂。

新增验证见 `tests/kb-governance.test.ts`、`tests/unknown-question-conversion.test.ts` 与 `backend/tests/test_kb_governance.py`。`tests/fixtures/kb-policy.json` 由 Node/Python 两侧共同读取，保证常见政策判断一致。
