# 通用知识库厂规准入

## 生效范围

`kb_faq.lookup()` 对 global、city、vertical 三层增加招聘政策检查。已精确匹配的 employer、position 条目仍按运营原文使用。原数据不被自动改写，不执行数据库迁移。

检查发生在关键词命中之后、同层选优之前。因此高优先级的不适用通用条目不会盖住低优先级的安全模板；全部不适用时返回未命中，后续走原有确认话术和未知问题记录。

## 内容约定

涉及工价、工资、体检、纹身、录用、年龄、食宿、社保、转正等常见招聘条件时，共享问答必须使用已知岗位事实占位符，不得包含字面政策承诺、默认政策或共享媒体。检查结合客户原话、FAQ 问题、关键词和正文，不以是否出现数字作为唯一条件。

可用示例：

```text
{medical}
{tattoo_policy}
这边工价是{wage}
{medical}。{tattoo_policy}
```

不适用示例：

```text
体检免费，有纹身都能进
转正后175元/班
{medical|免费体检}
{medical}，另收200元
{medical}，纹身都能进
```

模板只允许渲染器已知的招聘条件短名或字段全名，如 `{medical}` / `{medical_text}`。除标点和代码列出的中性字段标签外，不允许附加文字；需要自由组织的专属厂规应放到雇主/岗位作用域。

岗位字段为空时模板不会生成默认厂规。通用问答附带的图片或视频也可能承载其他工厂的承诺，因此敏感共享问答携带媒体时整条不参与命中。正常岗位话术和当前岗位媒体按原有白名单发送；普通通用问候、非政策类媒体介绍保持可用。

## 旧知识库

flow 接口启用的严格模式同时检查 `kb_entry` 回退：没有 `factory_name` 的招聘政策正文不参与命中；带厂名且匹配当前工厂的正文继续使用。旧知识库不具备同样的事实模板渲染流程，不能通过放一个占位符绕过校验。其他旧调用未启用严格模式时保持兼容。

## 运营处理

已有通用正文并不会被删除。具体工厂的政策迁到 employer 或 position 作用域；可复用模板使用上述占位符，把真实取值维护在岗位字段。普通聊天文字可以继续放通用层。新增未知字段要更新渲染器和准入字段列表，并补回归。

本规则是覆盖常见招聘条件的确定性约束，不是对任意自然语言或图片内容的语义审核；运营仍需确保厂规内容和归属正确。本次不检查资源文件中的文字，也不自动迁移历史数据。

## 联调补充：未预约客户明确换城

本地页面联调发现，模型缺席时客户说新城市会继续旧岗位邀约。现在短句「广州」「我想去广州」「换到广州」等明确表达由代码切换城市、重发新岗位，并清除旧岗位的同意和面试状态，保留姓名、手机。

新城市没有岗位时清空旧岗位身份和快照，回到问城市/确认岗位；不会继续用旧厂资料。朋友所在城市、否定句不按明确换城处理。已完成预约的会话不适用这个自动切换分支，复杂城市意图仍由原有路径处理。
