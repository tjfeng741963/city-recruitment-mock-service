# 产品功能与入口规范

首版：2026-11-21。由本轮用户明确要求建立，后续共同修订。

## 1. 实现前先确认位置

新增面向用户的功能，先讨论“用户在什么场景、从哪个页面、哪个位置找到它”，确认后再实现。不能因为技术上方便，就在侧栏、页面顶部或独立测试页随手增加入口。

新增、移动、隐藏、合并、重命名菜单或主要按钮，都属于产品入口变更。先给出具体方案，包含原入口如何处理；不能只说“整理一下”。

已经确认的位置与方案不重复请求确认。修复原位置的缺陷、补测试、调整代码内部结构，可以在现有授权内继续；如果新发现的问题会改变入口方案，再拿出具体差异讨论。

## 2. 每次新增功能的最小提案

| 必须说明 | 回答内容 |
|---|---|
| 用户任务 | 谁在什么情况下，需要完成什么事情 |
| 页面归属 | 属于日常招聘、招聘资料、AI 接待，还是账号与设置；复用哪个现有页面 |
| 具体位置 | 页面顶部、画布工具栏、右侧面板、表单区或更多菜单；给简图/截图标注 |
| 入口与路径 | 主入口叫什么、怎么到达、操作后去哪里、如何返回 |
| 与已有功能的关系 | 是否已有相同能力；复用、替换还是新增；旧入口/链接如何处理 |
| 实际结果 | 保存到哪里、实际招聘链路是否读取、如何验证生效；尚未接通的部分如何说明 |

提案应简短、具体，按改动大小提供必要图示。不能把技术模块名称直接当成用户菜单名称。

## 3. 页面和入口的放置顺序

优先扩展已有页面的相关区域；其次使用该页的标签页、抽屉或侧栏；只有确属独立且长期使用的任务，才讨论新增页面或左侧菜单。不是每个后端模块都需要一个页面，也不是每个新功能都需要一个侧栏菜单。

每项能力维护一个主要操作位置、一份配置与一份数据。相关页面可以有快捷入口，但必须携带当前岗位/账号等上下文，指向同一位置，不另外做一套编辑表单或测试实现。

一个主入口不等于全产品只能有一个链接。知识库、素材等有独立日常任务的页面可以保留侧栏入口；岗位页的“本岗位知识库”快捷链接也可以保留。两者都访问同一份知识数据。

## 4. 不靠隐藏有用功能来精简

用户常用的能力应直接可见，低频操作才考虑“更多”。不能把知识库藏到流程页深层菜单，再把“入口少了”当成产品简化。

合并入口前要列出原有能力、移动后的去向、访问路径和验证结果。不能随意删配置或历史数据；旧地址需要兼容时保留跳转。

已有独立页面、原生 Vue 控件可复用时，不再通过主题脚本注入第二套同功能按钮。迁移时明确唯一实现并停止重复注入。

### 界面文案与布局

标题、字段和按钮已经说明用途时，省去概述和重复说明。接口路径、配置内部结构、实现方式放在源码注释或维护文档中。

填写规则贴近对应字段，操作后果在相关操作处提示，错误、未保存、掉线、不可用等状态随实际情况显示。移除文案后检查标题与按钮对齐、内容间距和窄屏换行，避免留下空白横条。

## 5. 用户看见的效果必须真实

保存、客户端读取、AI 生成、客户端执行、企微发送及对方收到，是不同结果。界面只展示已有证据支持的状态。

新增字段或开关应查明实际消费者；仅保存成功、当前招聘链路不读取的设置，不能承诺生效。未接通能力需明确说明，不能用可点击按钮或成功提示掩盖。

预览与真实操作要明确：测试选择引擎不自动改变真实账号配置；模拟回答不自动发给客户、创建正式登记或推群。

## 6. 当前已确认的产品归属

| 区域 | 主要任务/位置 |
|---|---|
| 对话管理 | 查看真实客户对话、核对收发、人工接待；核心窗口保留 |
| 候选人管理、面试登记 | 查看报名与招聘跟进结果；核心窗口保留 |
| 微信账号 | 客户端连接、负责人、岗位绑定、实际回复来源、通知群；进入对应工作流 |
| 招聘资料 | 城市/项目、岗位事实；不重复维护 AI 测试工具 |
| 话术流程画布工作台 | 配置/查看流程，统一 Agent 与 Dify 测试；模拟回复和客户端联调在同一测试面板分步验收 |
| 问答知识库 | 维护通用和岗位问答；保留独立菜单，测试跳到统一工作台并保留上下文 |
| 图片与视频 | 维护通用和岗位素材；保留独立菜单 |
| Dify 后台 | 当前 Dify 原生流程的节点编辑与发布；本系统统一测试不代表重建其编辑器 |

上表包含已上线入口及已确认的统一测试方向，不代表统一测试已实现。具体范围以对应设计/验收记录为准。

## 7. 评审与交付

入口相关 PR 写清：功能放在哪、为什么、哪些入口新增/移动/保留、是否复用同一数据与实现、怎么验证用户完整路径。

验收要实际从主入口点击到结果，并核对返回、刷新、选中状态、当前岗位/账号和错误反馈。功能名称、入口位置或作用范围未确认时，先讨论这部分，不先散落实现一批按钮再要求用户接受。

已确认的方向：Agent 与 Dify 测试统一到画布工作台；后续任何新增功能，先明确位置再开发。位置已经确认的实施步骤不重复申请批准。
