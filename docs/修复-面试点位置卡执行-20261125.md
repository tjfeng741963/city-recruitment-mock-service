# 面试点位置卡：配置与执行修复

> 后续发布选择了「地址＋导航链接」。系统 Agent 画布按原有顺序和等待时间走文字发送。下文保留原生位置卡方案的历史记录，当前接口以《API 接口清单》为准。

用户在诊断后明确要求修复。基于 main f11f1a7。

## 根因与范围

画布选点以 favorite_title 为前提，选项不来自企微收藏；执行配置又过滤 favorite_location，
而客户端已有按坐标生成位置卡的程序。可保存与可执行两条路径未接通。

复用既有「招聘资料 → 招聘岗位 → 编辑 → 面试与门店 → 面试点」作为唯一地点资料。
补齐每个点的经纬度编辑，保留旧收藏字段但不以其作为发卡条件；不新增菜单/主按钮。
画布原「发送哪个面试点」显示该岗位所有唯一命名点，标注缺地址/坐标并禁选，
保存时后端从岗位资料生成可信位置快照。已有流程不因岗位资料修改而悄悄改变在途快照。

## 执行约束

新客户端主动声明支持此流程步骤；服务端下发完整顺序及地点快照。
旧客户端遇到包含位置步骤的启用流程，返回 blocked，提示升级，不能静默删步。
旧流程缺少快照必须重新保存；未知/缺失地点不能猜测、不能借别的岗位坐标。
沿用 location_card.send_card，不改动作、冻结核心或发送时序。
发卡前必须有本轮已确认目标文字；逐条记录 outbox，地点回读核对同一账号/会话、
新消息 ID、类型和位置内容，失败/不确定停止后项，不自动重放。
发送前再次检查接管、回复来源和桌面；不能以收藏存在或已回车当作送达。

## 验证与回滚

临时库与替身发送验证：无收藏名的有效点、缺坐标/越界/重名、岗位隔离、
保存快照/修改资料后不漂移、旧客户端阻断、新客户端下发、文字→卡→后文顺序、
延迟、错误会话/无回读/异常/重启不重放。执行仓库要求检查并构建前端。
本轮不写生产地点、不发真实消息。生产验收需要授权测试联系人。
回滚程序保留岗位、流程快照与 outbox；不清除历史记录制造未发送状态。

- npm ci、迁移序号检查、API 文档检查、后端 tsc 均通过。
- Vitest 全量：91 个文件，642 passed / 2 skipped。最后一项页面 key 修正后同步页面契约，重新跑全量通过。
- Python 全量：1221 passed / 5 skipped。新增 SQLite 地点回读、顺序/延迟、失败停止、重启不重放、账号/来源/接管切换、旧缓存和旧会话快照保护测试。
- Vue（含 vue-tsc）和原有前端生产构建均成功。构建已有大包提示；迁移检查已有 030 断号提示，不阻断检查。
- 隔离内存库、mock 通道、本地 Vue 页面实际点击：招聘资料 → 招聘岗位 → 编辑岗位 → 面试与门店。确认坐标回填、越界提示和保存；系统 Agent → 去画布编排保持同一岗位；位置下拉显示无收藏名的有效点，并禁用「缺有效坐标」点。保存等待 0.5 秒后刷新，版本递增、选点/等待值保留。未绑定设备、流程保持停用，没有实际客户发送。

## 升级与验收边界

服务端与新客户端双向声明 location_steps=1。先更新服务端，再安装客户端；新客户端拒绝不含标记的旧服务端响应和普通旧缓存，避免恢复被过滤过的流程。
旧客户端无法执行含位置卡的启用流程，服务端明确 blocked；旧位置步骤缺地点快照，须在画布重新选点保存。升级前的在途会话快照可能已丢步，新客户端保留记录并暂停待人工核对，不替换为新流程，不补发。
发卡使用本轮已确认文字的同一账号；账号切换、无唯一匹配 type6 新消息或内容不符都不能标记成功。回读只能确认本地目标会话新增该卡，不等同于对方设备已收到。
本轮只有本地测试和待审核分支；未合并 main、未部署生产、未安装云 Windows 客户端，也未核实真实企微收藏。真实收卡仍需上线后用指定测试联系人验收。
