# 实施计划 · 线索闭环（P0 裁决版）

> 裁决日 2026-11-04。优先级：**风控 > 只记事实 > 一条命令能关 > 不过度设计 > 可验收**。
> 一句话：P0 **一条主动消息都不新增**；把「到点该问」变成顾问屏上的待办，把「09:00 假时间」换成精度字段，把人工确认拆成逐条点击。

## 1. 裁决结果

### 冲突 1 · 到点自动询问 —— 采纳运维（否决自动发送）

理由：账号发 2 条（间隔 11 秒）就被退回登录页，任何「定点 + 批量 + 无人触发」的发送序列都是同一形态，deliveries 队列只是把风险技术化（还会隔夜补发）。

**折中后的行为**：sweep 命中后只做三件事——`pending_confirm=1`、写 `LeadEvent(check_pending)`、页面出现「该问一句」卡片（附可复制文案「今天还过来吗？需要我帮你改个时间吗」）。顾问自己粘到企微发（他本来就在企微里）。**不建 delivery、不调发送、不碰凭证**，新增消息条数 = 0。
日后若要自动化，前置条件照抄 03 §一（连续 14 天零处置、单条上限 1 次、失败永不补发……），P0/P1 一律不做。

### 冲突 2 · `interview_at` 只有日期 —— 采纳技术，按运维砍两处

理由：09:00 是凭空造出来的事实，会同时污染「顾问 9 点现场判断」和「到面率」。

**折中后的行为**：新增 `interview_precision`（`minute`/`day`）。`day` 时 `interview_at` 归一化到**本地当天 00:00**（存 naive UTC，即前一天 16:00），页面只显示「11-05 钟点未定」，`check_at` 取**当天 18:00**，绝不按 09:00 触发。
砍掉 02 的两处过设计：①`version` 乐观锁不做（单机 3 人，条件 UPDATE + manual 优先足够）；②`nudged_at` 改名 `alerted_at`——P0 不向客户发消息，叫 nudged 会诱导实现者去发。
**存量不回填 `check_at`（置 NULL）**、precision 回填 `day`、worker 默认关闭。这是运维第 3 条否决的直接落地：上线那一刻不许全量回溯。

### 冲突 3 · 人工确认默认值 —— 采纳技术/运维（默认不勾），否决「全选到」

理由：默认勾选 = 批量覆盖写事实，漏点一人就写错一条到面，方向恰是最贵的那个错。

**折中后的行为**：页面**没有**默认勾选、没有「全选到」、没有批量接口。每行三个按钮 `到了 / 没来 / 改期`，**点一下立即提交一条**（`POST /leads/{id}/manual`），无弹窗、无提交步骤；点错了再点另一个按钮即可修正，`lead_events` 留痕。产品要的「10 秒点完」靠「一行一键」达成，不靠批量。

## 3. 分工（三包文件不重叠）

### 公共契约（先定死，后两组照着写）

| 字段 | 类型 | 语义 |
|---|---|---|
| `interview_precision` | String(8)，默认 `day` | `minute`=钟点确定；`day`=只知道哪一天 |
| `check_at` | DateTime，nullable，索引 | 该标待核实的时刻（naive UTC） |
| `alerted_at` | DateTime，nullable | 已产出待办提醒的时刻，**与发消息无关** |

`compute_check_at(interview_at, precision, now)`：`day` → 当天本地 18:00；`minute` → `interview_at+3h`，落在本地 22:00–08:00 则顺延次日 09:00。规则写在 `models_lead.py`，A/B 共用。

### A 包 · 后端推断（关键路径）

**文件**：`backend/app/models_lead.py`、`backend/app/services/lead_extract.py`、`backend/app/api_lead.py`、`backend/app/workers/lead_sweep.py`、`backend/tests/test_lead_precision.py`、`backend/tests/test_lead_sweep.py`

1. `models_lead.py`：加三列 + `compute_check_at()` + `async def ensure_lead_columns(conn)`（`inspect` 查列 → 缺则 `ALTER TABLE leads ADD COLUMN ...`，SQLite/Postgres 通用写法；存量 `check_at` 保持 NULL，precision 回填 `day`）。
2. `lead_extract.py`：prompt 删掉「不知道钟点填 09:00」，改「不知道钟点 → `interview_precision='day'`，`interview_at` 给日期即可」；输出契约加 `interview_precision`；`normalize()` 缺该字段一律按 `day`，并**把 `day` 的 `interview_at` 归一化到本地当天 00:00**（模型即便吐 09:00 也不采信）；`observe()` 写 precision/`check_at`、清 `alerted_at`，开头加 `if not extract_enabled()[0]: return {"changed": False, "reason": "抽取已关闭"}`。
3. `api_lead.py`：`ManualIn`/`LeadOut` 加 `interview_precision`；标 `booked` 时重算 `check_at`，标终态时 `check_at=None, alerted_at=None`；`list_leads` 支持 `precision` 过滤不必做。
4. `lead_sweep.py`：`run_once(now=None, limit=50)` + `run_forever(interval)`。第一行 `sweep_enabled()`；`SELECT ... WHERE stage='booked' AND pending_confirm=0 AND check_at<=now`；逐条 `UPDATE ... WHERE id=? AND stage='booked' AND pending_confirm=0` 看 rowcount，再写 `LeadEvent(event_type='check_pending', source='system')`，一行一 commit。**零 LLM、零 Delivery、零 stage 写入**。

**验收**：`cd backend && uv run pytest tests/test_lead_precision.py tests/test_lead_sweep.py -q`，必须覆盖：①只给日期 → `interview_at` 是本地 00:00 且 `check_at` 是 18:00；②给了 09:00 但 precision=day → 仍归一到 00:00；③`run_once` 跑两次第二次 rowcount=0、不重复写事件；④sweep 后 `select count(*) from deliveries` 不变、`stage` 不变；⑤`LEAD_SWEEP_OFF` 存在时 `run_once` 返回 skipped。
**坑**：`create_all` 不会给老表加列，不调 `ensure_lead_columns` 必 500；SQLite 读回来是 naive，比较前统一 naive UTC，别 `datetime.now()` 不带时区就比（03/02 都踩过）。

### B 包 · 看板页面

**文件**：`backend/app/api_lead_board.py`、`backend/app/static/leads.html`（新建目录）、`backend/tests/test_lead_board.py`

1. `GET /api/v1/leads/board` → `FileResponse` 返回 HTML（页面是空壳，不需要鉴权）。
2. `GET /api/v1/leads/board/data` → `AdminUser`，返回 `{counts, today, pending, followup}`：`today` = `stage='booked'` 且 `interview_at` 落在本地今天，按 `interview_at` 升序（day 精度 00:00 天然最前）；`pending` = `pending_confirm=1`，按 `check_at` 升序；`followup` = `stage in (booked,intent)` 且 `updated_at < now-24h`。
3. 页面：顶部三格计数；`day` 精度显示「钟点未定」不显示 09:00；每行 `到了/没来/改期` 各调一次 `POST /api/v1/leads/{id}/manual`，改期用行内 `<input type=date>` 提交 `{stage:'booked', interview_at:'<date>T00:00:00+08:00', interview_precision:'day'}`；「该问一句」卡片带复制按钮。token 从 localStorage 读，缺失时给一个输入框。

**验收**：`uv run pytest tests/test_lead_board.py -q`，覆盖：①未登录访问 `/data` 返回 401；②插一条 precision=day 的 lead，`/data` 里该条 `interview_precision == "day"`；③HTML 里不含「全选」和批量提交；④页面源码不含 `09:00`。
**坑**：前端 fetch 必须带 `Authorization: Bearer`，而 `/board` 本身不能鉴权（否则浏览器直接打开拿不到）；别去接 `frontend/`，那套走 8080 是另一个库（02 §四）。

### C 包 · 加固与开关

**文件**：`backend/app/services/lead_guard.py`、`backend/scripts/lead_switch.sh`、`docs/线索闭环-使用说明.md`、`backend/tests/test_lead_guard.py`

1. `lead_guard.py`：`DATA_DIR = Path(__file__).resolve().parents[2] / "data"`；`extract_enabled()` / `sweep_enabled()` 返回 `(bool, 原因)`，只看 `LEAD_EXTRACT_OFF` / `LEAD_SWEEP_OFF` 是否存在，**不缓存**（每次 stat，几百次/天可忽略）。
2. `lead_switch.sh off|on|status`：touch / rm / ls 两个开关文件，输出当前状态。
3. 使用说明：两个开关的语义、抽取关闭时回复不受影响、worker 灰度步骤（先 false → 单顾问 → 全量）、回滚命令。

**验收**：`uv run pytest tests/test_lead_guard.py -q`；`bash backend/scripts/lead_switch.sh off && bash backend/scripts/lead_switch.sh status` 输出 OFF。
**坑**：路径必须锚定 `__file__`，别用相对 `data/`（cwd 不是 backend 时开关失效）；`backend/data/` 已在 `.gitignore`，开关文件不会被误提交。

**顺序**：C 先交 `lead_guard.py`（两个函数即可，先合入）→ A、B 并行 → A 的字段是 B 的前置。
