# 本地运行说明（Windows 单机）

本文只讲「怎么在这台 Windows 上把两个进程跑起来、怎么看日志、出问题怎么办」。
后端内部结构见 `backend/README.md`，自动回复的实现见 `agent/README.md`。

## 1. 这套东西分两个进程

| 进程 | 目录 | 命令 | 端口 | 作用 |
|---|---|---|---|---|
| 后端 API（FastAPI） | `backend/` | `uv run uvicorn app.main:app --host 127.0.0.1 --port 8090` | 8090 | 会话、知识库、企微通道 |
| 自动回复（企微 agent） | `agent/` | `uv run python autopilot.py --watch` | 无 | 读本地解密库，自动给企微会话回消息 |

两个进程各自有 `.venv`，都用 `uv run` 拉起（`uv run` 会自动复用各自目录的虚拟环境）。
**必须先起后端，再起自动回复。**

## 2. 前置条件

1. **uv**（≥ 0.11）。命令行执行 `uv --version` 能打印版本号即可：

   ```bat
   winget install --id=astral-sh.uv -e
   ```

   装完要**新开**一个命令行窗口，PATH 才生效。
2. **Python 3.13**。本机两个虚拟环境用的都是 3.13.14，`uv run` 会自己找/装解释器，一般不用手动装。
   首次启动如果发现依赖缺失，`uv` 会先下载依赖，窗口会停住一小会儿，属正常。
3. **企业微信 PC 端已登录**，并且运行期间：
   - 窗口**不要最小化**、不要被其他窗口完全盖住且长期不管（agent 要抢前台做键鼠操作）；
   - **不要锁屏、不要断开远程桌面**，锁屏后 UI 自动化直接失败。
4. 8090 端口空闲（没有别的程序占着）。

## 3. 启动顺序

### 3.1 第一步：起后端

双击根目录的 **`start-后端.bat`**，窗口标题会变成 `后端 :8090`。

脚本做的事：

1. 切到 `backend/` 目录；
2. 检查 `uv` 是否存在，不存在直接报错并给安装命令；
3. 检查 8090 是否已被占用，**被占用就提示并退出**（不会盲目再起一个导致端口冲突）；
4. 建好 `logs/` 目录；
5. 启动 uvicorn，输出同时打到控制台和 `logs/backend.log`。

成功标志（窗口里出现）：

```
INFO:     Uvicorn running on http://127.0.0.1:8090 (Press CTRL+C to quit)
INFO:     Application startup complete.
```

再用浏览器访问 <http://127.0.0.1:8090/healthz>，返回 JSON 即后端正常。

### 3.2 第二步：起自动回复

先确认 `agent/config.json` 存在（仓库里通常已经有一份）；
如果没有，把模板复制一份再填：

```bat
cd agent
copy config.example.json config.json
```

必填：`device_token`（后端下发的设备令牌）、`brain.password`（后端管理员密码），
占位符（带「填」字的）没改会被后端拒绝。

然后双击根目录的 **`start-自动回复.bat`**，窗口标题会变成 `自动回复`。

脚本会依次检查：

1. `uv` 是否存在；
2. 8090 是否在监听——**没起后端就直接提示「请先启动后端」并退出**；
3. `config.json` 是否存在——不存在就提示用 `config.example.json` 复制；
4. 建 `logs/` 目录，然后运行 `uv run python autopilot.py --watch`。

成功标志（窗口里出现）：

```
[HH:MM:SS] 数据目录 ...\WXWork\...
[HH:MM:SS] 监听范围 全部会话（排除系统会话）/ 首次 '1' · 后续 '233' / 冷却 8.0s
[HH:MM:SS] 开始监听（Ctrl+C 退出）
```

### 3.3 偷懒办法：一键起两个

双击 **`start-全部.bat`**：它用 `start "" cmd /k` 开两个独立的 cmd 窗口，
先起后端，`timeout /t 5` 等 5 秒，再起自动回复。

启动窗口自己会提示「按任意键关闭本启动窗口（不影响两个子窗口）」。
如果 8090 已经在监听，它会先提示一句：此时后端窗口会因端口被占用而自己退出，属预期行为。

> 后端首次装依赖可能超过 5 秒，那样自动回复窗口会提示「请先启动后端」。
> 等后端出现 `Application startup complete` 后，再单独双击一次 `start-自动回复.bat` 即可。

## 4. 日志怎么看

| 文件 | 内容 |
|---|---|
| `logs/backend.log` | uvicorn 的控制台输出（访问日志、异常堆栈） |
| `logs/agent.log` | 自动回复的每一轮扫描、发送、知识库命中/回落 |

- 两个窗口里能直接看到同样的内容（脚本把输出同时写屏幕和文件）。
- 日志是**追加**写，每次启动会插一行 `===== 日期 时间 启动 =====` 作为分隔。
- 查看方式：
  - 记事本 / VS Code 直接打开 `logs\agent.log`；
  - Git Bash：`tail -f logs/agent.log`；
  - PowerShell：`Get-Content logs\agent.log -Wait -Tail 50`（只读日志，不影响脚本）。
- 回复历史（发过什么、成功还是失败）存在 `agent/reply_log.db`，用命令看：

  ```bat
  cd agent
  uv run python autopilot.py --list
  ```

## 5. 常见问题

### 5.1 端口 8090 被占用

`start-后端.bat` 会打印：

```
[错误] 端口 8090 已被占用，为避免端口冲突，本窗口不再启动第二个后端。
```

排查：

```bat
netstat -ano | findstr ":8090 "
```

最后一列是 PID，确认它是什么再决定：

```bat
taskkill /PID <PID> /F
```

多半是上一次的后端窗口没关干净（或 `start-全部.bat` 又点了一次）。
最省事的做法：关掉已有的「后端 :8090」窗口，等几秒再重新双击。

### 5.2 提示找不到 `uv`

```
[错误] 找不到 uv 命令 ...
```

1. 安装：`winget install --id=astral-sh.uv -e`
2. **关掉所有 cmd 窗口重新打开**（PATH 在进程启动时读取，旧窗口不会更新）；
3. `uv --version` 确认有输出；
4. 仍不行就检查 `uv.exe` 所在目录是否在「系统属性 → 环境变量 → Path」里。

### 5.3 agent 报「抢不到前台，已中止」

这是 `wecom_io_core/send.py` 在把企微窗口置前失败时的原文，常见原因：

- 企微窗口被最小化、被别的窗口压住，或有 UAC 弹窗/其他程序抢焦点；
- 屏幕锁了、远程桌面断开了（锁屏状态下 UI 自动化必失败）；
- 有别的程序（输入法候选框、录屏、远程控制）在持续抢焦点。

处理：

1. 把企业微信主窗口**恢复成普通大小**（不要最小化），手动点一下窗口标题栏；
2. 关掉会抢焦点的软件（远程控制、录屏工具、弹窗类工具）；
3. 确认没锁屏，等下一轮（默认 `interval_seconds` 60 秒）自动重试；
4. 单条失败不会丢：记录留在 `reply_log.db` 里，重启后会补发。

### 5.4 `config.json` 缺失或还是占位符

```
[错误] 缺少 agent\config.json ...
```

```bat
cd agent
copy config.example.json config.json
```

然后改这几项：`device_token`、`brain.password`，以及 `tool_path`（解密工具脚本路径）。
`device_token` 里如果还带「填」字，后端会直接拒绝。

### 5.5 `brain.mode` 的取值

`agent/config.json` 里的 `brain` 段决定回复内容从哪来：

| 取值 | 含义 | 行为 |
|---|---|---|
| `kb`（默认） | 走**知识库** | 把客户消息 POST 到后端 `/api/v1/kb/answer`，用返回的答案回复；命中不到或超时，**自动回落固定文本**，绝不卡住客户 |
| `fixed` | 只用**固定文本** | 完全不请求知识库，第一次回 `reply_first`（默认 `"1"`），之后回 `reply_next`（默认 `"233"`） |

另外 `brain.password` 要能登录后端管理员账号（默认用户名 `local-admin`），
`brain.base_url` 与 `server` 都指向 `http://127.0.0.1:8090`。

> 现状提醒：当前 `autopilot.py --watch` 里 `_brain` 恒为 `None`，
> 也就是**实际发送的仍是固定文本**（首次 `1`、后续 `233`）。
> `brain` 段是为接知识库预留的配置，接上以后按上表生效。

### 5.6 双击后窗口一闪就没

说明前置检查没过（缺 uv、端口占用、缺 config.json）。这类失败分支会停在
「按任意键关闭窗口」，如果窗口仍然瞬间消失，改从命令行跑一次看完整输出：

```bat
cd /d C:\Users\a2436\Desktop\code\city-recruitment-mock-service
start-后端.bat --check-only
start-自动回复.bat --check-only
start-全部.bat --check-only
```

`--check-only` 只做检查、**不会真的启动进程**，检查通过时打印
`[检查通过] ... 准备启动：`，退出码 0；有问题则打印原因，退出码 1。
三个脚本都支持这个参数（`start-全部.bat` 只检查 uv、配置文件和端口，不会开窗口）。

> 补充：这几个 bat 请**直接双击**运行（或交给 `start-全部.bat` 用 `start "" cmd /k` 拉起）。
> 不要在自己写的 bat 里用 `call start-后端.bat` 这种方式串联——中文 bat 配合
> `chcp 65001` 时，`call` 会让 cmd 按字节偏移读错后续行，出现「找不到命令」「变量没赋值」这类怪现象。
> 要串联就用 `start-全部.bat`。

### 5.7 中文乱码

两个 bat 开头都有 `chcp 65001`，文件本身是 UTF-8。若仍乱码，通常是这个窗口被别的
程序（如旧版 IDE 终端）用 GBK 启动的——直接用资源管理器双击 bat 运行即可。

## 6. 怎么停

- 在各自窗口按 **Ctrl+C**；cmd 可能追问 `终止批处理操作吗(Y/N)?`，按 `Y`。
- **先停自动回复，再停后端**（避免 agent 还在发消息时后端已经没了）。
- 直接点窗口右上角 × 也行，但要确认进程真的退了：任务管理器里不应残留
  `python.exe`（uvicorn）或 `uv.exe`。
- 不需要停的话，后端窗口可以一直开着；改了 `backend/` 代码需要重启后端才会生效。

## 7. 目录结构（与本文相关的部分）

```
city-recruitment-mock-service/
├─ start-后端.bat          # 起后端 FastAPI:8090（含端口占用检查）
├─ start-自动回复.bat      # 起 agent autopilot --watch（含后端/配置检查）
├─ start-全部.bat          # 一键：后端 → 等 5 秒 → 自动回复
├─ logs/                   # 首次运行自动创建
│  ├─ backend.log
│  └─ agent.log
├─ backend/
│  ├─ .venv/               # uv 管理的虚拟环境
│  └─ app/main.py          # uvicorn 入口，健康检查 /healthz
├─ agent/
│  ├─ .venv/
│  ├─ autopilot.py         # --watch 常驻轮询
│  ├─ reply_log.db         # 回复历史（pending/sent/failed/skipped）
│  ├─ config.example.json  # 配置模板
│  └─ config.json          # 实际配置（含 device_token，勿外传）
└─ docs/
   └─ 本地运行说明.md      # 本文
```
