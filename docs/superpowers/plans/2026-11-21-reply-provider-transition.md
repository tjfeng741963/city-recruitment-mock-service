# 回复来源切换实施计划

网页入口为「微信账号 → 接待设置 → 回复来源」。Windows 管理器展示相同的阶段、等待时间及应用结果。切换使用设备独有的持久编号。只有同一设备令牌能上报，管理员可发起与撤回。

| 场景 | 处理 |
| --- | --- |
| Windows 忙于发送 | 等当前任务完成或进入待核对，阻挡领取新指令 |
| 页面关闭、请求响应丢失或重复点击 | 服务端保存进度，用编号核对并安全重试 |
| 断网、Windows 重启、服务重启 | 重连先读取服务端状态，再决定能否回复 |
| 企微离线、鉴权失效、配置拉取失败 | 暂停回复，两端显示原因和等待时长 |
| 操作者撤回 | 发起带新编号的恢复，Win 确认后恢复原来源 |
| 旧工作流和发送结果不明 | 保留快照和账本，旧快照保留待核对 |
| 客户端版本过旧 | 未报告支持切换时显示升级提示 |
| 同时操作和迟到回报 | 同一设备最多一个切换，旧编号无法覆盖新进度 |

依次实现服务端状态机、Win 发前闸门与状态展示、网页操作与等待提示。验证双向切换、离线重连、撤回、缓存隔离、误投和重发。冻结发送动作原样保留。生产回退前先撤回待切换请求并确认 Win 处于原模式。
