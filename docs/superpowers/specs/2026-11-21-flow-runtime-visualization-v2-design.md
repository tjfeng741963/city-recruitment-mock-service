# 招聘流程运行可视化改进设计

## 目标

让运营能同时看懂岗位保存了什么流程、哪些 Windows 设备会使用它、客户消息怎样推进节点、固定流程何时交给 AI，以及消息是否有真实运行证据。全屏编辑器仍复用现有 Vue 3、Element Plus 和流程 API。

## 已核实的线上事实

- 深圳岗位 ID 22 的节点流程为 v1、停用；4 条旧开场均启用，最后一条为视频 `安检.mp4`。没有 Windows 设备绑定岗位 22。
- `pc-win-01` 绑定岗位 ID 25“广东城际_穗深线安检安保”。岗位 25 的 v3 节点流程启用，与旧开场 7 条文本内容逐条相同；前 6 个节点连续执行，第 7 个节点等待客户回复。
- 浏览器只读取、编辑和保存流程配置，不会直接发送企微消息。Windows 客户端负责真实发送；服务端心跳、流程状态镜像和企微消息送达是不同证据。
- 岗位 25 最后一个等待节点收到客户回复后，如果没有后继节点，当前运行器仍把该条入站消息标为跳过。应把同一条消息交给 AI 对话，不让客户再发一条才得到答复。
- 本轮不更改深圳岗位启停、岗位与设备绑定、客户端配置或实际发送动作，也不启动自动回复。

## 方案

画布进入应用内全屏编辑模式，临时隐藏常规侧栏和页头，保留固定顶部工具栏、可滚动画布与右侧属性栏。工具栏提供缩小、放大、百分比滑块、100%、适配画布和退出全屏；右侧属性栏可拖动调整宽度并保持独立滚动。Escape 退出全屏。

画布上方显示只读的“实际运行路径”条带。它按真实岗位配置区分：未绑定设备时明确说明无人执行；流程启用时从 Windows 首次触发条件依次展示已保存节点、等待/分支/超时和 AI 接管；流程停用时显示当前设备会收到的旧开场序列。系统阶段用只读样式，与真实可编辑节点区分。若存在客户端流程状态镜像，按设备汇总节点、阶段、数量和最后上报时间，不展示会话名、消息或快照。镜像不是企微送达回执，页面会明确标注。

节点检查器显示客户可见的完整消息，以及该节点实际执行语义。文本节点说明 Windows 如何发送并确认目标；图片/视频节点说明先查本地素材、缺失时从 4222 预取、再经现有媒体发送路径处理，且节点流程媒体前必须已有本轮确认过的文本落点。等待节点展示等待时间、可匹配关键词和兜底连接；分支显示关键词优先级和默认去向；复聊显示等待/静默时段/一次性规则。流程结束说明后续客户消息进入 AI，模型上下文来自岗位事实、人设、话术和会话记录。

运行器修复只改 `agent/autopilot.py` 的流程/聊天编排：等待节点确实有后继时继续推进流程；没有后继时将当前客户回复传给 AI。保留现有发送核心、媒体动作、幂等和在途会话快照。

## 验收

- 全屏画布、退出、缩放、适配、属性栏调整在桌面与窄视口均可用；节点与连接编辑仍保存到既有 API。
- 岗位 22 显示流程停用、无绑定设备和 4 条旧开场；岗位 25 显示设备 `pc-win-01`、流程 v3、连续 6 节点再等待 1 节点、与旧开场内容一致。
- 运行状态摘要只对管理员开放且只含汇总字段；设备令牌现有状态接口响应保持兼容。
- terminal-await regression 测试证明没有后继的等待节点把本轮回复交给 AI；有后继时不调用 AI。
- 不发送任何企微消息、不更改服务器业务配置、不启动 Windows 自动回复。
