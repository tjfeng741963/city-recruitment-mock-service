# 恢复城市资料、知识库与 Dify 原看板

用户纠正：模式二必须复用本系统城市编辑、现有知识库和首页 Dify 看板，不把岗位编辑或独立测试页当作唯一入口。

## 行为

- 恢复城市抽屉被隐藏的字段。public Vue 注入层补完整城市原文资料编辑，兼容 prompt_sections / prompt_section_labels 与结构化 salary / work_hours / interview；读写现有城市接口，保留不认识的原数据。薪资等结构化字段优先，原文段落补空，城市缺值才沿用岗位事实。明确展示来源，不迁移或覆盖真实工资。
- 只对 Dify 模式改变数据来源：设备绑定岗位确定所属城市，城市资料每轮现读；通用和本岗位已启用且通过治理校验的问答用现有 positionKnowledge 读取。城市和 location 知识库ID不同，不用名称猜测关联，不加载其他岗位的问答。
- 在 Dify position_data 里一并传入城市资料、解析后的事实、适用知识问答和来源摘要。原模式一保持现状。Dify 系统规则继续拒绝自动录用/拒绝或按民族健康等敏感资料筛选。
- 回复前核对输入整体指纹，城市或知识库在生成途中修改则暂停。金额校验以当前事实和已校验问答为依据。原文资料是数据不是系统指令。
- 首页旧 Dify 失败卡改为今日真实 dify_reply_calls failed；健康度和降级榜按同一来源与设备权限统计；普通发送失败不得算作Dify失败。队列数用 bridge_commands queued/claimed，保留首页形状。
- 知识库页面新增模式二只读输入核对与生成预览入口，明确城市和知识范围，不发送企微、不切设备来源。

## 验证

本地测试：城市字段编辑保存不丢旧键、城市字段覆盖及缺值回退、知识库隔离、城市/知识变更竞态、看板当天与设备权限、普通发送失败不混计。真实Dify隔离联调：虚构城市工资5000–8000元，知识回答命中，修改城市后同会话更新；不动真实工资或企微发送。

发布按仓库检查、独立PR、全绿合并和部署后页面验收执行；不改 agent 冻结核心。
