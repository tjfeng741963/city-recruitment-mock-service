# 招聘流程图页面设计

## 背景

当前实际流程按岗位保存在 4222 的 `agent_flow`、`agent_flow_node`、`agent_flow_edge` 表中，并通过 `/api/v1/agent-flow` 读取和保存。岗位配置抽屉只有顺序卡片式的简化编辑器，不能展示分支关系，也不能拖动节点或编辑完整边条件。操作人员难以理解当前真实流程。

现有后端接受的节点类型为 `text`、`image`、`video`、`followup`、`branch`、`end`。前端只管理这些已支持的类型和字段，不展示虚构的资料采集能力。节点级停用会同步到图校验和 Windows 运行器，让配置状态与实际行为一致。

## 目标

- 在左侧“知识管理”下新增独立的“流程图”页面。
- 按招聘岗位选择流程；页面展示接口返回的真实保存流程，包括启停状态、版本、节点、连线和入口。
- 允许拖动节点并编辑现有节点、连线参数。
- 通过现有 `agentApi.flowGet`、`flowSave`、`flowMigrate` 接口读写，不新增后端接口或数据字段。
- 将岗位抽屉里的流程编辑入口统一到新页面，避免两套编辑器产生不同理解。

## 页面与交互

页面沿用当前 Vue 3 + Element Plus 后台的布局、组件、色彩、间距和文案风格；不另建一套导航、按钮、表单或状态视觉。画布节点和连线是唯一新增的专用交互，属性区继续使用现有 Element Plus 控件。

顶部工具区提供岗位选择、流程状态、版本、未保存提示、保存、从开场生成停用草稿，以及适配画布等操作。岗位选择后读取该岗位已保存流程；无流程时显示空状态，不伪造示例数据。

画布以节点位置 `x/y` 绘制节点，以 `edges` 绘制带触发标签的连线。节点可拖动，拖动只更新画布坐标。入口节点有明确标记；选择节点后在右侧属性区编辑节点参数，选择连线后编辑目标、关键词和优先级。可从等待回复节点或分支新增可选关键词连接并删除可选边；`default` 与 `any_reply` 主出口不能删除。`timeout` 连接在关联启用复聊节点时不能删除；没有启用复聊目标时可删除。关键词边只在等待节点和分支上执行，按优先级从高到低检查不区分大小写的包含匹配。分支没有关键词命中时沿 `default` 出口继续。新增节点、删除节点与入口调整需维护连通图；删除入口或最后一个节点时阻止操作。更改入口会预览不可达的启用节点，并在确认后将其停用。

节点编辑只暴露后端当前认可的字段：

- `text`：标题、1 到 6 条文本/媒体 parts、每条延迟、是否等待回复、等待分钟数。
- `image` / `video`：标题、已授权素材、消息延迟、等待设置。
- `followup`：一次性文本和 timeout 触发；遵守后端只允许一条文本的限制。
- `branch`：标题及其出边条件，不含消息。
- `end`：结束节点，不含消息和出边。

流程保存保留读取时的 `version`，使用现有服务端乐观并发校验。服务端返回 409 时提示流程已被他人更新，停止覆盖并要求重新载入。离开页面、切换岗位或刷新时，如果有未保存的修改，先确认是否丢弃。停用流程可以保存草稿；把流程切为启用时显示确认，且阻止启用仍有默认占位话术、空文本或未选择媒体的启用节点。保存成功后重新以服务端返回值作为页面状态。流程启停仍遵循服务端契约：只阻止/启用新会话，已开始会话继续使用本地快照。

节点级停用必须在服务端图校验和 Windows 运行器中同时生效：停用节点保留在图上供编辑与恢复，但运行器不得发送其 parts；执行应通过该节点的主兜底出口继续。分支停用走 default 出口，等待节点停用走 any_reply 出口，不触发 timeout 复聊。若没有可继续出口，流程结束。单节点停用要确认提示被绕过的节点及其关联超时复聊也会一并停用。进行中的会话使用本地快照，节点状态变更不改写它。

岗位抽屉移除现有流程编辑控件，改为显示该岗位的流程状态并提供“打开流程图”入口，跳转到新页面并预选当前岗位。人设和开场仍留在抽屉。

## 数据与边界

- 单个页面只编辑当前选中岗位的流程；不同岗位互相隔离。
- API 是流程内容和状态的唯一事实来源。页面不读取或推断客户是否正在某个流程节点。
- 首版不新增节点类型、不改变 LLM 调用、不自动启用迁移草稿、不修改回复发送动作或冻结核心。
- 后端图校验继续作为最终校验：入口必须有效、启用节点的执行路径必须连通、触发条件合法；停用节点可保留入边/出边以供运行器绕过；启用复聊必须连自启用等待节点；分支匹配顺序与 default 兜底须同 Windows 运行器一致；媒体必须属于岗位或通用池，启用流程的文本数字必须能在岗位事实中找到。
- 已有在途会话使用本地流程快照；页面保存新版本不会重写在途会话。

## 实现范围与验证

实现包括 Vue 前端、4222 流程图校验和 Windows `autopilot.py` 的节点执行器：增加独立流程图页和菜单入口，复用当前 Agent API 与纯图工具，更新岗位抽屉跳转入口，并使停用节点在新会话执行时被跳过。分支运行沿用现有执行器行为：关键词按优先级从高到低做不区分大小写的包含匹配，未命中时沿 `default` 出口继续。新增测试覆盖页面路由/菜单、按岗位加载真实流程、拖动坐标变化、节点与边参数编辑、保存提交版本、409 冲突不覆盖、启用确认、路由离开保护、入口变化后的不可达节点停用、启用内容校验、后端接受有连接的停用节点、运行器绕过停用节点、分支关键字/default 运行，以及抽屉岗位跳转。

验证包括 Vue TypeScript 构建、聚焦的流程图页面与图编辑器测试、现有 `agent-flow-editor` 测试，以及 Node 主站测试。测试不得启动自动回复、打开企业微信、扫码或发送消息。
