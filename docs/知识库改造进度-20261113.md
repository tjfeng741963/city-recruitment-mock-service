### 5.1 Node 配置接口（P1-2）

`src/modules/agent/kb-v3.routes.ts`，写操作仅管理员：

| 接口 | 说明 |
|---|---|
| `GET/POST/PUT/DELETE /api/v1/verticals` | 品类。删除时若还有招工方引用 → 409 + `blocking.employers` |
| `GET/POST/PUT/DELETE /api/v1/locations` | 位置树。`level` 是开放字符串；`parent_id=-1` 表示只取顶层；删除时有子级或被招工方引用 → 409 |
| `GET/POST/PUT/DELETE /api/v1/employers` | 招工方，含 `aliases`（传了即全量替换，不传不动）。删除时若还有场景问答 → 409 |
| `GET/POST/PUT/DELETE /api/v1/kb-faqs` | 场景问答。`scope_level` 与对应 id 强制配套（`employer` 必须带 `scope_employer_id`），否则检索永远命中不到 |
| `GET /api/v1/kb-templates`、`/:code` | 模板包列表 / 详情，`item_count`、`keywords`/`media` 解析成数组 |
| `POST /api/v1/kb-templates/:code/import` | 一键导入，同 `question` 跳过，不覆盖运营改过的内容，返回 `{imported, skipped}` |

两个设计点：

- **删不级联**：被引用就回 409 并说明谁在用，运营能看懂，也不会误删掉正在跑的问答。
- **手改即断模板链**：运营改过 `kb_faq` 后默认 `template_item_id=null`，避免下次模板升级把人工修订覆盖回去；要保留得显式传 `keep_template_link=true`。

### 5.3 存量回填（P1-4）

`024_kb_backfill_legacy.sql` + `src/db/backfill.ts`：

| 旧表 | 新结构 | 编码规则 |
|---|---|---|
| `cities` | `location`：`province` → `city` 两级 | `LEGACY-C{旧id}` |
| `factories` | `employer`（品类 factory） | `LEGACY-F{旧id}`，`location_id` 取所在城市 |
| `factories` 全名 | `employer_alias`（weight=10） | 便于按名称反查 |
| `service_positions` | `position_location` | 挂到所属工厂的位置 |

三条必须记住的：

1. **迁移先于种子跑**。全新库里 024 执行时 `cities`/`factories` 还是空的，只靠迁移会插入 0 行。所以 `server.ts` 在 `seedDatabase()` 之后再调一次 `backfillLegacyKb(db)`。
2. **省份要去重后插**。`NOT EXISTS` 是逐行判定的，同一省份的三条 `cities` 行互相看不见，直接写会插三份「广东」。
3. **旧表只读不写**。回填全部是 INSERT，出错整条删掉重跑即可，旧链路零影响。
