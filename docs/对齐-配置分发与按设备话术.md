# 对齐：配置分发、按设备话术、按城市工厂（2026-11-10 晚）

> 中控契约。三个 agent：**Node+客户端**（`src/`+`agent/`）、**Python flow**（`backend/`）、**前端**（`frontend/`）。
> 目录即边界，越界即返工。

## 一、总模型

```
服务器（4222）= 总库 + 分发
  ├─ 城市表 cities(province) / factories / service_positions   ← 运营管理页维护
  ├─ device_scripts(device_code 绑定话术)                       ← 新表
  └─ GET /bridge/devices/:code/config                           ← 分发出口（version 热更）

客户端 = 持有 + 执行
  ├─ 启动拉一次 config → 缓存本地（config.remote.json）
  ├─ 每轮心跳比对 version，变了重拉
  └─ 发送话术时：本机缓存优先，本地 config.json 兜底

flow（8090）= 编排
  ├─ 岗位信息按城市向 4222 查（缓存 60s，失败回落 DEMO_JOBS）
  └─ 话术按 device_code 从 config payload 里带出
```

## 二、接口契约

### 1. 配置下发（Node 新增）

```
GET /api/v1/bridge/devices/:code/config
→ {
  "version": "2026-11-10T22:00:00Z",          // data_json.updated_at 即 version
  "interval_seconds": 20,
  "cooldown": 8,
  "merge_delay_seconds": 0,
  "scripts": [                                 // 该设备绑定的话术，可为空数组
    {"stage": "send_info", "city": "深圳", "title": "龙华厂标准介绍", "content": "..."}
  ]
}
```
- 数据源：`agent_devices.data_json`（运行参数）+ `device_scripts`（话术）
- version = 两者的 max(updated_at)，客户端只认字符串不等
- 鉴权沿用 bridge 设备 token

### 2. 设备话术（Node 新表 + 路由）

```sql
-- 019_device_scripts.sql
CREATE TABLE IF NOT EXISTS device_scripts (
  id INTEGER PRIMARY KEY,
  device_code TEXT NOT NULL,
  city TEXT NOT NULL DEFAULT '',
  stage TEXT NOT NULL DEFAULT 'send_info',     -- ask_city/send_info/ask_interview/collect/done
  title TEXT NOT NULL DEFAULT '',
  content TEXT NOT NULL DEFAULT '',
  status TEXT NOT NULL DEFAULT 'enabled',
  created_at TEXT, updated_at TEXT,
  UNIQUE(device_code, stage, city)
);
```

```
GET    /api/v1/agent/device-scripts?device_code=&stage=&city=
POST   /api/v1/agent/device-scripts          （upsert by device_code+stage+city）
DELETE /api/v1/agent/device-scripts/{id}
```

### 3. 按城市查岗位（Node 新增，给 8090 用）

```
GET /api/v1/agent/jobs?city=深圳
→ {"items":[{"factory_name":"龙华电子厂","job_title":"质检","wage_text":"20 元/小时",
   "hours_text":"两班倒，月休 4 天","age_text":"18-45 岁","welfare_text":"包吃包住",
   "place":"龙华大浪街道"}]}
```
- 数据源：`service_positions JOIN factories JOIN cities`（`data_json` 里取工价/吃住/年龄/地点）
- city 按别名归一（广州/番禺 → 同城）；查不到返回 `{items:[]}`
- 鉴权：`X-Profile-Token`（复用现有服务间通道）

### 4. 客户端拉取（agent/）

- `agent/client.py` 加 `fetch_config()`
- `autopilot.py`：启动拉一次存 `config.remote.json`；心跳时比对 version，变了重拉
- 合并规则：**远端有就用远端，本地 config.json 兜底**；`scripts` 原样存缓存
- 失败静默：拉不到就用本地，不打日志刷屏（每次启动记一行即可）

### 5. flow 使用（Python）

- `send_info` 段 1 数据源改为：`GET /api/v1/agent/jobs?city=`（带 60s 缓存 + `X-Profile-Token`），空结果回落 `DEMO_JOBS`
- 话术选择顺序：**config.scripts 匹配（device+stage+city）→ 知识库 kb_entry → 模型生成**；命中 config 话术时模板字段（厂名/工价）由代码替换 `{{factory}} {{wage}}` 占位符，防止模型改数字
- 请求里 `device_code` 已有（`FlowAnswerIn.device_code`）
