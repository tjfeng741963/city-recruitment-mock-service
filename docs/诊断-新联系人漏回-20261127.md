- 13:28，北京时间，新 Win 读到了新好友事件和对方消息，网页也收到同步。企微会话还没有名称，回复账本直接记为跳过。此后该会话已有三条企微出站记录。该会话无需补发开场。
- 会话名缺失修复会按当前企微账号及对方 ID 从通讯录补名。近期漏回只在最新入站仍一致、没有后续出站且收件人仍可核验时回到原流程。旧记录及已发记录留在账本。
- 14:58，新版对另一条已入队的开场进入企微会话，停在标题核验，正文未粘贴也未发送。同一张标题截图连续两次用简体中文 OCR 都读错了四字母昵称，连续两次用英文 OCR 都完整读对。网页心跳和 Agent 回复模式均正常。
- 英文昵称、带英文字母的 ASCII 备注码使用 en-US 识别。英文语言包不可用时沿用中文识别。中文、混合昵称和纯数字维持现有识别语言。发送前仍要求标题精确匹配，并检查企微窗口及标题保持一致。改动可通过上一已验证客户端包回滚，保留本地配置和账本。
- 发布验收按客户端版本和在线心跳、自动回复进程、回读到目标会话的企微出站记录逐项确认。已有开场出站的会话和发送结果不明的会话禁止批量重放。

## 长开场出站确认

新版客户端重新处理一条未发送的开场，企微目标会话出现唯一出站。企微将这条正文保存为 25 个连续纯文本片段，旧回读只取中间一段，导致发送成功后被挂为待核对。按顺序还原后，正文与实际发送内容逐字一致。

回读补丁只在已有标题核验、已执行正文发送回车、冻结发送器未报告其他会话且目标账户未变化时启用。它仅接受已知文本片段结构，以及目标会话中唯一新增、正文完全一致的出站记录。旧发送结果待核对时不得重放。

## 短中文标题无法识别

15:03，第一起故障会话又有一条新入站。按原有单条恢复入口重跑问答，生成和发送前检查继续执行，但标题识别返回空，企微没有出站。同一帧经现有二值化之后多种尺寸均识别为空。保留同一标题内的灰度笔画并放大两倍后，Windows OCR 完整识别。备用图与原图来自同一帧，仅中文及混合名称在首次读空时重读，非空误读仍按原有完整标题校验拦截。

## 发送前核验回归

一次发布允许已知昵称唯一时继续发送，即使企微当前标题无法读取或读到了别的称呼。实际发送后的企微回读只能核对结果。回退该放行分支，并增加两条回归，覆盖通讯录唯一但标题不可读、通讯录唯一但标题显示另一联系人。两种情况下只允许既有的搜索回车，正文发送回车不执行。关闭错误放行后，暂停记录仍保留在账本。

## 混合昵称符号误读

16:29，北京时间，新 Win 已将客户来信同步到网页。Agent 正常生成回复，企微选中会话后卡在发送前标题核验，目标聊天没有这次问答的出站记录，来信保留在本地账本。

用三张故障现场标题图测试，Windows 原尺寸灰度识别能读全其它字符，但将波浪号读为中点。新版只在整行标题仅差这一处时，从同一帧取该字形的像素验证波形，并检查通讯录和备注中是否存在相近的其他联系人。OCR 完成后、粘贴前和发送回车前再次校验企微账号、前台窗口和标题。沿用原发送动作和企微出站回读，无需增加 OCR 依赖。

原常驻队列对一小时内、发送次数为零的同类暂停记录至多自动恢复一次。恢复要求当前仍是同一条最新来信，且没有后续出站、未确认发送或人工接管。之前卡住的问答走正常 Agent 问答。有出站历史的开场暂停记录继续保留。用上一个已核验的正式 Windows 包可回退，保留原配置、同步游标和回复账本。

## 普通自动回复没有使用已核验的备注

新 Win 的自动回复读取到了「现在23了吗」。企微本地联系人记录将界面中的唯一备注关联到正确的会话成员，但发送前只查昵称，误判无法核对收件人。另有空白昵称和仅逗号的昵称，在本地分别有 11 和 2 位联系人共用，且目标联系人没有独立备注。

普通自动回复现在从当前企微账号和会话 ID 找到准确的联系人。已有备注可以作为搜索词。昵称或备注重复、备注被移动、读取失败或现场标题不符时保持暂停。新来的未核验消息进入待回复账本，之后有唯一备注且话题仍是最新时由常驻队列处理。旧记录按既有一小时窗口及出站记录核对。已有对话的待回复走问答，首次接待仍走正常开场。

## 11 月 28 日自动回复受阻及恢复入口

常驻程序、企微和网页心跳仍在线，但多次发送停在企微标题核验。Win 管理器之前只根据进程存活禁用「启动回复」，业务受阻时也无法从该按钮恢复。

同一前台窗口的放大标题图漏读日期及汉字，原尺寸灰度可完整读出带日期的备注。客户端增加原尺寸的完整匹配并记录失败阶段。发送前仍核对账号、会话标题及窗口，最终以企微目标会话的出站回读为准。纯字母标题 O_o 在已有识别样本中仍可能被读成数字，需使用能核验的唯一备注。

「启动回复」在已停止时启动进程，运行且发送受阻时显示「恢复回复」并复用确认重启。最近的收件人核验失败会在本机及网页心跳中显示，常驻队列继续处理其他会话。仅自动重试一小时内、零次发送且仍是最新的安全候选；已有出站历史走正常问答，避免重播开场。回滚使用上一校验通过的客户端包。
