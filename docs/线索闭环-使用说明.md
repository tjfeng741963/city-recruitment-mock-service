# 线索闭环 · 使用说明（急停开关）

> **最重要的一句：关掉抽取后，自动回复完全不受影响。**
> 回复链路（收消息 → 生成回复 → 发送）一行都不读开关文件；关掉抽取只是不再判断谈单进行到哪一步，
> 客户照样有人回。所以「判不准」时不要犹豫，先关节省算力和风险，回复照常。

## 为什么要有开关

系统通过读企业微信本地加密库 + 模拟键鼠收发消息，已被风控处置过三次。
只要模型开始乱判、或者成本突然飙升、或者顾问反馈「状态全错了」，必须能**不停后端、一条命令关掉**，
所以用「文件存在即关闭」：`touch` 一个文件，下一次判定立刻生效，不用改环境变量、不用重启。

## 两个开关各管什么

| 开关文件（在 `backend/data/` 下） | 管什么 | 关掉后 |
|---|---|---|
| `LEAD_EXTRACT_OFF` | **抽取＝判状态**：每轮会话后让模型判断 stage（new/asking/intent/booked…）、到面情况 | 不再调模型判状态；已有 leads 数据保持原样，不新增、不改写；**回复不受影响** |
| `LEAD_SWEEP_OFF` | **扫描＝标待核实**：到点的约面打上 `pending_confirm=1` 并写一条 `check_pending` 事件 | 不再产生「该问一句」待办；不写库、不发消息 |

两者互不影响，可以只关一个。扫描本身零 LLM、零发送，一般只在页面待办太多时临时关。

## 什么时候该关

- **模型乱判**：同一客户反复在 booked/intent 之间跳、把「再看看」判成已约面；
- **成本异常**：抽取调用量或 token 消耗突然翻倍、日志里 LLM 超时/重试变多；
- **客户投诉判定错误**：顾问发现状态与事实不符，且短时间内纠正不过来；
- **任何说不清原因的异常**：先关抽取（代价只是少记状态），再排查。

关闭时不需要改代码、不需要重启，命令见下。

## 命令

在仓库任意目录执行（脚本路径基于自身位置推导，与 cwd 无关）：

```bash
bash backend/scripts/lead_switch.sh off            # 两个都关
bash backend/scripts/lead_switch.sh off extract    # 只关抽取（最常用）
bash backend/scripts/lead_switch.sh off sweep      # 只关扫描
bash backend/scripts/lead_switch.sh on             # 全部打开
bash backend/scripts/lead_switch.sh status         # 打印状态
```

`status` 输出形如：

```
抽取：开启 / 扫描：关闭
开关目录：/c/Users/xxx/city-recruitment-mock-service/backend/data
```

## 回滚（重新打开）

```bash
bash backend/scripts/lead_switch.sh on           # 两个都恢复
bash backend/scripts/lead_switch.sh on extract   # 只恢复抽取
```

恢复同样立即生效。确认 `status` 输出「开启」即可，不必重启后端。

## 灰度建议：默认关 → 单顾问观察 1 天 → 全量

1. **默认关**：上线时先 `off extract`，让系统只回消息、不判状态，确认回复与发送都正常；
2. **单顾问观察 1 天**：`on extract` 后只挑一位顾问的会话走抽取，盯 24 小时——
   看 `leads` 的 stage 是否与实际一致、`LeadEvent` 是否有明显错判、token 消耗是否平稳；
3. **全量**：单顾问一天无错判、无投诉，再放开所有人。扫描（sweep）同理，且其默认配置为关闭，
   需要时再开 worker。

任何一步出现异常，回到第 1 步即可，不需要回滚代码。

## 为什么开关文件不能提交 git

- 它们是**运行期状态**，不是配置：提交上去等于把「关闭」永久带给所有人和所有环境；
- `backend/data/` 已在 `backend/.gitignore` 中（`data/`），开关文件、数据库、实例信息都不会进仓库；
- 排查时若怀疑开关残留，`bash backend/scripts/lead_switch.sh status` 一眼可见，
  也可以直接 `ls backend/data/LEAD_*_OFF`。

## 给实现者的调用契约

```python
from app.services.lead_guard import extract_enabled, sweep_enabled

enabled, reason = extract_enabled()   # -> (bool, str)，关闭时 reason 非空
if not enabled:
    return {"changed": False, "reason": "抽取已关闭"}
```

- 返回 `tuple[bool, str]`：`True` 时字符串为空，`False` 时中文原因可直接写日志/接口返回；
- 每次调用都实时 stat，**不要自己在外面缓存结果**，否则开关又需要重启才生效；
- 目录锚定 `__file__`（`backend/data`），环境变量 `LEAD_GUARD_DIR` 仅测试用；
- 目录不存在时按「开启」处理，不抛异常。
