## 任务 1：前端功能适配（P0，约 3 天）

### 1.1 配置下发通道（2 天）— 最高优先级

**为什么最优先**：现在改 `target` / `cooldown` / `interval` 只能改本地 `config.json` 重启。客户有 10 台机器就是 10 次人工。

```
新增 GET /api/v1/bridge/devices/:code/config
  返回: agent_devices.data_json 里的运行配置 + version
客户端启动拉取一次 → 缓存为运行时配置
每轮心跳比对 version → 变了就重拉
```

**原则**：服务器配置优先，本地 `config.json` 兜底。

**改动文件**：

| 文件 | 改动 |
|---|---|
| `src/modules/messaging/device-bridge.routes.ts` | 新增 `GET .../config` |
| `src/modules/messaging/device-bridge.ts` | 加 `configVersion(code)` |
| `agent/client.py` | 加 `fetch_config()` |
| `agent/autopilot.py` | `load_config()` 后合并远端；心跳比对 version |

**不改** `send.py`（动作序列保持冻结），**不改**表结构（配置本来就在 `data_json`）。

**验收**：网页改「合并等待 0→3 秒」，客户端 30 秒内日志出现新值，无需重启。

### 1.2 补 `/api/v1/unknown-questions`（0.5 天）

前端「未知问题」页面会 404，是唯一缺失的接口。

### 1.3 设置项真正落地（0.5 天）

把 `data_json` 里的 `merge_delay_seconds` / `timeout` / `quiet_hours` / `event_rules` 读进 `autopilot.py`。

现状：`grep -rn "followup\|reminder-config\|agent-rules" agent/*.py` → **0 命中**。

**风险**：转发频率高会挤占自动回复的时间窗。

## 任务 5：发送图片与地址（P1，约 3 天）

### 5.1 图片发送（2 天）

**现状**：`send.py` 的 `_send_once` 全程 `Ctrl+V` 粘贴**文本**，无图片分支。

**方案 A（推荐）：剪贴板带图片**

```
用 win32clipboard + PIL 把图片写入剪贴板（CF_DIB 格式）
→ 点击输入框
→ Ctrl+V 粘贴
→ Enter 发送
```

优点：不改动作序列，只换剪贴板内容，复用现有焦点/校验逻辑。

**方案 B：模拟「发图片」按钮**
不可靠：会弹出系统文件选择对话框，需要处理额外的窗口和路径输入。

### 5.2 地址发送（0.5 天）

- **纯文字地址/地图链接**：现在就能发，零改动
- **卡片式位置消息**：需要另一套 UI 操作，成本高，建议不做

### 5.3 素材管理（0.5 天）

- `kb_asset` 表已存在（`backend/app/models_kb.py`）
- 前端上传 → 存本地路径 → 客户端发送时按岗位取图

## 建议推进顺序

```
第一周   任务 1.1（配置下发） + 任务 4（改名，纯前端，最快见效）
第二周   任务 3（知识库，依赖客户资料）+ 任务 2（转发）
第三周   任务 5（图片发送）
```

**理由**：

- **1.1 是地基**：其他所有「网页上改设置」的功能都依赖它

- **任务 3 依赖客户资料**：需要提前催客户给聊天记录，否则会阻塞
