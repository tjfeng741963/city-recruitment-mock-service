## 方法

## 当前用户应如何编辑

- 启用的节点流程：进入“AI 接待→话术流程”，选岗位，再选“编辑流程”。点击节点后在右侧改原文、选择素材、设置每条发送后间隔、等待开关和等待分钟数。改发送顺序要选择连线并改目标，拖动节点只改坐标。保存后，已绑定该岗位的客户端在下一轮流程刷新时取得新版本。
- 深圳当前节点图为停用 v1，实际设备没有绑定深圳。修改这张停用图不会替换现行旧开场。旧开场需从“招聘资料→招聘岗位→该岗位接待话术→开场”编辑；当前旧客户端进程缓存旧开场，保存后还需重载客户端实例才能使用新值。
- AI 按需图片/视频分支只是来源和条件说明，素材内容/归属在“本岗位图片视频”管理，回答依据在“本岗位问答”及岗位资料/人设维护。它们不是固定发送步骤；若要求每个新客户固定收到图片，应明确添加到启用节点流程。

## 问题与修复范围

1. **远程版本不一致**：发布和安装不是同一步。网页已经有停用节点功能，云 Windows 仍用 `0578519`，因此停用配置被忽略。需要通过现有更新器升级并在业务就绪后重新验收，不能只用 Release 发布成功当作已安装。
2. **旧开场没有热更新**：`Brain.opening()` 只在 `_opening is None` 或 `force=True` 时重新拉取；业务调用不主动 force。网页修改旧开场不是“等一分钟就生效”。
3. **节点间隔误导**：`_run_flow` 使用 part 的 delay，node delay 仅在 part 缺该字段时回退，而服务端会给每个 part 补默认值。应统一为每条实际发送后间隔，或定义并实现独立节点间隔后再暴露该控件。
4. **入口不统一**：停用流程的旧开场无法在运行图直接编辑；AI 按需媒体也是只读。用户必须区分三种入口，目前还不够直观。

本轮按“仔细实测”请求只做验收与记录，没有改业务源码或擅自更新 Windows。以上问题不能以测试替身通过宣称全部解决。
