### 2.2 客户端

**定位消息不再被丢掉**（PR #78，**未合并**）

企微把定位存成 `content_type=48`，而 `agent/wecom_io_core/store.py:397` 只对文本类型
（2 / 573）提取正文：

```python
text = _pb_text(r["content"]) if ctype in (2, 573) else ""
```

所以定位消息的 `in_text` 恒为空。到了 `drain()` 里两处 `if not hint`：

```python
if not hint:                      # 流程等待节点
    rlog.mark_skipped(mid, cid, "空系统事件不推进等待节点")
if not hint and not dry:          # 自由对话
    res = {"ok": False, "detail": f"消息没有文本（type={it['in_type']}）"}
```

两边都把它当空事件跳过了。客户明明发了东西，Agent 既不推进节点也不回话。

改法是新增 `_inbound_hint()`（与 `_media_label()` 放在一起），文本照旧返回原文，
**已登记**的非文本类型退化成可读提示：

```python
_INBOUND_HINTS = {
    48: "客户发来一个定位，可能是在问面试地点或确认自己的位置。",
}
```

只放开定位。图片 / 视频保持原来的跳过行为；加好友、撤回这类系统提示（type≈1011）
不在映射表里，仍旧按空事件处理，不会突然开始回复系统消息。

**没有做、也不该做的事：让 Agent 发原生定位卡片。**
`agent/wecom_io_core/send.py` 只有 `send()` 打文本和 `paste_media()` 走剪贴板贴图两条路径。
补「位置」动作要在企微里点「+」→ 位置 → 搜索或翻收藏，是一串坐标点击，
而 `wecom_io_core/` 是冻结区，`AGENTS.md` 明确禁止没有实测证明就加鼠标坐标动作。
Agent 永远用「文字地址 + 地图图片」替代。

## 5. 交接时必须说明的风险

- 这是本地企微库读取和键鼠发送方案，没有接入企业微信官方客户联系 API。
- **Agent 发不出原生定位卡片**，这是冻结区的硬约束，不是待办。客户发来的定位我们也
  只当作「客户发了东西」处理，不解析地名或坐标。
- 设备显示 online 只代表心跳，不等于桌面一定可发送。
- 接口返回成功只代表拿到文案，不代表客户已经收到。
- `agent/wecom_io_core/` 是冻结的发送动作层，任何改动都可能导致企微风控、
  隐藏窗口或重新扫码。
- 素材库文件存在服务端 `data/media/<sha256>.<ext>`，**没有任何异地备份**。
  部署用的 `git clean -fdx -e data` 保住了 `data/`，但机器挂了、磁盘满了就没有第二份。
- 流程停用只阻止新流程；已经开始的会话使用自己的流程快照。
- 不能通过清库、删除状态或批量重试来掩盖发送失败。

## 6. 回滚方法

### 服务端 / 网页端

用 Git revert 合并出来的提交，推送 `main` 触发流水线部署旧行为。
禁止 force push 或直接改写远程历史。

### 客户端

1. 停止唯一的 sender / autopilot 进程。
2. 保留 `reply_log.db`、`flow_state.db` 和日志。
3. 用更新时生成的 `xxx.py.bak-YYYYmmdd-HHMMSS` 逐文件回滚。
4. 确认旧版本不再读取新的流程状态后，才允许恢复运行。

不要直接把旧客户端覆盖回去后立即启动，旧客户端不认识新的流程游标和状态文件。
