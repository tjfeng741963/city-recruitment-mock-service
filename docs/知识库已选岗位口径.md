# 知识库已选岗位口径

本次修复 `POST /api/v1/flow/answer` 的岗位上下文选择，不改变数据库结构或 FAQ 作用域层级。

## 取值顺序

1. 在 FAQ 检索前加载本轮设备、城市下的岗位，清空没有城市或加载失败时的注入。FAQ 渲染不再读上轮 ContextVar 中的岗位数据。
2. 会话已有 `position_id` 或 `job_snapshot` 时，按该岗位精确找本轮条目。找不到只用该会话的岗位快照，不借列表第一条。
3. 尚无会话选择时，设备明确绑定的 `position_id` 可用于精确查找。没有明确 id 且只有一个岗位时可用该岗位；多个岗位不能默认用第一岗的政策。
4. FAQ 的雇主、位置及旧知识库的厂名均从同一份上下文取。已有会话选择时，缺字段不借设备默认工厂；城市优先使用会话城市。
5. 同岗位仍在列表中时，用本轮条目的最新动态字段。条目消失或远端不可用时，快照仅作为该会话已看过的信息，不代表岗位仍在招。

## 换岗与事件回放

发卡的 `pin_position()` 同步替换岗位、雇主、位置 id 和岗位快照。无效或缺失 id 写 `0`；不能只从内存字典删除，因为 `diff_slots()` 只记录字典内的键，删除不会形成清除事件，旧值会在下轮回放时恢复。

快照保存岗位可渲染的标量字段，包括体检、纹身等动态字段；媒体数组和嵌套对象不写入文本快照，身份 id 使用独立槽位。新岗位的空快照也覆盖旧快照，避免沿用前厂资料。

## 旧知识库回退

flow 接口对 `kb_placeholder.lookup_entry()` 启用 `require_factory=True`。已知工厂仍按原有简称匹配和城市过滤；未知工厂时排除具名工厂条目。其他旧调用不传此参数时保持原接口语义。

## 边界

本次修复上下文选错造成的串厂，不自动改写运营内容。FAQ `global/city/vertical` 中写死的体检、纹身、工价等口径，以及旧知识库未标厂归属的正文，仍可能包含不适用内容；应配置为雇主/岗位作用域，或使用本岗事实占位符。需要进一步制定通用内容准入规则。

历史会话快照未保存某动态字段且岗位也查不到时，不从别岗补齐该字段，按原有未知问题/兜底流程处理。测试均为本地合成数据，没有真实模型调用或企微实发。
