## 一、这套系统在干什么

企业微信里客户来问招工信息 → 电脑上的客户端自动用键盘鼠标回复 → 会话和线索同步到服务器 →
人在网页上看会话、看线索、必要时人工接手回复。

```
客户（微信）──发消息──→ 你电脑的企业微信 ──读取本地加密库──→ autopilot（Python）
                                                                    │
                                              ① 心跳/上报/知识库问答 ↓ ② 桥接心跳/会话上报
                                                                    ↓
                                              ┌─────────────────────┴──────────────────┐
                                       8090 Python 后端                        4222 Node + Vue
                                       （会话/线索/看板/设备）                  （配置台/会话/激活）
                                       PostgreSQL 5435                           SQLite
                                              └────────── 同一台服务器 119.91.113.100 ──┘
```

**关键点：回复内容由服务器知识库生成，客户端只负责"读消息 + 敲键盘"。**

## 四、数据链路（四条，都在跑）

| 链路 | 方向 | 周期 | 作用 |
|---|---|---|---|
| 主心跳 | 客户端 → 8090 | 30s | 设备在线状态、看板红条告警 |
| 增量上报 | 客户端 → 8090 | 30s | 新消息同步、会话记录 |
| 桥接心跳 | 客户端 → 4222 | 30s | Vue 设备页绿点 |
| 会话上报 | 客户端 → 4222 | 30s | Vue 会话列表实时可见（`observe_only` 只记录不回复） |
| 指令领取 | 客户端 ← 4222 | 10s | 控制台人工发消息 → 键鼠真实发送 |
| 实时推送 | 4222 → 浏览器 | 事件驱动 | SSE，事件到 DOM 约 73ms |

### 防重复回复（重要设计）

4222 端设备被标记 `observe_only: true`：**只记录会话和消息，不生成任何自动回复指令**。
自动回复只走 Python 知识库这一条路。人工发送不受此限制（它是指令队列）。

如果哪天要把 4222 的自动化引擎也打开，必须先关掉 Python 侧的自动回复，否则客户会收到两条回复。

## 五、前端说明（最容易误会的地方）

`public/` 里 **只有编译产物，没有源码**（从仓库第一个提交起就是这样，源码在别处构建后拷进来的）：

```
public/index.html                 入口
public/assets/*.js|css            Vue 3 + Element Plus + Router + Pinia（Vite 构建）
public/admin-enhancements.js      手写增强层
public/theme/*.css|js             手写换肤/动效/侧边栏/实时层
```

**要改页面行为，改 `theme/` 下的手写文件，不要碰 `assets/`（构建产物）。**

### 实时是怎么做到的（`public/theme/realtime.js`）

不改 Vue 源码的取巧方案：

1. 普通 script 放在 `/assets/index-*.js` **之前**执行 → 抢到 `window.setInterval`
2. 只劫持 2500–3500ms（消息轮询）和 8000–12000ms（会话列表）两个区间，登记回调
3. 订阅 SSE `/api/v1/agent/stream`，收到事件立刻手动调一次登记的轮询函数 →
   Vue 响应式数据更新 → 页面立即重渲染（实测 73ms，原来是 0–3 秒）
4. 附带：新消息标题闪 + 提示音；发送失败右下角 toast

调试开关：`localStorage.realtime_debug=1` 看控制台日志。

**限制**：如果 Vue 以后把 3000 改成别的值，注入层会静默失效（回归原生轮询），不报错。
改 bundle 后要 `grep -o 'setInterval([^;]\{0,200\}' public/assets/*.js` 核对一次。

## 七、踩过的坑（血的教训，别再犯）

| 坑 | 现象 | 正解 |
|---|---|---|
| **data 目录属主** | 桥接全 500 `readonly database`，消息一条都上不去 | 必须是 `1000:1000`（容器内 node 用户）。**每次 chown 项目目录后都要改回来** |
| `/tmp/app.env` 丢失 | 新容器起不来、端口 000 | 从旧容器导出：`docker inspect --format '{{range .Config.Env}}{{println .}}{{end}}' \| grep -E '^(REA_\|NODE_ENV=)'` |
| git worktree + root 操作 | `reset --hard` 静默不生效（dubious ownership） | 一律用 `sudo -u deploy git -C ...` |
| 新增静态文件不重启 | `/theme/xxx.js` 返回 index.html（text/html） | 新增文件后 `docker restart` |
| 改 public 忘了进镜像 | 容器重建后文件消失 | 提交 git + 重建镜像 |
| 客户端进程被会话回收 | 设备离线几十分钟 | 用 `客户端模式.bat` 或开机自启，不要挂在临时会话里 |
| 企业微信被风控 | 发送时"抢不到前台"、`login_required` | 客户端会自动停手；`login_watch` 会拉窗口提示扫码；不要写自动重登 |

## 八、事故记录

### 2026-11-05 14:17 测试消息误发真实客户

- **经过**：智能体做端到端测试，选的测试会话「我的客服」在企微搜不到，Ctrl+F 回车落空后焦点回到上一个会话（Daylan），消息发给了真实客户。
- **内容**：`?\n=[E2E自测] 人工发送链路 20261105-141739，无需回复`
- **处置**：已超撤回时限，需人工解释；测试会话数据已从库中删除。
- **已加护栏**：
  1. 目标必须是企微会话表中真实存在的**非系统会话**，否则一条按键都不发
  2. 读不到会话列表 → fail-closed（宁可失败不盲发）
  3. 人工发送启用 `verify_db + expect_id`，落点不符直接回执 failed

> **给后来人：任何需要"真的发消息"的测试，先建一个自己的测试微信号当客户，绝对不要用真客户会话做靶子。**

### 2026-11-05 11:16 桥接中断 3 小时

- 原因：运维脚本 `chown -R deploy` 项目目录，把 `data/` 属主也改了，容器内 node(1000) 无法写 SQLite。
- 后果：心跳 500 → 设备判离线 → 新消息全部 409 拒绝，Vue 端 3 小时没有新会话。
- 教训：见第七节第一条。

## 九、已知限制 / 待办

1. **Vue 源码缺失** —— 仓库/服务器/历史全都没有 `.vue`，只有构建产物。要真正改组件（发送状态、图片附件、失败提示样式），需要原始工程。
2. **状态自动刷新** —— 已用注入层缓解（事件驱动刷新），但 `queued→sent` 的最终态仍依赖页面重新拉取列表。
3. **图片/视频不能发** —— 键鼠只能发文本，`sendManualReply` 传图片会当纯文本发出去。
4. **实时层依赖轮询区间** —— Vue 若改间隔，注入层静默失效（不报错、退回原生轮询）。
5. **LLM 未启用** —— 生产回复走知识库模板（准确、口径统一）；配 `APP_LLM_API_KEY` 可升级为模型改写。
6. **线索自动扫描默认关** —— `APP_LEAD_WORKER=false`，到点不自动标「待核实」。
7. **8090 是 HTTP 明文** —— 建议上 443 + 反代。
8. **客户端未做健康守护** —— 进程崩了不会自动重启（开机自启只在登录时跑一次）。可考虑加 watchdog。
