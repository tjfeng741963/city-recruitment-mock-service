## 可确认的故障链

1. 管理窗口把短暂发现 autopilot PID 当作启动成功，只检查进程存在，不检查初始化完成。
2. autopilot 在启动顺序上先初始化、刷新企微数据库，再创建/调用登录二维码上传器。扫码等待和数据初始化耦合。
3. 此次数据库初始化失败使进程退出，未到二维码上传/验证码处理的主循环。网页每三秒刷新也无法使客户端产生新二维码。
4. 管理窗口取消完整定时刷新后，没有额外监测这个稍后退出的进程；截图中的绿色“运行中”属于旧快照。已安装新版不等于业务进程正常。

“未登录导致无法取得数据库密钥”与截图吻合，但目前不能仅据通用异常排除账号目录、权限、企微版本等其他因素；本轮不继续执行密钥提取或修改冻结组件。

## 已实施的修复范围

- 管理窗口读取 `logs/client-state.json`，区分启动中、等待打开企微、等待扫码、数据库初始化、业务就绪、失败/已退出；旧进程 PID 的状态文件不能让新进程直接显示可用。
- `autopilot.py` 先探测企微并启动二维码/验证码链路，只有确认在线后才创建 Store 并执行 `store.refresh()`；初始化失败写入失败状态且不进入发送路径。
- 状态文件使用原子替换写入；管理器仍使用轻量本地状态读取和现有进程快照，不恢复高频阻塞式完整轮询。
- 回归测试覆盖企微未就绪、旧 PID 状态、等待登录、数据库初始化顺序和客户端管理界面状态。验证不启动真实自动回复、不扫码、不发送客户消息。
