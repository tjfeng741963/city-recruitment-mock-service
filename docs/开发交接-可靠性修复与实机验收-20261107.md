## 2. 项目背景，以及这次没有做的事

现有链路有三个主要进程：

| Python FastAPI | `backend/` | 主上报、设备、会话、知识库、线索/看板；现有代码支持 SQLite/PostgreSQL |

Node 的 `observe_only: true` 禁止由 Node 观察入站生成自动回复，**不禁止人工指令，也不禁止本地 agent 的知识库自动回复**。测试中同时使用隔离账号、dry-run 和调用守卫控制发送范围。

前端只有 `public/assets/` 的 Vue 编译产物，手写增强层位于 `public/theme/`、`public/admin-enhancements.js`。没有恢复 `.vue` 源码；不要回到已删除的 React 工程，也不要把直接改压缩 bundle 当成可维护方案。

### 三个容易被下一位误读的细节

1. W09 最初真实流程确实失败：回执比观察先到时，HTTP 到达时间覆盖真实发送时间，旧出站成为新摘要。修复后，原失败的局部恢复和新标记分阶段复验分别通过。原失败/监听超时报告没有改写成成功。
2. W09 最初“已发”实际是在核对企微→小度的出站；后来用户才从“小度”的微信发来反向入站。补验监听首次本机脚本又因 str→Path 类型错误零动作退出；仅修正验收脚本并另存记录，未修改 Store。
3. W06 的 5 秒 socket 超时不能限制整个响应总时长。持续缓慢返回数据时，原客户端 66 秒后仍会收到过期指令；旧 pump 已进入剪贴板检查入口，被守卫拦住。用户确认后修复，24 项新增回归在旧实现中 22 失败/2 通过。首轮修复复验因运行期间补 README 触发一致性守卫而停止；稳定副本新目录复验通过。这些均不代表发生了新的实际发送。

右侧“服务总结/客户详情”侧栏收起后曾单条成功，但没有证明它是所有焦点失败的唯一根因。不要为此添加点击/抢焦点补丁，也不要宣称后台或无人值守发送稳定。

## 5. 新增状态和维护命令，必须理解后再操作

| 状态/命令 | 含义及接手注意 |
|---|---|
| 自动回复 pending/failed | 普通常驻发送进程可能消费；dry-run 也可能登记 pending，因此 dry-run 目录不能直接切到真实发送 |
| 自动回复 held | 知识库异常/空结果等暂停，需要人工审查；恢复服务和普通重启不自动释放 |
| 人工执行 unknown | 结果不明确或执行条件无效；不能解释为“没发出去”，更不能直接重发 |
| 人工 receipt_state=pending | 只说明 HTTP 回执待传，不是允许再发送一次 |
| 人工 receipt_state=acked | 服务端已确认该回执；真实送达仍看状态和实际落点证据 |
| 人工 receipt_state=rejected | 冲突/校验拒绝，需要人工核对，不删除记录来绕过 |
| `--list` | 看记录；不创建 Store、不发送；仍须使用正确的配置和状态目录 |
| `--retry-held` | 仅 held→pending 后退出；不消费队列。没有逐条筛选参数，不要拿它处理混合业务库 |
| `--flush-receipts` | 停止常驻后对当前桥接目标仅补人工回执，不创建 Store/输入/发送/claim；dry_run=true 时跳过 |

`--flush-receipts` 退出码：0 表示当前目标无 pending/rejected，1 表示仍需处理，2 表示配置缺失。维护命令不要求数据目录在线，但仍校验配置字段类型。它会访问配置中的桥接地址，不能在不确认目标的旧目录里盲跑。

`--target` 只限制自动回复采集/处理，**不限制普通 Reporter 的全部上报，也不限制人工指令**。实机验收额外用了 Store 范围过滤器；这不是仓库中的正式账号隔离功能。

新人工指令必须携带有效数值毫秒 `lease_until`。更新 agent 前确认服务端 claim 返回该字段，两端时钟正常；不兼容字段时会停止新执行并 unknown。历史已落盘的成功回执仍原样补传。当前检查不保证任意时钟漂移或冻结 sender 开始执行之后的到期情况。

### 配置与凭据对应关系

| agent 配置 | 应指向/来源 | 不要混淆 |
|---|---|---|
| `server` / `device_token` | Python 主后端及其注册设备返回的 token | 不是 Node pair 的凭据 |
| `bridge_server` / `bridge_token` | Node 桥接及其 pair 返回的 token | 重新配对使旧桥接 token 失效；当前入口重启后读取新配置 |
| `device_code` | 测试设备编码，两套后端需各自注册 | 编码一致不代表 token 通用 |
| `brain.mode=kb` / `brain.base_url` / 认证字段 | Python 知识库问答及实际授权账号 | 不能靠留空或错误地址验证后期待固定文本兜底 |
| `data_dir` | 当前独立测试账号真实 Data 目录绝对路径 | 空值会按冻结核心默认发现账号；错误显式路径退出，不回退 |
| `dry_run` / CLI `--dry` | 测试开始保持 true/显式 --dry | dry-run 仍写本地 pending 和上报，不等于完全不读/不出网 |
| `target` | 自动回复范围 | 不等于 Reporter/人工指令的安全白名单 |

配置文件与状态是运行数据，不提交。不要照抄 `config.example.json` 的默认 false 后直接启动；也不要为本轮单机验收复用生产的设备、管理员认证或桥接 URL。
