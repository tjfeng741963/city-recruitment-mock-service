## 二、岗位数据 → cities / factories / service_positions

### 2.1 工厂 xlsx（13 行，字段几乎与系统 1:1）

| xlsx 列 | 系统字段 |
|---|---|
| 城市 / 区/镇 | cities.city_name（如「广州 番禺区钟村」→ city=广州，区镇入 data_json） |
| 工厂名 | factories.factory_name（松下·万宝、利口福、华荻…全实名） |
| 岗位名 | service_positions.position_name |
| 工作内容 | data_json.work_text |
| 年龄下限/上限 | data_json.age_text（拼「18-40 岁」） |
| 最低/最高工价 + 单位 | data_json.wage_text（拼「21-25 元/小时」） |
| 性别限制 | data_json（只要女生/男） |
| 包吃 / 包住 | data_json.welfare_text |
| 面试时间 | data_json.place + interview 窗口 |
| 有效期 | data_json.valid_until（2026-12-31） |

13 行里 2 行标注「示例行，可删除」→ 导入时跳过。**实际有效约 11 个工厂岗位，全部在广州番禺。**

### 2.2 地铁 xlsx（7 行，结构与工厂完全不同）

列是：城市 / 薪资待遇 / 上班时间及月休 / 基本要求 / 安排线路 / 面试时间 / 联系人 / 面试地址 / 携带资料 / 上岗流程 / 临时备注。

注意：「城市」列实际是**线路组**（广州 / 佛山 / 南昌 / 深圳 / 广东城际佛莞线 / 广东城际穗深线），一行内多线路多班次。

映射规则（建议）：
- 每行 → cities（广州/佛山/南昌/深圳；广东城际并入对应城市或单列）
- 每行 → factories（厂名=「XX 地铁安检」或按线路）+ service_positions（岗位名=安检员，data_json 存薪资/班次/线路/联系人/面试地址整段原文）
- 联系人（聂队长 136…等）进 data_json.contact_text——**面试环节要用**

### 2.3 通用 CSV

只有 2 行示例（标可删除），作为导入脚本的字段校验基准即可，不导入。

## 三、话术 → kb_entry(kind=script)

### 3.1 常用问答模板.txt（5 组，直接建）

| 问 | 关键词（标题用） |
|---|---|
| 有没有日结的工作？ | 日结 |
| 宿舍几人间？有空调吗？ | 宿舍几人间 |
| 要不要押金？ | 押金 |
| 多大年龄能做？ | 年龄要求 |
| 什么时候可以面试？ | 面试时间 |

→ 每组建一条 kb_entry（title=关键词，body=答），导入即可生效，无需重启。

### 3.2 工厂话术 docx（109 段 → 拆约 10-15 条）

内容按主题自然分块：万宝招聘信息 / 转正政策 / 招聘要求 / 体检 / 工资发放 / 工作内容 / 住宿环境。
→ 每块一条：title=「万宝招聘」「转正政策」「住宿环境」…，city=广州，factory_name=松下万宝（可空）。
**注意**：话术里全是具体数字（6847.1 元、底薪 2650），与 xlsx 的 21-25 元/小时**口径不同**（合同价 vs 小时价）——
导入前需要客户确认以哪套为准，或者拆成「长期工价」与「小时工价」两条。

### 3.3 地铁话术 docx（42 段 → 天然的场景问答）

docx 里已经是**场景标题 + 回答**结构：「外宿人员嫌弃面试地址远」「工资待遇不清晰/嫌低」「工作岗位图片…」。
→ 每个场景一条 kb_entry：title=场景名，body=该场景下所有回答段拼接，city=广州（地铁账号主城市）。

### 3.4 灰色口述部分

两份 docx 标题里的「灰色部分口述+文字」——docx 中可能有颜色标记的段落（口述为主，无文字）。
导入脚本需检查 run 颜色，口述段列出清单**请客户文字化**，不要猜。
