# 契约：设备心跳 / 会话上报 / 看板告警

> 本轮多个智能体并行开发，**所有实现必须严格按本文件的字段名和语义**，不得自行改名。

## 一、设备心跳

### 请求

```http
POST /api/v1/devices/{device_code}/heartbeat
X-Device-Token: <device_token>
Content-Type: application/json

{
  "agent_version": "1.0.0",
  "capabilities": {},
  "wecom_state": "online",        // 必填，取值见下
  "queue_size": 0,                 // 可选，待发送条数
  "last_error": ""                 // 可选，最近一次错误（截断 200 字）
}
```

`wecom_state` 枚举：

| 值 | 含义 | 判定依据（agent 侧） |
|---|---|---|
| `online` | 正常，可收发 | 进程在 + 主窗口类名 `WeWorkWindow` |
| `login_required` | 掉线，需要扫码 | 主窗口类名 `WeChatLogin` |
| `not_running` | 进程没起 | 找不到 `WXWork.exe` |
| `hidden` | 进程在但窗口不可见 | 窗口 `IsWindowVisible=false` |
| `unknown` | 还没探测过 | 初始值 |

### 响应

```json
{ "ok": true, "server_time": "2026-11-04T12:00:00+08:00" }
```

### 副作用（必须实现）

1. `device.status = "online"`
2. `device.wecom_state = payload.wecom_state`
3. `device.last_heartbeat_at = now(UTC)`
4. `device.last_error = payload.last_error[:200]`

## 三、离线判定

新增 `backend/app/workers/device_watch.py`：

```python
OFFLINE_AFTER_SECONDS = 90

async def run_once(now: datetime | None = None) -> dict
async def run_forever(interval: float = 30.0) -> None
```

规则：

1. 查 `status = 'online'` 且 `last_heartbeat_at < now - 90s` 的设备
2. 逐条条件更新 `UPDATE devices SET status='offline' WHERE id=? AND status='online'`
3. rowcount==1 时用 `ws/hub.py` 的 `EVT_DEVICE_STATUS` 推一条事件：
   ```json
   {"type": "device.status", "device_code": "pc-office-01", "status": "offline",
    "wecom_state": "login_required", "last_heartbeat_at": "...", "reason": "心跳超时 90 秒"}
   ```
4. 返回 `{"checked": n, "marked": n}`
5. **不改 `wecom_state`**，只改 `status`（`wecom_state` 是设备自己报的，服务器不猜）

> 定时推送用 `from ..ws.hub import hub` + `await hub.publish("device:" + code, event)`；
> 若 `hub` 没有可用的事件发送函数，就调用现有的 `emit_*` 或直接 `publish`，不要自己造一套。

## 四、看板数据新增 `device` 与 `alerts`

`GET /api/v1/leads/board/data` 的返回**追加**两个键（原有 `counts/today/pending/followup` 不动）：

```json
{
  "device": {
    "device_code": "pc-office-01",
    "status": "offline",
    "wecom_state": "login_required",
    "last_heartbeat_at": "2026-11-04T19:20:00+08:00",
    "age_seconds": 720
  },
  "alerts": [
    {
      "level": "danger",
      "code": "agent_offline",
      "text": "采集端离线 12 分钟，期间消息收不到（企业微信已退出登录，需扫码）"
    }
  ]
}
```

规则：

- `device` 取第一条设备记录；没有设备时整个 `device` 为 `null`
- `age_seconds` = 现在 - `last_heartbeat_at`，无心跳时为 `null`
- `alerts` 生成条件：
  - `status != "online"` 或 `age_seconds > 90` → `agent_offline`（level=danger）
  - `wecom_state == "login_required"` → 文案附带「需扫码登录」
  - `wecom_state == "hidden"` → 文案附带「窗口被隐藏，可能已被风控」
  - 都在线则不返回 alert（空数组）

## 五、看板页面

1. **顶部红条**：`alerts` 非空时显示在页面最上方，红底白字，内容是 `alert.text`；空则隐藏
2. **每行增加「地点」按钮**：点一下把该行的地点文字变成 `<input>`，回车（或失焦）提交
   ```json
   POST /api/v1/leads/{conversation_id}/manual
   { "stage": "<当前 stage 不变>", "interview_place": "番禺厂门口" }
   ```
   提交后刷新数据
3. 今日约面行要显示地点（没有则显示「地点未定」）

## 六、约束

- 不改 `agent/wecom_io_core/`，不给 agent 增加任何键鼠动作

- 不引入新依赖
- 时区：库里 naive UTC，接口输出带 `+08:00`
- 中文注释
