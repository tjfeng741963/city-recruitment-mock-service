## 测试方法与边界

自行登录测试网页，创建专用验收岗位 ID 29 和隔离设备，未改变 `pc-win-01` 的岗位 25 绑定或业务配置。用浏览器修改文本、等待设置、连线目标和素材后保存。云 Windows 进程使用真实设备 HTTP 协议拉取这个专用岗位，真实下载素材并校验文件；只提取已安装运行器的流程选择与执行函数，发送层替换成顺序记录器，不载入企微键鼠模块，不发送客户消息。

因此本次证明网页保存、设备鉴权拉取、客户端缓存、节点路由和媒体预取可联通，不能作为企微最终送达验收。云 Windows 的远程桌面断开，旧客户端进程存在也不能当成发送就绪证据。

同步遵循：必须保存并启用流程，设备绑定该岗位；新会话使用客户端最新拉取版本；流程配置最多每分钟拉取一次；节点坐标只影响布局，发送顺序由 `entry_key` 和连线决定。把媒体放到一次执行最前面或等待闸门后而没有先成功文本验证目标时，节点执行器会暂停，不能据“配置同步了”推断“媒体一定已发送”。

## 验收中发现并修复

素材库 `GET /api/v1/media` 已经只返回启用素材，但响应省略 `status`。流程页面将缺少的 `status` 映射成空字符串，又要求必须为 `enabled`，导致用户添加图片/视频时下拉显示“无数据”。已提取素材规范化与过滤 helper：缺少状态视为接口返回的启用素材，显式 disabled/deleted 仍不可选，保留岗位与类型约束；增加回归测试，并用本地修复页面接真实测试服务器验证素材下拉与保存。
