## 三、架构现状

```
前端(38页) ──► Node :4222 (Fastify)          ──┐
                 配置 CRUD / 企微回调 / 自动回复   │
                                                ├─► PostgreSQL（city-recruitment-postgres）
               Python :8090 (FastAPI)          ──┘
                 知识库检索 / 回复生成 / 数字校验
```

- Node 调 Python：`POST http://city-recruitment-api:8090/api/v1/kb/answer`
- 认证：`X-Service-Token`。令牌由 **Python 启动时生成**写入共享卷
  `/run/kb/service-token`，Node 读同一个卷——**不需要手工填密钥**。
- Python 服务不对外暴露端口，只在 compose 网络内。

### 三层漏斗（已实现前两层）

1. **SQL 结构化筛选**：`tenant_id + city + status + 年龄区间`，岗位优先于话术
2. **全文匹配**：中文按**二元组**切词后 `LIKE`
3. 向量层：**实测不建**（top-3 召回 78% > 70% 阈值）

## 六、踩过的坑（都会再踩一遍，务必看）

### 数据库
- **SQLite 的 `BigInteger` 主键不自增**：要 `BigInteger().with_variant(Integer, "sqlite")`
- **`ALTER TABLE ADD COLUMN` 不能同时带 `REFERENCES` 和 `NOT NULL DEFAULT`**：
  报 "Cannot add a REFERENCES column with non-NULL default value"，线上因此宕机一次
- **`INSERT ... VALUES` 必须写列名**：加字段后静默错位，错误还会被上层 catch 吞掉

### 备份
- **`node:sqlite` 的 `backup()` 产出过 0 页空壳，`integrity_check` 仍返回 ok**。
  必须校验 `page_count` 和表数。现在用 `VACUUM INTO` + `scripts/backup-sqlite.mjs`

### 检索
- **中文整句当一个词 LIKE，召回率只有 36%**，必须按二元组切词
- **SQL 层不排序会按主键截断**，话术占满 limit，岗位一条都出不来

### 部署
- **API 容器 `read_only: true`**：`docker cp` 进不去，导入要用一次性 `docker run` 挂载
- **SSH 22 会被频繁探测封禁**（ping 通、4222 正常、22 超时）。一次连接做完所有事
- **改完必须提交再推**：这次两次"改了工作区没提交"，导致 CI 跑旧代码，
  排查时误以为是环境问题，实际是自己没提交
