### 唯一真缺口：省字段

```
cities 表            有 province（001_init.sql:9）
agent_conversations  无
candidate_events     无
```

录屏里「城市/区县」列显示的是 **`广东省广州市/白云区`**，说明省是拼接出来的。

**改法（推荐）**：新增迁移 `017_province.sql`

```sql
ALTER TABLE candidate_events ADD COLUMN province TEXT NOT NULL DEFAULT '';
ALTER TABLE agent_conversations ADD COLUMN province TEXT NOT NULL DEFAULT '';
```

写入链路：`flow_engine.py` 的 `PROFILE_KEYS` 增加 `province` → `profile_push.build_profile()` 带出 → `profile.routes.ts` 落库。

**替代方案（零迁移）**：前端按 `city` 反查 `cities.province`。缺点是多一次查询，城市不在表里就空白。

## 二、两条真实业务流程（录屏 + 逐字稿还原）

### 2.1 工厂账号（账号与工厂一一对应）

```
① 求职者加好友 → 自动通过
② 自动发送固定话术（薪资定位 + 逼单话术），不询问具体岗位
③ 知识库对答（工作时间、体检、住宿等）
④ 问「明天早上 9 点到 11 点能不能到」
⑤ 发面试地点定位
⑥ 要姓名 + 手机号
⑦ 改备注（网页侧可见）
⑧ 名单发内部邀约群
```

逐字稿 00:30 原话：

> 进来了之后通过嘛，自动通过了之后发这一个固定的话术，发完之后比如说员工的一些对答……

### 2.2 地铁账号（一个账号对应多个城市）

```
① 求职者加好友 → 自动通过
② 先问「投递的是哪个城市的简历」   ← 与工厂最大区别
③ 发该城市的：筛选 + 招聘信息 + 补充介绍 + 工作视频
④ 按红标/绿标复聊（例：体检报不报销）
⑤ 发对应城市面试地点定位 + 邀约
⑥ 要姓名 + 手机号 → 改备注 → 名单发群
```

逐字稿 09:23：

> 第一句肯定会先问他们投递的是哪一个城市的简历……因为地铁的话，我们的那些账号不可以保证说它一个账号对应的只有一个城市。

逐字稿 11:32：

> 地铁会比工厂的更加简单，就没有那么多地名，很固定，因为我们来去就只有这几个城市。

### 2.3 两者差异对照

| 维度 | 工厂 | 地铁 |
|---|---|---|
| 账号与工厂/城市关系 | 一一对应 | 一对多 |
| 入群后第一步 | 直接发固定话术 | 先问城市 |
| 内容量 | 岗位信息、工价 | 筛选 + 招聘信息 + 介绍 + 视频 |
| 复杂度 | 高（地名多） | 低（城市固定） |

## 三、内部邀约群格式

### 实际格式（录屏 02:10 实证）

```
深11/9 谢子鑫 18077352958
深11/9 陈牧 18185007410
深11/9 姚紫山 18489070561
万11/9 李煜升 15919022487
百11/9 贾雯红 19860013778
```

拆解：

```
[城市简写][月/日] [姓名] [手机号]
    深/万/百       11/9   谢子鑫  18077352958
```

- **城市简写**：深=深圳，万=万江（东莞），百=? —— 完整映射表需客户提供
- **日期**：面试日期，格式 `月/日`
- **姓名**：客户真名
- **手机号**：11 位

### 待客户确认

1. 城市简写的完整映射表
2. 日期取「面试日期」还是「发送当天」
3. 群是固定一个，还是按城市/招聘员分多个

## 四、MVP 范围（客户明确划定的）

逐字稿 02:27：

> 你先把这个名单可以自动去发群就可以了，这已经可以了

逐字稿 11:09：

> 现在先做最小 MVP 就不要做（视频）

逐字稿 11:21：

> 求职者给你发了这些什么名单之类的，OK 我们就自动去录名单，然后按照这个格式去发就行了

### MVP = 三件事

1. 聊天中收集：姓名、手机号、所在地（省市区）、面试时间、厂名
2. 落库成档案（OA 页面可见）
3. 按格式自动发到内部邀约群

### MVP 之外（后续）

| 项 | 原因 |
|---|---|
| 发送视频 | 客户明确说先不做；`send.py` 目前只发文本 |
| 发送图片/定位 | 同上，且需剪贴板贴图能力 |
| Boss 直聘平台内邀约 | 风控未验证 |
| 全自动（无人工介入） | 客户要求先半自动 |
