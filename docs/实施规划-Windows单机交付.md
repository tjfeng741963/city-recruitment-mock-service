# 实施规划：Windows 单机交付版

> 依据 2026-11-04 决策：用户端 = Windows 单机；服务器端通过 IP 管控；LLM Key 界面填写（DeepSeek）；服务器端不存知识库。
>
> 本文是**动手清单**，不是架构说明。架构见 `开发路线-双后端与知识库下沉.md`。

---

## 一、三条铁律

### 1. 企微链路冻结

`agent/wecom_io_core/` 与 `agent/compat.py` 的动作序列**一个字都不改**。

```
Ctrl+F → Ctrl+A → Ctrl+V(会话名) → Enter → 点输入框 → Ctrl+A → Delete
→ Ctrl+V(正文) → Ctrl+A/Ctrl+C 哨兵回读 → Enter
```

这条序列是上游逐条调过的（剪贴板占用、焦点丢失、窗口隐藏、首次按键被吞，四类问题各对应一处处理）。换任何"更简洁"的写法都会退回原状——本项目已经为此付出过两次代价（一次误判"键盘被过滤"，一次把抢前台改坏）。

**唯一允许的改动**：`autopilot.py` 里"回什么内容"的来源（固定文本 → 调本地知识库）。发送动作本身不碰。

### 2. 召回率暂不优化

SQLite 版只要**能检索、能返回合理结果**即可，不追求 78%。

- 不建向量层
- 不调分词语料
- 不重新标定 50 个问法的评测集

留一个 `kb_eval` 入口，等真实客户用起来、暴露出具体答非所问的 case 再针对性优化。

### 3. 客户端轻量

三个进程合计约 350MB 内存，客户 8G 机器无压力。但**安装包要小**：

- Python 用 embed 版，只装必要依赖（不装 pandas/onnx 这类）
- 图片素材（78 张 164MB）不进安装包，首次启动下载或按需加载

## 二、已验证的事实（省掉大量猜测）

| 结论 | 证据 |
|---|---|
| **知识库代码已支持 SQLite** | 136 个 `test_kb*` 测试在 `sqlite+aiosqlite` 下全部通过 |
| 模型层无 PG 特有类型 | `BigIntPK = BigInteger().with_variant(Integer, "sqlite")`，无 `JSONB`/`ARRAY` |
| 检索用 ORM 表达式 | `KbEntry.title.like(...)`，不是 `ilike`，无原生 SQL |
| Node 侧本来就是 SQLite | 交接文档的 `node:sqlite`、`VACUUM INTO`、`backup-sqlite.mjs` |

**结论：PostgreSQL → SQLite 不需要改代码，只改连接串。** 上一版规划的"2 周改造"作废。

## 三、阶段与顺序

### P0 · 知识库落地 SQLite（0.5 天）

| # | 动作 | 验收 |
|---|---|---|
| 0 | 生成并持久化 `install_id`（UUID，存 `data/instance.json`） | 重启后不变，服务器端将来据此关联 |
| 1 | `APP_DATABASE_URL` 切 `sqlite+aiosqlite:///./data/kb.sqlite` | 启动不报错，表自动建 |
| 2 | 导出 534 条为 `kb_seed.json` | 条目数一致，含图片引用 |
| 3 | 写 `kb_seed_import.py`：首次启动导入种子 | 导入后 `kb_eval` 能跑出结果 |
| 4 | 验证时区问题（`DateTime(timezone=True)` 在 SQLite 是 naive） | 巡检 `interview_at`/`valid_until` 比较不抛异常 |

第 4 项要重点看——`agent_ingest` 已经踩过 aware/naive 混比的坑，知识库的 `valid_until` 判断大概率会重演。

### P1 · Windows 打包（3~5 天）

| # | 动作 | 关键点 |
|---|---|---|
| 5 | `python-embed` + 依赖 | pywin32 的 `pywin32_system32/*.dll` 要跟 exe 同级 |
| 6 | Node 产物 + 前端静态 | `node.exe` + `dist/`，端口 4222 |
| 7 | `autopilot` 打 exe | PyInstaller，注意 `win32clipboard` 的隐式导入 |
| 8 | 启动器 `启动.bat` | 端口占用检测、三进程守护、日志写 `data/logs/` |
| 9 | 首次启动向导 | **安装 ID（自动生成 UUID）+ 模型 Key + 企微数据目录探测** |

**打包是最容易出问题的一步**，建议先做一个小实验：只打包 `python-embed + fastapi + pywin32`，跑通 `import win32clipboard` 和 `uvicorn` 启动，再往里加东西。

### P2 · 服务器端管控（3~5 天）

| # | 动作 | 说明 |
|---|---|---|
| 10 | 服务器最小服务：租户 + 授权 + heartbeat + 指令队列 | 新建目录，约 600 行 |
| 11 | 指令签名（服务器私钥签，用户端内置公钥验） | 防伪造 |
| 12 | 控制台：在线列表 + 远程改配置 + 重启 | 复用现有前端框架 |

**通道走反向轮询**（用户端每 30s 出站请求）。客户没有公网 IP，服务器连不进去是常态。

### P3 · 采集端整合（2 天）

| # | 动作 | 说明 |
|---|---|---|
| 13 | `autopilot` 与用户端对接 | `POST 127.0.0.1:8090/api/v1/agent/reply` → 拿回复文本 |
| 14 | 发送结果回传 | `POST .../agent/sent`，落库用于统计 |
| 15 | 启动器一并拉起 | 独立进程，崩了不影响 Web |

**保持独立进程**：它要抢前台、模拟键鼠，容易被杀软盯上；独立进程崩了单独重启即可。

### P4 · 交付与运维（3 天）

| # | 动作 |
|---|---|
| 16 | 自动升级（下载 → 校验 → 替换 → 失败回滚） |
| 17 | 日志打包上传（脱敏） |
| 18 | 备份（SQLite `VACUUM INTO`，参考 `backup-sqlite.mjs`） |
| 19 | 知识库导出（客户能带走自己的数据） |

## 四、明确不做

| 不做 | 原因 |
|---|---|
| **授权码 / License 校验** | 阶段一用一个 **install_id**（UUID）占位，等服务器端做好再来调 |
| 改 `wecom_io_core` 任何一行 | 铁律 1 |
| 改 `autopilot` 的发送动作序列 | 铁律 1 |
| 向量检索层 | 铁律 2 |
| RLS 多租户 | 单机版是单租户，表结构留着就行 |
| Linux / Docker 部署 | 客户环境是 Windows |
| 重写检索逻辑 | SQLite 已直接支持，没必要 |
| 图片传 COS | 本地存即可，不需要云存储 |

## 五、风险

| 风险 | 等级 | 应对 |
|---|---|---|
| PyInstaller 打包 pywin32 失败 | **高** | 先做最小验证；备选：不打 exe，直接带 python + 源码 |
| SQLite 时区导致日期比较异常 | 中 | P0-4 专测；统一 naive UTC（`agent_ingest` 已有先例） |
| 客户机器休眠/断电导致 autopilot 停摆 | 中 | 启动器加守护 + 开机自启；断电后消息漏掉需补发 |
| Windows 防火墙拦 4222/8090 | 中 | 启动器检测 + 引导用户放行 |
| 指令签名密钥泄露 | 低 | 每租户独立密钥，可远程吊销 |
| **ID 无授权保护，谁都能跑** | 低（当前阶段） | 只发给信任的客户；服务器端接入后改为 ID + 签名校验 |

## 六、执行顺序

```
P0（0.5天）→ 验证 SQLite 能跑知识库
   ↓
P1（3-5天）→ 打出能双击启动的包
   ↓
P3（2天）→ autopilot 接上本地知识库，端到端跑通
   ↓
P2（3-5天）→ 服务器管控（可与 P3 并行）
   ↓
P4（3天）→ 升级/备份/导出
```

**P0 和 P1 是硬前置**，P2 可以和 P3 并行。P3 完成才第一次有"客户能用的完整产品"。
