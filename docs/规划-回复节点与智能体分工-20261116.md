# 回复逻辑规划：节点剧本 + 智能体兜底

> 时间：2026-11-16
> 依据：客户 `01-聊天记录` 真实对话（63 张截图，逐段读取）+ `03-话术资料` 两份 docx + `02-岗位信息` 两份 xlsx
> 目的：把「客户发来一句话，系统回什么」这件事，从「模型自由发挥」改成 **RPA 式剧本**——每个节点回什么前端一清二楚，剧本覆盖不到的问题才交给智能体。
> 读者：前端（要照着建配置界面）、后端（要照着改 `flow_nodes`）、运营（要照着填话术）。

---

## 0. 一句话

**能预判的 11 个环节写死成节点，逐字可控；预判不了的答疑交给智能体，但只准「答事实」不准「改数字、改流程」。**

节点负责**推进**（把客户从"刚加好友"推到"到厂门口"），智能体负责**答疑**（"宿舍几人间""有空调吗""你是中介吗"）。

---

## 1. 先分析：现在的回复为什么不像真人

对照真实聊天记录，现在的实现有四个结构性差异，都不是"措辞不好"，而是**流程设计**的问题。

| # | 现状（代码里的样子） | 真实聊天记录里的样子 | 后果 |
|---|---|---|---|
| 1 | **一条消息 = 一条回复**，2～3 句短句 | 一个环节 = **4～6 条连发**：卡片 → 解读 → 视频 → 提问 | 客户感觉"这人在敷衍"，信息量不够，问一句答一句 |
| 2 | 首句**先问城市**（`STAGE_ASK_CITY`） | 设备绑的是**单个岗位**，首句直接发【用人要求】卡 | 多问一轮废话，客户直接流失 |
| 3 | **模型自由措辞**，只禁数字 | 话术是**逐字固定的**，连"👆""[玫瑰]"都不变 | 品牌口径丢失；模型会把"150/班"说成"150一天" |
| 4 | 阶段钳制 `_max_stage`：缺 city 就压回 ask_city | 客户问什么先答什么，**答完再抛下一个问题** | "你答了但还在问同一件事"（见 `回复逻辑全景.md` §4） |

**结论**：不是调 prompt 能解决的。要把"说什么"从模型手里拿走，变成**可配置的节点**。

**读出来的四条规律：**

1. **一句话 = 一个环节，一个环节 = 一组消息**。节点不是"一条消息"，是"按顺序发的一组消息（parts）"。
2. **每个节点都以一个问题结尾**（"看完回复我""看明白不""能否接受""有空过来吗""名字发我"）。这是推进的钩子，缺了客户就不动了。
3. **必须等回复才发下一段**。工厂话术 docx 里写得很明白：「先发12，回复了发3，回复了发45」——这就是 RPA 的**等待闸门**，不是定时连发。
4. **所有事实都从岗位表取**（地址、面试时间、携带资料、工价）。话术只负责"怎么说"，不负责"说多少"。

补充证据（另外两组）：
- 工厂线（`工厂-冉/华智普工.jpg`）：客户首条就是「普工」+「公司位置在哪 现在工价多少 宿舍分摊水电嘛 宿舍离上班地方远嘛」→ 回复是**一整条大卡**（工价/补贴/合同一致/福利/企业概况/食宿/招聘要求）+ 结尾「看下能否接受，明天下午12点-12点半方便到厂里面试吗？」+ 位置卡。工厂线**一条卡就是全部**，不需要拆。
- 条件不符的转厂（`工厂-冉/华智普工花臂纹身转松下.jpg`）：纹身挡不住 → 换厂，不是直接拒。这必须是一个**分支节点**，不能交给模型自由发挥。

## 3. 节点清单

### 3.1 三个通用约定（前端要按这个建模）

**① 一个节点 = 一串 parts，不是一个字符串。**

```jsonc
"parts": [
  { "text": "【用人要求】…", "media": [], "await": false },
  { "text": "✅这边看下用人要求是否符合条件，看完回复我，我发给你详细薪资待遇🌹🌹", "await": true }
]
```

- `await: true` = **发完这条停下，等客户回话才继续**。
- 一组 parts 内部按顺序发，条间隔 1.5～3 秒（模拟手打；太快会被企微风控，见 `AGENTS.md` 附一）。

**② 变量只从白名单取，不许手写数字。**

| 变量 | 来源 | 例 |
|---|---|---|
| `{{consultant}}` | 设备配置 | 宗锐 |
| `{{city}}` / `{{city_short}}` | 岗位表 | 佛山 / 佛 |
| `{{factory}}` `{{job_title}}` | 岗位表 | 佛山百花地铁安检 / 安检员 |
| `{{age_text}}` `{{height_text}}` | 岗位表 data_json | 18-30岁 / 女155 男165（可垫鞋垫） |
| `{{wage_intern}}` `{{wage_regular}}` | 岗位表 data_json | 110/班 / 150/班 |
| `{{shift_text}}` `{{rest_text}}` | 岗位表 data_json | 早7-15 中15-23 / 月休上3休1 |
| `{{interview_addr}}` `{{interview_time}}` `{{route_text}}` `{{bring_text}}` | 岗位表 | 百花广场22楼2220 / 上午11点或下午2点 / 广佛线祖庙站A出口 / 身份证原件+复印件2张 |
| `{{sign_no}}` | 人工填 | 0107 |

**这条是护栏**：保存节点时校验——正文里出现的「N元 / N岁 / N小时 / 点 / 楼」必须能对上岗位字段，对不上就不让保存。防的就是"运营手改成 160/班，模型和卡片两套口径"。

**③ 节点有类型，不只是"发话术"。**

| 类型 | 作用 | 前端表现 |
|---|---|---|
| `script` | 发一组话术，可能等待 | 默认 |
| `branch` | 只判断，不发消息，跳到子节点 | 无正文，只有条件 |
| `timer` | 定时触发（T+4h、前一天 21:00、当天 08:00） | 有"延迟"字段 |
| `handoff` | 转人工 / 转线索池 | 有"原因"字段 |

### 3.2 地铁线（vertical = `subway`）：11 个节点

设备绑的是「城市 + 面试点」，岗位固定，**不问城市**。只有一台设备挂多城时才插入 `ask_city`（保留现有节点，作为可选前置）。

| # | node_key | 触发 | 前端标题 | 等待 | 下一节点 |
|---|---|---|---|---|---|
| 1 | `greet` | 新好友首条入站 | 破冰 | — | `qualify` |
| 2 | `qualify` | 上一节点发完 | 用人要求（筛选） | ✅ | 客户回"符合/可以/有什么要求"→`wage_pitch`；回"超龄/有纹身"→`b_unsuitable` |
| 3 | `wage_pitch` | 筛选通过 | 上班时间 + 工资待遇 | —（同一组连发） | `work_show` |
| 4 | `work_show` | 报价发完 | 工作内容 + 视频 | ✅ | `invite` |
| 5 | `invite` | 视频发完 | 面试邀约 | ✅ | 答应→`addr_time`；问地址→`addr_time`；拒绝→`b_giveup` |
| 6 | `addr_time` | 客户答应/问地址 | 地址 + 时间二选一 | ✅ | 客户选时间→`collect` |
| 7 | `collect` | 时间有指向 | 收姓名 + 电话 | ✅ | 电话到手→再要名字；齐了→`notice` |
| 8 | `notice` | 姓名电话齐 | 面试通知卡 | — | `remind_night` |
| 9 | `remind_night` | 面试前一天 21:00 | 前一晚提醒 | — | `remind_morning` |
| 10 | `remind_morning` | 面试当天 08:30 | 当天早上提醒 | — | `remind_depart` |
| 11 | `remind_depart` | 面试前 30 分钟 | 出发提醒 | ✅ | 客户"到了"→`on_site` |
| 12 | `on_site` | 客户说到场 | 签到编号 | — | 结束（转 `interviewed`） |

> 说明：`addr_time` 和 `collect` 在真实对话里常常合并成一轮（"发我姓名电话"+"给你安排明天下午的可以吗"），但**状态必须分开**——地址发了不等于约上了，约上了不等于资料齐了。这是 `谈单状态机与面试记录设计.md` 里 `intent → booked` 的判定基础。

#### 节点正文（可直接抄，含来源）

**① `greet`**

```
您好，boss直聘{{consultant}}（{{city_short}}）
```

> 来源：`佛山百花-宗锐` 首条。Boss 直聘场外添加时可换「您好，{{factory}}直招，看下岗位要求哈」。**不发长开场白**，真实账号就是这么短。

**② `qualify`（核心节点，决定后面所有对话的质量）**

```
【用人要求】年龄{{age_min}}-{{age_max}}岁 女生净身高{{h_female}}cm或以上 男生净身高{{h_male}}cm或以上（可以垫鞋垫/穿增高）
{{color_text}}
{{minority_text}}
{{hukou_text}}
接受暑假工（不能随时到岗提前告知具体到岗日期）/ 短期至少做一个月 / 长期
如果不能随时到岗的，提前告知能到岗时间！
（年龄在35-45岁，请提前告知可以安排另外岗位）

✅这边看下用人要求是否符合条件，看完回复我，我发给你详细薪资待遇🌹🌹
```

> 原文（佛山）：`年龄18-30岁 女生净身高155cm或以上 男生净身高165cm或以上（可以垫鞋垫/穿增高）/ 无色弱色盲/案底/大面积伤疤/纹身（短袖能遮住）/明显染发 / 维吾尔族、回族、彝族、藏族名额已满`
> 原文（深圳）：`年龄18-35岁 女生身高152或以上 男生身高162或以上 / 身体健康 无纹身 明显染发 案底 色弱 大面积伤疤（纹身伤疤短袖能遮住即可）/ 维吾尔族、彝族、藏族、回族名额已满，深圳本地户口需提前告知`
> ⚠️ **每城口径不同，甚至同城不同线路也不同**（广州 xlsx：「广州本地户籍不招」；广东城际：「无户口限制」）。这一段必须整段来自岗位表，**禁止运营在节点里手打**，否则串城。

**③ `wage_pitch`（同组连发 3 条，不等回复）**

第 1 条：
```
【上班时间】
{{shift_text}}
{{rest_text}}，排班制 自由申请上单班/加班/休息，多劳多得 人性化管理

【工资待遇】
{{wage_text}}
实习期是{{probation}}，表现好可以申请提前转正的
```

第 2 条：
```
你看下这个工资架构能看明白不👆
入职即按正式工待遇上{{days_full}}天班工资能拿到{{income_full}}，剩下{{days_free}}天自由安排的 因为我们都是按班次计算的 多劳多得 可以一天只上一个班次，或者想多赚钱的话连上一个月班也可以 看你自己
```

第 3 条：
```
【内部晋升岗位】{{promotion_text}}（具有良好的沟通能力和服务意识），底薪不低于7-8k+
```

> 原文（佛山 150/班）：`实习期内上23天班左右工资能拿到5500+…转正23天班6500 剩下7天也是自由安排的，多上几天班 月综合7000+`
> 原文（深圳 150/班）：`入职即按正式工待遇上20天班工资能拿到6000，剩下10天自由安排的…7000-9000以上`
> 原文（南宁 110/班）：`实习期内上20天班工资能拿到3200…转正20天班4800…月综合6000以上`
> 这三个数（天数/保底/综合）是**联动的**，必须由 `{{wage_regular}}` 算出，不能让运营各填各的。

**④ `work_show`**

```
{{media:工作视频}}

地铁安检前台值班坐看电脑监控，新手都能快速上岗，全ai电脑识别不需要一直盯着屏幕，偶然轮岗起来巡查转转即可，纯酱油轻松岗位，不需要久站久坐的 都是人性化管理，岗位环境看下能否接受？
```

> 来源：`深圳-吴松平`。视频用的是 `05-视频/地铁工作视频（通用）/安检.mp4`。

**⑤ `invite`**

```
工作视频看下能否接受，没问题的话明天方便到总部面试面聊吗？
```

> 短、单一问题、带时间。**不要**在这里加"名额有限""今天最后一天"——真实账号不这么说，模型爱加。

**⑥ `addr_time`**

第 1 条：位置卡（微信原生位置消息，不是文字）
第 2 条：
```
总部这边只需要过来一次 后面工作安排的话是就近安排的 你看你明天 {{slot_a}} 或者 {{slot_b}} 有空过来面聊吗？
```

> 来源：`佛山百花-宗锐` 原文「总部这边只需要过来一次 后面工作安排的话就是就近安排的 你看你明天 11 点或者下午两点有空过来面聊吗？」；`深圳-吴松平` 的变体是「面试好分岗分线路分发制服，后面你上班以及未来的考勤都在你就近的站点，我们的总基地你只需要过来一次即可」（这句话在话术 docx 里标为"外宿人员嫌弃面试地址远"的应对）。

**⑦ `collect`（分两句问，别一次问两个）**

```
那麻烦你这边把姓名还有电话号码发我一下 我这边给你备注 然后安排面试

给你安排{{chosen_slot}}的可以吗？
```

> 来源：真实对话就是先发第一句，客户给了电话才补"名字也发我一下哈"，然后确认时间。
> **注**：现有 `SYSTEM_PROMPT` 要求"一次问姓名+手机号"，与真实做法相反。真实账号是**先电话后名字**，两轮。改配置时以真实为准。

**⑧ `notice`（字段全部来自岗位表）**

```
按照指引图按电梯上来{{floor}}，进来公司签到{{sign_no}}，坐着等待面试即可

【{{city}}🗺面试通知】
面试时间：{{interview_time}}
面试地址：{{interview_addr}}
{{route_text}}
找不到路联系我

面试请携带：{{bring_text}}
```

> 原文（佛山）：`面试时间：周一至周六 上午11点或者下午2点 准时到 / 面试地址：乘坐广佛线 祖庙站A出口，出来步行导航"百花广场写字楼"，按电梯上来22楼2220，找不到路联系我 / 面试请携带：身份证原件+复印件2张（有就带）`
> ⚠️ **队长电话不在这一步发**。岗位表 xlsx 的列头就写着「联系人（人员到场之前不发送此信息，而且队长电话有可能会有变更）」——这是客户明确的业务规则，必须做成节点级开关 `send_contact: false`。

**⑨⑩⑪ 三个定时提醒**

```

晚上好🌙今天早点休息哈，调好闹钟明天准时过来面试，在公司等你哈，不懂路的话滴滴我🤝

```

**⑫ `on_site`（半自动：签到号人工填）**

```
签到编号：{{sign_no}}
签好到等一会还没到的人哈
```

> 来源：`佛山百花-宗锐`。签到号是**当天现场排的**，系统给不了，所以这一步必须有"人工填号"入口，前端要留输入框 + 一键发送。

### 3.3 工厂线（vertical = `factory`）：7 个节点

工厂线的结构比地铁简单：**一条大卡就把所有事说完**，然后直接邀约。

| # | node_key | 触发 | 等待 | 下一节点 |
|---|---|---|---|---|
| 1 | `greet` | 新好友 / 客户问"普工""有什么工作" | — | `job_card` |
| 2 | `job_card` | 破冰后 | —（卡尾自带邀约问句） | `pick` |
| 3 | `pick` | 客户问"做什么的/累不累" | ✅ | `addr` |
| 4 | `addr` | 客户问地址 / 表达可以去 | ✅ | `collect` |
| 5 | `collect` | 时间有指向 | ✅ | `notice` |
| 6 | `notice` | 姓名电话齐 | — | `prep` |
| 7 | `prep` | 客户确认到岗日 | ✅ | 结束 |

**② `job_card` 正文结构（一条 message，五段）**

```
🎉🎉纯{{wage_total}}元+包吃包住+周结1000元

【{{job_title}}薪资】💰{{wage_base}}元/小时，{{shift_subsidy}}
‼️签合同一致纯工价，无套路，包吃3餐包住‼️
💫{{welfare_text}}，综合薪资{{income_range}}/月，每月{{payday}}号固定打卡发

💰日薪政策：打卡满七天后，每周可借支500-1000元

【企业概况】{{company_text}}
【食宿情况】{{dorm_text}}
【招聘要求】{{require_text}}

💗当天可安排住宿也可外宿 自由选择，上面薪资时间公司位置看下能否接受，{{interview_slot}}方便到厂里面试吗？
```

> 来源：`工厂-冉/华智普工.jpg`（华智，25→26 元/h）、`03-话术资料/工厂话术.docx`（万宝 22→24 元/h + 开年红包；广汽荻原 24/25/26 递进 + 夜班补贴）。
> 注意：工厂的**工价是分段递进的**（第一个月 24、第二个月 25、第三个月 26），所以 `wage_text` 不能是一个数，得是"分段表"。前端要支持多行。

**⑦ `prep`（面试注意事项，按真实节奏分批发）**

docx 里的原话是：**「先发12，回复了发3，回复了发45」**——这就是把 5 条注意事项拆成 3 个 parts 的 `await` 闸门：

| 序号 | 内容 | 发送时机 |
|---|---|---|
| 1+2 | 面试只考察面试态度；面试会问能否接受两班倒/站班/长期做，**都要回答"能接受 没问题"** | 立即 |
| 3 | 白班夜班有什么要求吗，今天长白班名额只有5个，我这边可以登记 | 客户回复后 |
| 4+5 | 拿到工牌饭卡拍照给我；现场有领导在，问啥都说可以接受，表现积极 | 客户回复后 |

⚠️ 这一段里有一句「**也不要给其他员工说自己长白班，因为名额不够的**」——属于业务灰话术，节点里**保留原文**，但它也说明了为什么这段不能交给模型：模型会自己加解释、加承诺。

### 3.4 分支节点：异议处理（8 类，地铁线为主）

这些是"客户说了某句话 → 走某个固定回复 → 回到主线"。**必须是节点，不能是智能体**——因为它们是"销售话术"，有固定套路，模型自由发挥只会绕圈。

| key | 命中词（示例） | 回复来源 | 回主线到 |
|---|---|---|---|
| `b_wage_low` | 太少, 太低, 才150, 不划算, 能不能加 | 话术 docx「工资待遇不清晰/嫌低」整段（含 350/天、高峰补贴 30-43.7/次、1-2月转正、队长 7k+） | `invite` |
| `b_shift_long` | 太长, 站不住, 12小时, 连班, 累不累 | 话术 docx「连班时间长」整段（实际在岗 5-6h、半小时轮岗、试用期 4500-5500、转正 6500） | `invite` |
| `b_far` | 太远, 地址远, 不去那么远, 有没有近的 | 话术 docx「外宿人员嫌弃面试地址远」（面试只来一次、后面就近分线路） | `addr_time` |
| `b_social` | 社保, 五险一金, 有没有社保 | 话术 docx「社保/五险一金」（转正后缴、全国联网不断缴） | `invite` |
| `b_welfare` | 有什么福利, 包吃吗, 宿舍几人间 | 话术 docx「福利」6 条 | `invite` |
| `b_base_pay` | 保底多少, 底薪多少 | 话术 docx「一定要问清楚保底薪资」（实习 3600+奖金 / 转正 4800+3倍+社保） | `invite` |
| `b_hesitate` | 考虑一下, 再看看, 我和家里商量 | 话术 docx「考虑/犹豫/聊得差不多推进话术」（普通岗位冬暖夏凉、名额有限、基地直招不收费、明天能到吗） | `addr_time` |
| `b_unsuitable` | 超龄, 纹身, 案底, 色弱, 身高不够 | 先判有没有替代岗位（同城其他厂/岗位），**有就转厂**（如"华智花臂纹身转松下"），没有就 `b_giveup` | `job_card`（换岗位）或结束 |
| `b_unreal` | 骗子, 是不是中介, 真的假的, 收费吗 | 工厂 docx「质疑工价地址不真实」（企查查可查、合同一致、到厂门口联系我）；地铁 docx「安检基地直招，不收取任何一分钱」 | 回原节点 |
| `b_giveup` | 不去了, 算了, 不合适, 不要了 | 一句客气话，`gave_up`，**不再邀约**（现有 `_max_stage` 已支持） | 结束 |

**优先级必须写死**：`b_giveup` > `b_unsuitable` > 其他异议 > 主线推进。真实踩过的坑：客户说"太远了不去了"，系统判成"问地址"继续发邀约。

## 4. 智能体接管范围

### 4.1 什么交给智能体（三条，不多不少）

| 场景 | 例 | 为什么必须模型 |
|---|---|---|
| **岗位事实答疑** | "宿舍几人间""有空调吗""要不要体检""工资几号发""能带孩子吗" | 问题无限多，答案在知识库里，节点穷举不完 |
| **个性化异议** | "我 52 了还能去吗""我手臂有纹身遮不住" | 要结合年龄/岗位条件做判断，话术是模板但结论要算 |
| **闲聊与情绪** | "你是机器人吗""太远了不想去""谢谢" | 需要共情，固定话术会很生硬 |

### 4.2 智能体绝对不能做的（红线，写进 `SYSTEM_PROMPT`）

| # | 红线 | 现状有没有 | 说明 |
|---|---|---|---|
| 1 | **不改任何数字**：工价、年龄、身高、补贴、保底、班次时间 | ✅ 已有（`SYSTEM_PROMPT` 硬性规则） | 数字只能来自节点/岗位表 |
| 2 | **不改流程节点**：不许自己"约好了"、不许跳步 | ✅ 已有（`_max_stage`） | 保持 |
| 3 | **不提前发联系人电话** | ❌ 缺 | 岗位表明确写「人员到场之前不发送」 |
| 4 | **不承诺节点外的东西**：报销路费、包体检、保留名额、安排夫妻房 | ❌ 缺 | 模型最爱编"我帮你留着名额" |
| 5 | **不冒充真人**：被问身份要说"我是{{factory}}的招聘助理，人工在后台" | ⚠️ 部分 | 现有 prompt 只说"叫陈姐"，反而更像冒充 |
| 6 | **不覆盖节点话术**：节点已发的内容不重复、不改写 | ❌ 缺 | 现在模型会把已发的工资再答一遍，口径还不一样 |

### 4.3 交接语义（前端要展示，后端要记录）

```
节点执行中，客户发了「插问」
   ↓
智能体答（只有 1 轮，不推进 stage）
   ↓
回到节点，继续原来的 await
```

- **插问不打断剧本**：客户问"宿舍几人间"，答完仍然等他对"能否接受岗位"的回答，不重发节点。
- **插问答不上就转人工**：知识库没命中 + 涉及钱/承诺 → `handoff`，前端标黄"待人工"。
- **客户明确要人工**（"叫你们负责人""我要投诉"）→ 立即 `handoff`，节点暂停。

## 5. 与现有代码的差距（后端照着改）

现有 `flow_nodes` / `flow_edges` 只是把老的 5 个 stage 换了个名字（`034_flow_nodes.sql` 里 10 条默认节点，body 全空），**还不支持本文的剧本**。缺的字段：

| # | 表 | 加什么 | 为什么 |
|---|---|---|---|
| 1 | `flow_nodes` | `parts_json`（数组：text + media + await + delay_ms） | 现在只有一个 `body` 字符串，装不下"卡片+解读+视频+提问" |
| 2 | `flow_nodes` | `node_type`（script / branch / timer / handoff） | 现在全是话术节点，没法表达定时和判断 |
| 3 | `flow_nodes` | `timer_json`（`T+4h` / `21:00` / `-30m`） | 三个提醒节点需要 |
| 4 | `flow_nodes` | `send_contact`（bool） | 队长电话默认不发 |
| 5 | `flow_nodes` | `fallback_node`（转智能体 / 转下一节点 / 转人工） | 现在没配 body 就整段回退到老逻辑，粒度太粗 |
| 6 | `flow_edges` | `condition_type` 增加 `intent`（真语义，不再按 keyword） | 现在 `intent` 就是 `keyword`（`flow_graph.py:39`），"可以接受"和"可以考虑"会误判 |
| 7 | 新表 `flow_timers` | `session_key, node_key, fire_at, status` | 现在**完全没有定时器**（`岗位话术配置说明.md` §五已承认） |
| 8 | `flow_events` | `node_key`、`await_since` | 要知道"卡在哪个节点多久了"，才能做跟进和看板 |
| 9 | 渲染器 | `render_parts(node, job, device)` | 现在 `render_script` 只做占位符替换，不校验数字 |

**优先级**：1/2/4/9 是 P0（不做就发不出真实节奏）；3/7 是 P1（不做只是没有提醒，不影响主线）；6 是 P1（不做会误判拒绝）。

## 6. 前端要做到什么（这是本文的重点）

前端的目标不是"能编辑"，是**"运营看一眼就知道客户会收到什么"**。

### 6.1 节点列表页（按板块分 tab：地铁 / 工厂）

每行显示：

| 列 | 内容 |
|---|---|
| 序号 | 拖拽排序（等于执行顺序） |
| 节点名 | 「② 用人要求（筛选）」——**用业务语言，不用 node_key** |
| 类型 | 话术 / 判断 / 定时 / 转人工（带颜色徽标） |
| 首句预览 | 正文前 20 字，灰字 |
| 条数 | 3 条 · 1 条需等待 |
| 媒体 | 🎬1 🖼2（hover 显示文件名） |
| 状态 | 启用 / 停用 / **未配（红）** |
| 命中次数（近 7 天） | 让他知道这个节点在不在跑 |

顶部要有一个 **「流程预览」按钮**：把整条链按顺序列出来，每条消息一个气泡，跟微信一样。**这是运营验收的唯一手段**，比任何字段都重要。

### 6.2 节点编辑抽屉（字段清单）

```
基本信息
├─ 节点名（运营看的）
├─ node_key（自动生成，只读，高级模式可改）
├─ 类型：话术 / 判断 / 定时 / 转人工
└─ 状态：启用 / 停用

话术（类型=话术时）
├─ 消息 1  [文本域]  [插入变量▾]  [上传/选媒体]  [☑ 发完等客户回复]
├─ 消息 2  …
└─ [+ 添加一条消息]        ← 关键：支持多条，每条独立 await

下一步（类型=话术时）
├─ 默认下一节点 [下拉]
└─ 条件分支 [+ 添加]：关键词 / 正则 / 槽位已收 / 意图 → 目标节点
      （拖拽调优先级，拒绝类自动置顶）

定时（类型=定时时）
├─ 相对当前节点：+4 小时 / +1 天
└─ 绝对时间：21:00 / 08:30 / 面试前 30 分钟
   夜间静默：21:00-09:00 不主动发 [默认开]

兜底
├─ 客户不回复：[等多久] → [发什么 / 转跟进 / 转人工]
└─ 配错时：[跳过本节点 / 转智能体]
```

### 6.3 三条保存前校验（必须有，否则一定出事）

1. **数字校验**：正文里的 `\d+元|\d+岁|\d+小时|\d+楼|\d+点` 必须命中岗位字段或本节点变量白名单，否则报错「第 2 条消息里的『160/班』不在 {{wage_regular}} 里」。
2. **必填钩子**：类型=话术且 `await=true` 的最后一条，必须以问号或"回复我/发我/看下"结尾。**没有提问的节点等于流程断头**。
3. **媒体存在性**：`{{media:xxx}}` 必须在媒体库里，且 sha256 能对上（现在是发送时才校验，那时已经晚了）。

### 6.4 一条必须做的视图：「这个岗位，客户会收到什么」

选一个岗位 + 一个板块 → 把 12 个节点用真实数据渲染出来，一条一条气泡排开，可导出成 txt 给运营核对。

**为什么**：地铁 5 个城市 × 每个 3-5 个面试点，话术是同一套但数字全不一样。运营没有这个视图，只能靠"配完上线看效果"，出了错是客户先发现。

## 8. 落地顺序

| 阶段 | 做什么 | 验收 |
|---|---|---|
| **P0（2 天）** | `parts_json` + 前端多条消息编辑 + 渲染器 + 数字校验；把地铁 12 个节点按本文正文录进去（佛山一套） | 选佛山岗位 → 预览 → 打出来的字和 `佛山百花-宗锐` 截图**逐字一致**（除了姓名电话） |
| **P1（1 天）** | `await` 闸门真实生效：发完停下，等客户回话才发下一段 | 客户不回，第 2 条不发；客户回"可以"，才发 `wage_pitch` |
| **P2（2 天）** | 分支节点 8 个 + `intent` 边（拒绝优先） | 说"太远了不去了"→ 走 `b_giveup`，不再发邀约 |
| **P3（1 天）** | 定时器：T+4h 跟进 / 前一天 21:00 / 当天 08:30 / 出发前 30m | 约了明天下午两点 → 21:00 收到提醒，08:30 收到提醒 |
| **P4（2 天）** | 工厂线 7 个节点 + 分段工价表 + 面试注意事项三批发 | 客户问"普工" → 收到大卡 → 位置卡 → 注意事项按 12/3/45 三批 |
| **P5** | 智能体红线 6 条写进 prompt + 插问不打断剧本 | 客户插问"宿舍几人间" → 答完仍在等"能否接受" |

**每个阶段结束都要跑一次「真实问题回归」**：用 `测试对话历史.md` 里的客户原话，加上本文截图里的 20 句典型提问，逐句过一遍，错的挑出来。

## 9. 风险与未决

| # | 风险 / 未决 | 处理 |
|---|---|---|
| 1 | **工价口径冲突**：岗位表是"合同价 vs 小时价"两套（万宝 xlsx 21-25 元/h，话术 docx 写 22→24 元/h + 6xxx 月薪） | 上线前必须让客户确认以哪套为准，否则节点和卡片的数字会打架 |
| 2 | **民族/户籍条款**是硬拒绝条件，写错等于歧视投诉 | 整段来自岗位表，节点里禁止手改；广州"本地户籍不招"这种，保留原文但加审核标记 |
| 3 | `b_giveup` 误判（"太远了"可能是问路，不是拒绝） | 意图边必须两条都配：`b_giveup` 优先但要求同时有否定词（"不去了/算了/不面了"），单独的"太远"走 `b_far` |
| 4 | 定时提醒撞夜间（21:00-09:00 不发） | 全局静默窗，冲突时顺延到 09:05 |
| 5 | 微信个人号发长卡容易被折叠/风控 | 条间隔 1.5-3 秒；单节点最多 6 条；超过拆成两个节点 |
| 6 | 5 个城市 × N 个面试点 = 配置炸弹 | 节点话术只写"结构"，数字全部走变量；按城市复制一份模板，只改岗位数据不改正文 |
| 7 | 签到号、队长电话是人工字段 | 前端留"待填"状态，不填就跳过该行，不发空 `{{sign_no}}` |
