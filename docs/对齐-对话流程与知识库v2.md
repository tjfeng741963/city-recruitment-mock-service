# 对齐：对话流程 v2 与知识库占位（2026-11-10）

> 中控对齐文档。**前端 agent 只改 `frontend/`，后端 agent 只改 `src/` + `backend/`。**
> 依据：2026-11-08 会议逐字稿 + 陈文龙 11-10 口述流程。

## 一、对话流程 v2（地铁账号；工厂账号后续复用）

```
① 加好友 → 问「你投递的是哪个城市」
② 说了城市 → 发该城市的工作信息（多段、可分批）
      段 1 文本：厂名 / 工价 / 班次 / 年龄 / 吃住
      段 2 文本：面试地点 + 时间窗口
      段 3.. 图片 / 视频  ← 本期占位，不真发（列表见 §四）
③ 问「这两天能不能过来面试」
④ 接受 → 问姓名 + 手机号（一次要两个字段）
⑤ 落档案（后端推 4222，OA 页可见）
⑥ 收尾：「期待你来面试，到了联系我」
⑦ 之后客户零散提问（工厂情况 / 面试地点 / 体检）→ 走知识库；未命中则占位兜底 + 记 unknown_questions
```

状态机（`backend/app/services/flow_llm.py`）：

| stage | 进入条件 | 退出条件 |
|---|---|---|
| `ask_city` | 会话开始 | 拿到 city |
| `send_info` | 有 city | 已发完工作信息（一个 turn 内可发多段） |
| `ask_interview` | 信息已发 | 客户表态（来 / 不来 / 问细节） |
| `collect` | 客户答应来 | 拿到 name + phone |
| `done` | 档案完整 | 不再主动发问 |
| `kb` | 任意阶段的插问 | 命中知识库 |

- 面试时间默认 **次日 09:00-11:00**（常量 `INTERVIEW_WINDOW`，工厂账号可改成别的窗口）
- 客户明确说别的时间 → 以客户为准，但仍写 `interview_date` + `interview_time`
- 拒绝面试 → `stage='done'`，`recruit_status='disqualified'`，不再追问

## 二、多段发送（本期只做文本分批发）

客户端一次只能发一条消息，所以 8090 返回 `parts: string[]`：

```json
{
  "reply": "段1\n段2",            // 兼容老客户端：拼成一段
  "parts": ["段1", "段2"],        // 新客户端按顺序逐条发
  "attachments": []               // 本期恒为空，占位
}
```

客户端按 `parts` 顺序逐条 `send`，条间 sleep 1.5-2s（防折叠/限流）。

## 三、档案字段（在 11-08 契约上新增 province）

```
name / phone / province / city / district / factory_name
interview_date(YYYY-MM-DD) / interview_time(HH:MM 或 09:00-11:00)
stage / notes / job_title
```

- `province` 走 017 迁移：`agent_conversations` + `candidate_events` 各加一列
- 省市区由模型抽，`province` 允许空（只说了"广州"就没有省）
- 前端列显示规则：`province + city + "/" + district`，缺省时优雅降级

## 四、图片 / 视频（本期不做，先记）

## 五、知识库（本期做占位，不做真实内容）

```
命中：kb_entry(kind='script') 按标题/关键词匹配 → 返回话术
未命中：返回一句兜底（"这个我确认下，稍后回你"），并写一条 unknown_questions
```

- `unknown_questions` 当前**后端不存在**（前端知识库页会调 `/api/v1/unknown-questions`，现在 404）
- 本期要求：Node 侧补这个接口（列表 + 标记已处理），数据从 `unknown_questions` 表来
- 知识库**内容**（每个节点 3-5 条话术）不在本期范围，等客户给聊天记录

## 七、验收口径（双方对齐）

1. 后端：`POST /api/v1/flow/answer` 返回 `parts`（≥2 段）、`stage` 走完 5 步、档案含 province
2. 后端：`GET /api/v1/unknown-questions` 不再 404
3. 前端：候选人员页能显示 `广东省/广州市/白云区`，缺省不报错
4. 前端：`npm run build` 通过，无 TS 错误
5. 联调：一条真实对话走完 → `/candidates` 出现该客户，字段齐全
