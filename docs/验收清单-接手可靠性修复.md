# 接手可靠性修复验收清单

更新日期：2026-11-07。适用：草稿 PR #5。W01–W05、W08、W10 已取得对应实机证据，其中 W03/W05 对端均确认仅收到一条；W04/W05 在两次发送前失败后，经用户另行授权、收起侧栏后完成。W06/W07/W09 的自动化证据和真实场景缺口分列如下，不能将替身发送等同于真实企微送达。

## 环境准备

1. 使用独立 Windows 测试账号、企微账号及专用测试联系人。停止其他 agent，只运行一份本分支。`--target` 仅限制自动回复采集/处理，不限制桥接人工指令；因此整个测试账号必须隔离。
2. 使用测试服务端和测试数据库，不复用生产 `.env` 或 `config.json`。先部署 Node 服务端并执行已有迁移（含 015），再更新 agent。确认 Node 桥接与 Python 主上报分别连接到了预期实例。
3. 停止 agent 后备份该测试实例的 `agent/reply_log.db` 和 `agent/.report_state.json`。重启恢复测试必须保留这两份状态，不能删除记录来触发重发。
4. 在测试配置中填写 `server`、`device_token`、`device_code`、`bridge_server`、`bridge_token` 和 `brain`。Node 桥接 token 与 Python 设备 token 不是同一个凭据。Node 测试设备设置 `observe_only: true`，避免 Node 自动回复与本地知识库同时生成回复；该设置不禁止人工指令或本地自动回复。
5. 首先设 `dry_run: true`，从 `agent/` 运行下列命令。dry-run 仍可登记记录和发送心跳/观察上报，但不发送聊天消息、不领取人工指令，也不补传执行回执。

文档目录已重定向时，在 config.json 设置 data_dir 为当前测试账号的 Data 目录绝对路径，或用 --data-dir 覆盖。显式目录须存在且包含 message.db/session.db；无效时退出码 2，不回退到其他账号。空值仍使用核心默认发现。维护入口 --list/--retry-held/--flush-receipts 不要求数据目录在线，也不创建 Store。

```powershell
python autopilot.py --list
python autopilot.py --once --dry --target "专用测试联系人"
```

## 自动化验证

从仓库根目录运行，与 CI 一致：

```powershell
npm ci
npx tsc --noEmit
npx vitest run --testTimeout=20000
python -m pytest backend/tests/ -q
```

重点测试文件：`tests/bridge-recovery.test.ts`、`tests/bridge-outbound.test.ts`、`tests/manual-send.test.ts`、`tests/agent-stream.test.ts`、`backend/tests/test_agent_recovery_http.py`、`backend/tests/test_manual_readback.py`、`backend/tests/test_manual_receipt_journal.py`、`backend/tests/test_bridge_inbound_report.py` 和 `backend/tests/test_autopilot_brain_failure.py`。

这些测试以临时/内存数据库和受控 HTTP 验证状态及重试，不向真实企微发送。新增跨进程验收实际启动本机 Node 服务、故障代理和独立 agent 恢复进程，发送函数为替身：回执到达前返回 503，或服务端接收回执后丢弃 HTTP 响应，均须先落盘、恢复后只补传回执，最终只有一个 sent 气泡。另验证 held 经真实进程重启仍不执行，`--retry-held` 仅重新入队并退出，不初始化桌面 Store。

W06 的故障只能在测试代理/夹具中注入，不调整发送时序、核心模块或额外键鼠事件。无法可靠产生故障时标记“未执行”，保留自动化结果，不能据此填写通过。

W03 使用隔离服务的真实人工发送 HTTP API 触发，并非人工点击浏览器按钮；状态和气泡以网页同一消息 API 核对，未独立验收登录后的浏览器操作。第一次无标记落库，第二次出现一个新自发标记；首次失败的根因未完全确定，成功也不能证明后台焦点或无人值守发送可靠。正常使用仍需完成直接启动、目录配置和焦点稳定性验收。

恢复回执可在停止常驻 agent 后执行 `python autopilot.py --flush-receipts`。该命令不创建企微 Store、不做输入，仅对当前桥接目标发 HTTP；`dry_run: true` 会跳过。退出码 0 为当前目标无 pending/rejected，1 为仍有待处理，2 为配置缺失。使用 `--list` 核对执行记录；rejected 或 unknown 必须人工检查，不能用删除数据库的方式重发。

新人工执行必须在目标会话中观察到唯一的新自发消息 ID，才回执 succeeded 和真实 `contact_id:message_id`；核心回读未返回会话 ID 时也适用。无新增 ID、快照不可读、多条新增同文或核心明确返回其他会话，均回执 unknown，不生成新的 `keyboard-<command>` 成功标识。历史已落盘的 keyboard 回执仍原样补传。unknown 需人工核对实际落点，不能直接重发或宣布去重验收通过。图片、语音和附件、修复前已经越过游标的历史消息均不在本批范围。

## 验收记录与发布

每项记录提交号、操作时间、脱敏日志、网页/测试联系人截图及结果，不收集 token、密码、租约内容或真实客户信息。unknown 不等于未发送，遇到 unknown 先人工核实实际落点。

本轮未合并 main、未部署生产、未执行生产凭据轮换；截至 11-07，真实企微共执行用户分别授权的五次单条尝试：W03 首次失败、W03 重试成功、W04 前两次发送前失败、侧栏收起后成功，没有启动历史自动回复队列。各次执行记录保留在独立验收目录，不接入常驻 agent；临时服务已停止。手动关闭侧栏后的单次成功不能证明侧栏是唯一根因或无人值守发送可靠。实机启动适配器明确传入重定向文档目录，并精确过滤测试联系人；正式运行仍需处理本机目录与采集范围配置，不能将适配器验证当作裸命令启动通过。后续实际发送仍需确认联系人、正文和次数。完成 PR 审查、其余实机验收、部署实例与备份核对后再安排发布；推送/合并 main 会触发生产部署。服务端回滚可保留新增表，但 agent 回滚前必须保留本地状态并核对所有待处理回执。

后续经用户确认，入口已支持 data_dir/--data-dir。真实 main() 通过配置传入冻结 Store，单次、35 秒轮询、保留游标重启通过，无输入/claim/发送；目录注入适配器已移除，验收仍保留联系人范围过滤。该结果补齐本机目录配置，正式采集范围和无过滤整账号启动仍待验收。

W09 后续增加了第六次单条尝试，原发送函数/内部尝试各 1 次且对端只收到一条；首次五次尝试的记录仍保留。回执恢复后摘要检查失败，未执行后续出站观察补传。现有执行记录为 succeeded/acked，待传观察仍持久化，目录保持停止。不能通过重新发送相同标记修复摘要。服务端新修复保留无观察时的既有排队时间，由后到观察校正真实时间；本地 Node 269 项及隔离 HTTP 八场景通过，实机原失败与修复后自动化结果分别记录。
