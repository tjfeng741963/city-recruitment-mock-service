# 接手可靠性修复验收清单

日期：2026-11-06。适用：草稿 PR #5。本文列出自动化验证范围和独立 Windows 测试账号上的人工验收步骤；人工项目前均为未执行。

## 环境准备

1. 使用独立 Windows 测试账号、企微账号及专用测试联系人。停止其他 agent，只运行一份本分支。`--target` 仅限制自动回复采集/处理，不限制桥接人工指令；因此整个测试账号必须隔离。
2. 使用测试服务端和测试数据库，不复用生产 `.env` 或 `config.json`。先部署 Node 服务端并执行已有迁移（含 015），再更新 agent。确认 Node 桥接与 Python 主上报分别连接到了预期实例。
3. 停止 agent 后备份该测试实例的 `agent/reply_log.db` 和 `agent/.report_state.json`。重启恢复测试必须保留这两份状态，不能删除记录来触发重发。
4. 在测试配置中填写 `server`、`device_token`、`device_code`、`bridge_server`、`bridge_token` 和 `brain`。Node 桥接 token 与 Python 设备 token 不是同一个凭据。Node 测试设备设置 `observe_only: true`，避免 Node 自动回复与本地知识库同时生成回复；该设置不禁止人工指令或本地自动回复。
5. 首先设 `dry_run: true`，从 `agent/` 运行下列命令。dry-run 仍可登记记录和发送心跳/观察上报，但不发送聊天消息、不领取人工指令，也不补传执行回执。

```powershell
python autopilot.py --list
python autopilot.py --once --dry --target "专用测试联系人"
```

## 自动化验证

从仓库根目录运行，与 CI 一致：

```powershell
npm ci
npx tsc --noEmit
npx vitest run --testTimeout=20000
python -m pytest backend/tests/ -q
```

重点测试文件：`tests/bridge-recovery.test.ts`、`tests/bridge-outbound.test.ts`、`tests/manual-send.test.ts`、`tests/agent-stream.test.ts`、`backend/tests/test_manual_receipt_journal.py`、`backend/tests/test_bridge_inbound_report.py` 和 `backend/tests/test_autopilot_brain_failure.py`。

这些测试以临时/内存数据库和受控 HTTP 模拟验证状态及重试，不向真实企微发送，也不验证真实键鼠、窗口焦点或企微数据库解密。

## Windows 人工验收

仅在上述隔离环境中切换 `dry_run: false`，每项单独运行并记录证据；不并行操作企微窗口。先检查 `--list` 确认没有无关 pending/failed 积压。

| 编号 | 操作 | 通过条件 | 当前结果 |
|---|---|---|---|
| W01 | 保持 dry-run，从测试联系人发送唯一标记文本 | 主上报与 Node 会话各显示一条；重复轮询不重复入库，agent 不发送 | 未执行 |
| W02 | 在企微里人工输入并发送另一段唯一文本 | Node 出现一条 outbound、原始时间正确、未读数不增加、没有新增发送指令 | 未执行 |
| W03 | 网页对测试联系人提交一条人工回复 | 领取、发送串行完成，实际收到恰好一次；queued 最终变为 sent | 未执行 |
| W04 | 执行成功后阻断测试桥接 HTTP 回执，再恢复连接 | pending 留在本地；恢复后只补回执，不再次操作输入；网页变为 sent | 未执行 |
| W05 | 对 W04 的本地 pending 状态停止并重启 agent | 保留数据库后仍只补传回执；测试联系人没有收到第二条 | 未执行 |
| W06 | 使用测试服务端代理/测试夹具暂停 claim 响应超过 60 秒，令领取租约过期，再刷新网页 | 指令和消息均为 unknown，无自动重发；同租约迟到的有效成功回执仍可变为 sent | 未执行 |
| W07 | 有 queued 和 claimed 指令时，在测试后台重新配对设备 | queued 的消息/投递变 failed，claimed 变 unknown；旧 token 失效，新 token 可用；不会自动重发 unknown | 未执行 |
| W08 | 暂停测试知识库或让其返回空结果，再由测试联系人发文本 | 记录变 held，无固定兜底消息；恢复知识库和重启均不会自行发送 held | 未执行 |
| W09 | 在测试代理里延迟一条发送观察/回执，期间测试联系人再发一条新消息，然后解除延迟 | 人工气泡按明确的真实消息 ID 合并；摘要保留新消息，历史消息原始时间正确 | 未执行 |
| W10 | 核实 held 内容仍需回复，停止常驻进程后运行 `python autopilot.py --retry-held` | 命令仅重新入队并退出，不操作企微；再次启动发送必须另行检查队列 | 未执行 |

W06 的故障只能在测试代理/夹具中注入，不调整发送时序、核心模块或额外键鼠事件。无法可靠产生故障时标记“未执行”，保留自动化结果，不能据此填写通过。

恢复回执可在停止常驻 agent 后执行 `python autopilot.py --flush-receipts`。该命令不创建企微 Store、不做输入，仅对当前桥接目标发 HTTP；`dry_run: true` 会跳过。退出码 0 为当前目标无 pending/rejected，1 为仍有待处理，2 为配置缺失。使用 `--list` 核对执行记录；rejected 或 unknown 必须人工检查，不能用删除数据库的方式重发。

真实消息 ID 无法明确回读时仍可能保留临时 `keyboard-<command>` 标识。这类情况无法保证气泡合并，应记录为需人工核对，而不是宣布去重验收通过。图片、语音和附件、修复前已经越过游标的历史消息均不在本批范围。

## 验收记录与发布
