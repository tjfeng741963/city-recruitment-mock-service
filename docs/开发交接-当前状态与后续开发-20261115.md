## 3. 同事反馈的 KB 串厂：解决到了哪里

### 3.1 原问题与根因

同事说 employer_id 已传到位，但命中的是没有工厂归属的 global 工资答案。该判断成立：**请求带 employer_id，不会把 global 正文自动变成该厂事实**。若共享问答仍写固定价格，光修参数不能解决。

本轮同时修了岗位上下文、检索顺序、共享正文准入、内容整理、跨服务发布和问答后处理，不能只用“ID 已传”作为验收标准。

## 8. 业务验收：哪些真正在微信通过

“自动测试通过”“后台落库”“客户端 sent”“用户收到正确内容”是不同证据层次。隔离脚本构造的 sent 不代表企微已送达；旧错误证据也不能被新部署状态覆盖。

| 场景 | 当前结果 | 说明 |
| --- | --- | --- |
| 广州推荐广东城际两基地 | 已按决定实现并测试 | 竹料、陈村均可推荐，不应因设备默认工厂或点位筛选漏掉 |
| 陈村切竹料及工资追问 | 真实链路通过 | 使用各自岗位事实；首卡完整上下文及审核保护已修 |
| 同意邀约、姓名电话收集、正式建档 | 真实链路通过 | 双处摘要；日期不当作同意；保人工备注和运营状态 |
| 下午场次、改期、重复改期 | 真实链路通过 | 不重复新增候选人或预约 |

## 10. 知识库发布与身份映射的剩余工程

### 10.1 当前可用发布范围

受控发布目前仅限 tenant 1 的 **global / vertical 共享 FAQ**。品类按稳定编码匹配；city/employer/position 专属 FAQ 暂时明确拦截，不用数字 ID 相等强行同步。

发布前后至少核对：源版本、目标版本、目标实例、变更预览、事务结果、历史记录、回复侧逐字段读回。失败不能显示成功；内容回滚使用受控快照并重新预览，不用直接改生产 SQL。

实际操作入口为「知识库配置 → 场景问答 → 预览发布」。Node 使用 `REA_BRAIN_URL`、`REA_PROFILE_TOKEN`，目标校验对应 `FLOW_PROFILE_TOKEN` 或管理员身份；只核对变量是否正确配置，不在日志/工单打印值。用 Windows brain 实际地址的 `/api/v1/instance` 对照预览 install_id，不把实例标识当作鉴权。

预览有效期 15 分钟，提交前再次校验两端版本。超时先用同一发布 UUID 查记录/重试，不假定失败后新建一批；过期先查提交结果再重新预览。后台展示最近 30 次记录，目标持久保存快照。回滚只恢复回复库，**配置后台草稿不会随之回退**，再次正常发布会按当前草稿覆盖，因此回滚后仍须解释源/目标差异。

发布通道不迁移旧 kb_entry、岗位事实、设备绑定或流程图，也不认领已有独立 FAQ。岗位材料本轮通过岗位配置出口使用，不属于“所有事实都已通过 FAQ 批量同步”。

### 10.2 扩展发布前的设计要求

1. 为 Node 工厂/岗位/地点与 Python employer/position/point 建明确映射，绑定租户、源系统、稳定标识和有效状态；同名或 ID 相同只作为人工候选。
2. 缺映射、冲突映射、目标已删除或跨租户，均阻止发布并显示可处理的原因；不能静默降成 global。
3. 预览与提交都校验映射版本，覆盖并发修改；保留前后快照、来源和操作者，定义映射变化后的回滚语义。
4. 用两个同城/同名工厂、同厂两基地、不同租户相同数字 ID、目标缺失等反例做 HTTP 与事务测试。
5. 对 18 条资料候选先小批映射、逐字段核对。第一批成功读回及业务验收后再扩大范围，不能一口气把历史图片识别内容作为正式答复发布。

### 12.2 隔离开发与测试

Node 建议与 CI 一致用 22.21.1，Python 3.11。已有虚拟环境可复用，但须确认解释器及依赖；新电脑可按下列方式创建。只在没有生产 `.env` 的开发 checkout 测试，不复制生产连接串。

```powershell

$handoffDb = Join-Path ([IO.Path]::GetTempPath()) ('recruit-handoff-' + [guid]::NewGuid().ToString('N') + '.db')
```

**测试 conftest 会删除测试数据库文件。** `APP_DATABASE_URL` 必须指向新建独立临时库，绝不能指向生产数据库、真实本机业务库或它们的唯一备份。先查看 `backend/tests/conftest.py` 的当前行为；如环境已配置生产变量，另开隔离 shell/checkout，不直接运行上述测试。

`npm ci` 与依赖 Node 的 HTTP 脚本顺序执行，避免安装中删除依赖引发伪失败。隔离脚本自行建随机端口、临时凭据和数据库，不启动真实 agent，见[隔离 HTTP 联调](隔离HTTP联调.md)。

## 13. 发布、回滚和禁止操作

- 改动使用具体路径 `git add`，禁止 `git add .` / `git add -A`；不夹带已有未跟踪缓存或其他人的修改。提交遵守 Conventional Commits。
- push 前按 `AGENTS.md` 完成 npm ci、TypeScript、Node 全量；涉及 Python/发布/迁移补相应 Python、HTTP、PG 检查。PR 和功能分支只检查；合并/push main 自动上线。
- 部署核对两个目标。部署 checkout 处于 detached revision 是可接受状态，以 SHA 为准，不为满足旧文档而强行切普通分支。
- 代码故障用 revert 走流水线；不 force push main，不 reset/clean 真实业务工作区。
- SQLite 备份使用 `scripts/backup-sqlite.mjs`，核对 page_count、表数等实质内容；空库也能 integrity_check 成功，不能只看该项。
