## 已复现的恢复缺陷

用临时 SQLite 账本模拟 08:13 来信、09:31 启动。超过一小时的待发记录和失败记录被转为待核对，内容仍保留。执行现有的显式重排后，下一轮仍按原始来信时间判断，立刻把同一条消息转回待核对。已标为发送成功的记录不会进入这条重排路径。

## 如何逐条恢复

在 Windows 客户端安装目录执行以下命令，先用回复历史找到对应的会话编号和消息编号，然后核对企业微信会话的实际出站。只有核对后确认需要回复，才登记该条恢复。

```powershell
python autopilot.py --list 100
python autopilot.py --retry-message 'S:会话编号' '消息编号' --verified-unsent --reason '已核对该会话出站，确认仍需回复'
```

旧版账本若显示已发，只有确认企微会话没有该回复时才追加 `--legacy-sent`。带有新版企微回读确认的记录受保护。若同一会话有更新的客户消息，以新的消息为准。已有部分内容发出时，由人工补齐缺失部分。仍在等待确认的首句或节点流程要先核对流程进度。

恢复登记后，由原自动回复进程在就绪时处理。恢复只跳过原来信的一小时时限，保留原时间。执行失败时回到待核对，中途退出会留下结果未知。回复历史会列出每次恢复的结果，本机账本 `reply_recoveries` 同时保留操作者、核对说明、原状态和处理时间。日志中的 `reply_recovery_age_hold` 可用于统计因时限暂停的数量。

验收使用隔离 SQLite 覆盖旧版误标已发、新版已确认发送、过期处理、重复触发和中断。回退前备份回复账本和日志。在旧版本启动前核对未完成的恢复记录，旧版会再次应用一小时限制。

用生产失败时的标题截图复现了彩色后缀漏识别。旧裁剪给 OCR 保留深色文字，彩虹表情落在裁剪之外。常驻程序读到的名称少一个字符，因而在输入正文前挂起了回复。此次在同一帧核验完整文字、彩虹和企微外部联系人标识的颜色像素，并排除有相同汉字的竞争昵称和备注。不同缩放或主题下像素不匹配时，记录保留待核对。

位置问答可能在单条文字之外附带原生位置卡。旧回复恢复时，坐标和地址通过校验后随原文字一并生成可点击的导航链接，仍走一次已核验的文字发送。坐标或地址无效、含多段或其他附件的回复保留待核对。
