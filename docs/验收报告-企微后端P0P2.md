## 四、端到端闭环（`test_e2e.py::test_full_loop`）

用 `FakeClient` 顶替 `WeComClient`，其余全部走真实代码路径：

| 步 | 动作 | 断言 |
|---|---|---|
| ① | `ensure_channel` + `sync_channel`（模拟客户发"你们还招人吗？"） | 新建通道、1 个客户、1 条消息 |
| ② | `GET /conversations` | 列表 1 条，`unread=1`，预览为原文 |
| ③ | `POST /conversations/{id}/messages`（人工回复） | 202，`status=queued`，**假客户端一次都没被调用**（证明写接口不发送） |
| ④ | `run_once()` 消费发件箱 | `accepted=1`，`send_text` 收到正确 `external_userid` 与内容 |
| ⑤ | `GET /conversations/{id}/messages` | 顺序 `inbound → outbound`，内容一致 |
| ⑥ | `POST /conversations/{id}/read` | `unread` 归零 |
| ⑦ | 接管后插入一条 AI 投递 | 状态 `blocked`，`blocked_reason="human takeover"`，且**没有发出** |

回调幂等（`test_webhook_returns_success_and_dedupes`）：同一份加密 body 连推两次，都返回 `success`，`webhook_events` 只新增 1 条。

## 七、集成期修掉的三个问题（记录，避免重复踩）

1. **测试隔离**：`test_sync_webhook` 断言 `webhook_events` 绝对条数，单跑通过、全量跑失败（别的用例也写这张表）。改为断言增量。
2. **事件循环绑死**：SQLite 连接池把连接绑在首个事件循环上，pytest 每个用例一个新循环 → `OSError`。改 `NullPool`。
3. **手写 AES**：初版为保证"零依赖"内置了纯 Python AES（56 个测试 + Node 交叉验证通过）。集成时引入 `cryptography`，AES 走 OpenSSL，纯 Python 实现保留为回退路径，157 个测试仍全绿。
