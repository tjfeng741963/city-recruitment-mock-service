## 一、部署结构

```
/srv/apps/city-recruitment-mock-service/
├── source/              # 生产 TS 应用（CI 部署，docker 4222）
├── python-backend/      # ← 新后端：git worktree，分支 feat/python-backend
│   └── backend/
│       ├── app/         # 代码
│       ├── .venv/       # 虚拟环境（Python 3.12 + 运行依赖）
│       ├── .env         # 生产配置（0600，deploy:deploy）
│       └── data/app.db  # SQLite 库
```

**为什么用独立 worktree**：`source/` 会被 CI 每次 `git checkout --detach` 重置，把新代码放进去会被覆盖；worktree 共享同一个 `.git`，但工作区独立，CI 不会碰。

## 三、代码怎么更新

### 现状（临时）

服务器无法 `git pull` 到新分支，本地也推不上 GitHub（本机代理对 github.com 的 CONNECT 大量 502）。所以本次是用 **git bundle** 传输：

```bash
# 本地
git bundle create /tmp/backend.bundle feat/python-backend ^origin/main
# 上传后在服务器
sudo -u deploy git fetch /tmp/backend.bundle feat/python-backend:refs/heads/feat/python-backend
sudo -u deploy git -C /srv/apps/city-recruitment-mock-service/python-backend merge --ff-only FETCH_HEAD
sudo systemctl restart recruit-backend
```

### 目标（推荐）

把 `feat/python-backend` 推到 GitHub 后改为正常拉取：

```bash
# 服务器
cd /srv/apps/city-recruitment-mock-service/python-backend
sudo -u deploy git pull --ff-only
sudo -u deploy backend/.venv/bin/pip install -r requirements.txt   # 若依赖有变
sudo systemctl restart recruit-backend
```

⚠️ 服务器的 deploy key 是**只读**的：`ERROR: The key you are authenticating with has been marked as read only`，所以服务器只能拉、不能推。
