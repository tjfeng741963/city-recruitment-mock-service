# 当前回复逻辑梳理

> 仅梳理现状（截至 2026-11-13），不改代码。目的是把"一轮对话从客户发消息到 AI 回复"的完整链路写清楚，便于排查"回复为什么有问题"。
> 涉及文件：`backend/app/api_flow.py`、`backend/app/services/flow_llm.py`、`backend/app/services/flow_engine.py`、`backend/app/services/kb_placeholder.py`、`backend/app/services/flow_session.py`、`backend/app/services/job_lookup.py`、`backend/app/services/device_scripts.py`、`backend/app/services/profile_push.py`。

---

## 一、整体架构

```
客户消息（企微）
   │  客户端 autopilot 采集 → 4222 agent_messages（inbound）
   │  客户端 brain 调用 8090：
   ▼
POST /api/v1/flow/answer  (api_flow.flow_answer)
   │
   ├─ 1. 加载事件流 → 投影出 state（stage + slots + profile + turns + history）
   ├─ 2. done 重激活（stage==done → 改 ask_interview，保留 slots/profile）
   ├─ 3. KB 命中（仅 ask_interview/collect 阶段、非问候语）→ 取 kb_body + 媒体标记 + 是否重复命中
   ├─ 4. 城市归一 + 真实岗位注入（FLOW_ONLY_SUBWAY 默认开：只推地铁/安检岗）
   ├─ 5. 档案抽取（姓名/手机/省区，模型漏抽时兜底）
   ├─ 6. 运营话术素材（仅未发过岗位的轮次注入）
   ├─ 7. 已发摘要（告诉模型什么说过了）
   ├─ 8. build_material 素材包（单一决策点的输入）
   ├─ 9. a_step：模型决策（一次 LLM 调用）→ apply_result 护栏
   ├─10. 收尾：回声防护 / 媒体兜底 / 完整性补全
   ├─11. 落库（inbound/reply/slot/stage/action/kb 事件）
   ├─12. 副作用：档案推送 / communicating 推送 / 未知问题记录（全部 try/except，失败不影响回复）
   ▼
返回 {reply, parts[], stage, finished, action, slots, profile}
   │  客户端按 parts 逐条发企微 + 贴媒体
   ▼
4222 agent_messages（outbound）
```

**核心原则**：一轮对话 = 一次 LLM 决策。代码只给素材 + 事实护栏，不替模型决定话术（模型不可用时才退到确定性状态机）。

## 二、状态机

阶段定义（`flow_engine.py`）：

| stage | 中文 | 含义 |
|---|---|---|
| `ask_city` | 问城市 | 等客户报城市 |
| `send_info` | 发岗位 | 已有城市，发主推岗位信息 |
| `ask_interview` | 约面试 | 岗位已发，邀约面试 |
| `collect` | 收档 | 客户答应面试，收姓名+手机 |
| `done` | 收尾 | 面试已约 / 客户拒绝 |
| `kb` | 插问标签 | 暂存态，进 a_step 即被改成 ask_interview |

推进顺序：`ask_city → send_info → ask_interview → collect → done`。`_max_stage(slots)` 按"缺什么停在哪"算天花板，模型不能跳过未拿到的槽位（`_STAGE_ORDER` clamp）。

**done 重激活**（`api_flow.py:91`）：客户在 done 后再来消息 → stage 强制改 `ask_interview`（保留 slots/profile，老客户不重新问城市），落一条 `stage_change {from:done, to:ask_interview}` 事件。

## 三、每轮处理 12 步详解

### 步骤 1：加载与投影

```python
events = await store.load_events(session, payload.session_key)
state = store.project(events)   # stage/slots/profile/turns/history/actions
```

事件类型（`flow_session.py`，append-only）：
`inbound` / `reply` / `slot_set` / `stage_change` / `action` / `profile` / `kb_hit` / `reset`。

`reset` 事件会清空投影（`project` 里遇 reset 即 `new_state()`）。**注意**：api_flow 的 done 重激活用的是 `stage_change` 而非 `reset`，所以不会清 slots。

### 步骤 2：done 重激活

仅当 `stage_before == "done"`：
- `state["stage"] = "ask_interview"`（不 new_state，slots/profile 全保留）
- `stage_before` 也改成 `ask_interview`（影响后续 KB 分支判断）

### 步骤 3：KB 命中

条件：`stage_before in {ask_interview, collect}` 且**不是纯问候语**。

问候语正则（`api_flow.py:47`）：
```
^(你好|您好|在吗|在么|嗨|哈喽|hi|hello|老板|师傅|帅哥|美女)[!！。~～,，\s]*$
```
命中问候 → 跳过 KB 查询（避免"你好"被回"刚才回复过你"）。

KB 查询（`kb_placeholder.lookup_entry`）：
- 取所有 `kind=script, status=enabled` 条目
- `keywords_of(title)`：整句 + 前2/3字片段（"体检要自己出钱吗"→"体检"/"体检要"）
- `match(question, title)`：客户问法包含任一关键词即命中
- 城市加权：同城 +3，异城排除，空通配
- 工厂加权：同厂 +5，异厂排除，空通配
- 取得分最高的一条

命中后：
- `kb_body` = 条目正文（含媒体标记 `【图片:x】【视频:x】`）
- `kb_markers` = 正文里所有媒体标记
- `kb_repeat` = 本会话历史里是否已对该 id 落过 `kb_hit` 事件（去重基准）

### 步骤 4：城市 + 岗位

```python
city_hint = extract_city(payload.text) or slots.get("city")
```
- 只在 `ask_city/send_info` 阶段或 slots 无城市时接受改城市（邀约/登记阶段顺口提地名不换岗）
- `lookup_jobs(city)`（`job_lookup.py`，60s 缓存，调 4222 `/agent/jobs`）
- **`FLOW_ONLY_SUBWAY` 环境变量默认 "1"**：过滤 `factory_name/job_title` 含"地铁"或"安检"的岗位；过滤空回退全量防呆
- `set_remote_jobs({city: jobs})` 注入引擎

### 步骤 5：档案抽取

`absorb_profile(slots, text, strict_name=stage==collect)`：从客户文本里抽姓名/手机/省区，模型漏抽时兜底。

### 步骤 6：运营话术素材

仅在 `city_for_jobs` 有值且 `not slots.get("interview_offer_sent")`（还没发过岗位）时：
- `fetch_scripts(device_code)` 拉设备绑定的 config 话术
- `pick_script` 按 stage=send_info + 城市挑一条
- `render_script(content, job)` 渲染（占位符替换）
- 作为 `script_material` 喂给素材包（不直发，由模型决定用不用）

### 步骤 7：已发摘要

告诉模型"什么说过了"：
- `interview_offer_sent` → "该城市主推岗位信息已发过，别整段重发"
- 历史 `kb_hit` 数 → "知识库答复已发过 N 条"
- `booked` → "面试已经约好"

### 步骤 8：build_material 素材包

`flow_llm.py:164`，把模型能看到的全部事实整理成 `Material`：

| 字段 | 内容 |
|---|---|
| `stage` | 当前阶段 |
| `slots` | 槽位（含 city/job_index/booked/interview_at/...） |
| `when` | 下一个面试时间（`next_interview`） |
| `text` | 客户这轮原话 |
| `city` | 城市 |
| `primary` | **主推岗位全字段**（factory_name/job_title/wage_text/hours_text/age_text/welfare_text/place） |
| `other_jobs` | 其余岗位**只给名称**（不给数字，防三段混用） |
| `kb_body` | KB 命中原文 |
| `kb_repeat` | 是否二次命中 |
| `script` | 运营话术素材 |
| `sent_summary` | 已发摘要 |
| `media` | 可用媒体清单（`job_media_markers` 算出，地铁岗 = `【视频:安检工作】`） |
| `booked` | 是否已约 |

### 步骤 9：a_step 模型决策

`flow_llm.py:873`：

```python
async def a_step(state, text, provider, now, kb_answer, material):
    mat = material or build_material(...)
    if provider is None:
        return _deterministic(...)   # 无模型 → 确定性状态机
    raw = await provider.complete(build_messages(...), temperature=0.7, max_tokens=900)
    data = _parse_json(raw)          # 解析模型 JSON
    return apply_result(state, data, text, now, material=mat)
```

- `build_messages`：`SYSTEM_PROMPT` + 历史轮 + 素材包渲染
- 模型输出 JSON：`{reply, parts, stage, slots, profile, action, finished}`
- `apply_result` 落状态 + 跑护栏（见下）

**SYSTEM_PROMPT 要点**（`flow_llm.py:69`）：
- 不自称名字/身份（"陈姐"已删）
- 礼貌直接简洁，像微信真人
- 事实护栏：数字/地址/媒体只能照抄素材，不许编
- 已约好：只答疑/确认/改约，不推销
- 输出 JSON 格式

### 步骤 9.5：apply_result 护栏（`flow_llm.py:718`）

落槽位 → 重建素材 → 跑护栏：

**① 媒体白名单**（`_filter_media`）
- 模型输出的 `【图片:x】【视频:x】` 必须在 `mat.media` 清单里
- 清单外的标记直接删

**② 事实护栏**（`_guard_part` 逐句）
- `_numbers_ok`：工价/年龄/时间/日期/月休的数字串必须在 `_corpus(mat)` 里（素材原文归一后比对）
- `_addresses_ok`：带行政区/道路后缀的地点必须在素材里（问句"哪个区"除外）
- `_leaks_other_job`：分句出现其他岗位的工价/地点/年龄 → 三段不同源 → 删
- `_is_job_sale`（仅 booked）：分句是岗位卡（"厂名:"/"工价:"）或含工价+厂名+招工词 → 删（已约不推销）
- 违规分句剔除，合规的保留（保模型自然措辞）

**③ 三段不同源整轮回退**
- 岗位介绍轮（`primary 有 + 未 booked + 未 offer_sent + stage in send_info/ask_interview`）若有分句被护栏剔除 → 整段回退 `send_info_parts(slots)` 素材原文

**④ offer_sent 置位**
- `_job_info_present`：parts 里出现厂名 + (工价或地点) → 认为岗位真说出去了
- 置 `interview_offer_sent=True`，send_info → ask_interview

**⑤ booked 硬规则**
- `slots.booked=true` → `action=None, stage=done, finished=True`（不许再约/再推）

**⑥ stage clamp**
- `_max_stage(slots)` 算天花板（缺城市→ask_city，缺 offer→send_info，缺同意→ask_interview，缺档→collect，齐→done）
- 模型想跳超过天花板 → 压回天花板

**⑦ action 校验**
- `gave_up` → disqualified + done
- `handoff` → done（不写面试时间）
- `book_interview` → 必须有 name+phone，否则 action=None 退 collect；有则写 interview_at/window/place、booked=true、done

**⑧ collect 纠偏**
- 模型想约（action=None, stage=collect, 未 booked）但回复里没要姓名 → 用 `fallback_step` 补一句要档话术

**⑨ 空回复回退**
- parts 为空（护栏全剔或模型空回）→ `_fallback_result`：
  - booked → `_booked_confirm`（"你之前已经约好面试啦…"）
  - 否则 → `fallback_step`（确定性状态机）

### 步骤 10：收尾护栏（`api_flow.py:236`）

**① 回声防护**
- `len(inbound_text) >= 6 and inbound_text in result.reply` → 模型复读客户原话
- 丢弃，回退 KB 原文（非 repeat）或通用接话"我在的，你想了解哪方面？"

**② 媒体兜底**
- KB 命中带 `kb_markers` 但模型回复里没有媒体标记 → 末尾补回

**③ 完整性补全**（`api_flow.py:256`）
- 条件：`stage_before == "ask_city"` 且 `result.stage in (send_info, ask_interview)` 且未 booked
- 模型回复里没有岗位关键事实（工价/面试地点）→ 用 `send_info_parts` 补全三段（岗位/地点时间+视频/邀约）
- **这是"问完地点就发岗位信息+图片视频"的硬保障**

### 步骤 11：落库

```python
records = []
if flow_reset: records.append((EVENT_STAGE, {from:done, to:ask_interview}))
records.append((EVENT_INBOUND, {text}))
if result.stage != stage_before: records.append((EVENT_STAGE, {from, to}))
records.extend(diff_slots(before, result.slots))      # 槽位变化
records.extend(diff_profile(before_profile, result.slots))
if result.reply: records.append((EVENT_REPLY, {text, parts}))
    if kb_entry_id: records.append((EVENT_KB, {id}))  # 记 KB 已发
if result.action: records.append((EVENT_ACTION, {name, stage}))
await store.append_events(session, session_key, records)
```

### 步骤 12：副作用（全部 try/except，失败不影响回复）

- `profile_push.push`：档案有变化或 action → 推给 4222 `/api/v1/agent/profile`
- `communicating_pushed`：进 collect 时推一次 `{stage: collect}` 让候选人页先出"已答应面试"
- `unknown_questions.record`：KB 没答上的提问记一条给运营补话术

## 四、确定性兜底（无模型时）

`_deterministic`（`flow_llm.py:853`）→ `flow_engine.step`（`flow_engine.py:422`）：

- booked → KB 原文或 `_booked_confirm`
- ask_city：无城市 → 问城市；有城市 → `enter_info_result` 发岗位卡（`send_info_parts` 三段）
- send_info：`enter_info_result` 重发岗位卡
- ask_interview：`is_disagree` → gave_up；`is_agree` 且非问句 → `_agree_interview` → collect；插问 → `fallback_step` 用 kb_answer
- collect：`_book`（姓名手机齐）或继续要档
- done：**静默返回空 reply**（`flow_engine.py:439`，见下方问题点）

岗位卡 `send_info_parts`（`flow_engine.py:285`）：
- 段1：厂名/工价/班次/年龄/吃住
- 段2：面试地点/面试时间 + `job_media_markers`（地铁岗 = `【视频:安检工作】`）
- 段3：邀约问句

## 五、已知问题与隐患（用户反馈"回复有很多问题"的来源）

### 1. 调试 print 残留（`flow_engine.py:440`）

```python
if stage == STAGE_DONE:
    print("DBG_DONE_ENTER text=", repr(text), "stage=", stage)  # ← 昨天调试没清
    return FlowResult(reply="", stage=STAGE_DONE, slots=slots, finished=True)
```
done 阶段进 `step()` 会打调试日志到 stdout，污染 run.log。应删。

### 2. done 静默分支与重激活的冲突

`flow_engine.step` 里 `stage == done` 直接返回空 reply（静默）。但 `api_flow` 的 done 重激活在 a_step 之前把 stage 改成 ask_interview，所以**正常路径**走不到这个静默分支。**例外**：`_fallback_result` 调 `fallback_step` 时若 state.stage 恰好是 done（极端情况），会静默。建议 `flow_engine.step` 的 done 分支也回 `_booked_confirm` 而非空。

### 3. 完整性补全只在 ask_city→发卡轮触发

`api_flow.py:256` 的补全条件：`stage_before == "ask_city"`。意味着：
- 客户在 send_info 阶段说"再说说岗位" → 模型若漏发岗位事实，**不会补全**（因为 stage_before 不是 ask_city）
- done 重激活后（stage_before=ask_interview）客户问岗位 → 也不补全
- 这是有意为之（避免老客户每次都被强发岗位卡），但模型若该答不答就没人兜

### 4. 回声防护门槛偏严

`len(inbound_text) >= 6 and inbound_text in result.reply`：
- 客户说"广州地铁安检多少钱"（≥6字），模型回复"广州地铁安检工资是…" 含客户原话 → 被判回声 → 丢弃整段
- 实际是正常答疑被误杀。建议改为"回复**整段等于**客户原话"或"客户原话占回复 80% 以上"才判回声

### 5. KB 去重变软

重构后 `kb_repeat` 不再用代码短句覆盖，只靠 prompt 提示"这条发过别整段重发"。模型理论上可能重发整段（护栏不拦"重发"只拦"编造"）。无模型兜底时 `fallback_kb = kb_body if not kb_repeat else 媒体标记`，仍防住；有模型时是软约束。

### 6. 媒体兜底可能重复贴

`api_flow.py:248`：KB 命中带 `kb_markers` 且模型回复无媒体标记 → 末尾补 `kb_markers[-1]`（最后一个）。但如果 KB 正文有多个标记（图片+视频），只补最后一个，前面的丢。且 `result.parts` 也只追加最后一个，导致 parts 和 reply 的媒体不一致。

### 7. 地址护栏偏严

`_addresses_ok`：带"区/镇/路/街/社区/工业园/附近"后缀的地点必须能在素材里找到。但素材 place 可能写"番禺南村员岗地铁站附近"，模型说"番禺区"会被判违规（"番禺区"含"区"后缀但素材里是"番禺南村"不等于"番禺区"）。护栏会剔这句。

### 8. 已约答疑的推销误判

`_is_job_sale`：分句含"厂名:"/"工价:"标签 → 推销。但 KB 原文答疑里若出现"厂名：广州地铁安检"（KB 条目正文带厂名）→ 被判推销 → 删。虽然有 `text in kb` 豁免，但 KB 正文若被模型改写几个字就不豁免了。

### 9. done 重激活后 stage 固定 ask_interview

老客户 done 后再来消息 → 强制 ask_interview。如果客户其实是来"问工资"（KB 答疑）→ stage 仍是 ask_interview → 下一轮模型可能又邀约。`booked` 硬规则会拦住再约，但 stage 不变可能让模型困惑。

### 10. 模型 raw 输出未持久化

模型这一轮的原始 JSON（reply/stage/action/slots）和护栏剔除明细**只在内存里算完就丢**。排查"这轮为什么这么回"只能翻 run.log，没有结构化 trace。这正是要做"决策回放页"的动机（见 `docs/对齐-多智能体对话流程设计.md` 与产品设计师的 trace 设计稿）。

### 11. SYSTEM_PROMPT 重复段

`flow_llm.py:69` 和 `:87` 都有"# 说话方式"标题，内容部分重叠（"礼貌直接简洁" vs "像微信真人短句口语"）。模型可能收到冲突信号。建议合并。

### 12. job_media_markers 注释过时

`flow_engine.py:269` 注释还写"地铁岗：面试点图 + 工作视频"，实际已改为只发视频（面试点图已删）。注释应同步。

## 八、一句话总结

**一轮对话 = 投影状态 → 装素材 → 一次 LLM 决策 → 5 道护栏剔违规 → 收尾兜底 → 落库**。

模型决定"说什么"，代码决定"事实对不对、能不能发"。问题主要出在护栏门槛（回声/地址/推销误判）和几处边界（done 静默、补全条件窄、KB 去重变软），以及 trace 没持久化导致排查困难。
