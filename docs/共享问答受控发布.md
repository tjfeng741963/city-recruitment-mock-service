# 共享问答从配置后台发布到实际回复服务

后台的 4222 SQLite 与 Windows 客户端连接的 8090 回复库是两套数据。保存配置只改前者；在「知识库配置 → 场景问答」点击「预览发布」，核对目标地址、实例及逐条差异，再点击「确认发布到回复服务」。只有收到目标服务持久化后的确认，界面才显示成功。

## 本批支持范围

- 发布 tenant 1 的 global / vertical 问答，包括内容更新、启用、停用和删除后的软停用。
- 用 `vertical.code` 找到目标库自己的品类编号；缺失时仅新增品类编码，不覆盖已有品类配置。
- city / employer / position 问答暂时阻止整批发布，不能靠两边相同的数字编号推断实体相同。需要后续建立稳定身份映射再开放。
- 不同步旧 `kb_entry`、岗位事实、设备绑定、流程节点或流程边，不开启节点化路由。
- 仅更新本通道拥有的 FAQ，已有独立 FAQ 不被认领或覆盖。源编号与目标编号由独立归属表关联。

## 校验、并发及恢复

Node 管理员才可预览、发布及读取记录；目标服务要求管理员或已配置且匹配的服务令牌，普通招聘员不能发布。共享工资、厂规及面试材料只能引用受支持的本岗字段，不能夹带默认承诺；停用条目保留原文。

每次预览持久化源内容版本、目标 URL / install_id、目标内容指纹与发布代次、完整待发布快照、差异和操作者。预览有效期 15 分钟。提交前检查后台版本，目标在事务内校验实例、版本并用原子代次更新互斥；竞争、内容变更、非法条目或数据库错误都回滚整批。HTTP 请求不跟随重定向，凭据不出现在响应、审计快照或前端。

发布 UUID 是幂等键；超时不声称成功，可用同一预览重试或查发布记录，目标已提交时返回原确认，不会重复插入。预览过期后先查记录再重新预览。

目标的发布记录持久保存前后快照，后台展示最近 30 次。点击记录的「预览回滚」，查看恢复到该次发布之前的差异，再确认。回滚沿用相同校验、原子事务及幂等流程；新增的问答只停用，不删除历史。回滚只改回复库，配置后台仍保留当前草稿，因此再次正常发布会恢复后台当前配置。

## 配置与核对

Node 使用 `REA_BRAIN_URL` 和 `REA_PROFILE_TOKEN`。目标要求对应 `FLOW_PROFILE_TOKEN` 或管理员身份。生产 Compose 显式指向真正对外的 `http://119.91.113.100:8090`，不能改用 `REA_KB_API_URL` 指向的内部另一份库。发布前将显示的 install_id 与 Windows `config.json` 中 brain 地址的 `/api/v1/instance` 对照；这是实例核对信息，不替代鉴权。

岗位模板渲染从已选 Node 岗位快照取厂名、工资及地址；不再用 Node 的数字编号查询 Python 本地另一套雇主/地址。字段缺失走现有兜底，不借其他岗位补值。

## 验证

- `npm ci`、`npx tsc --noEmit`、`npx vitest run --testTimeout=20000`
- `python -m pytest backend/tests`
- `python scripts/acceptance-smoke.py`
- `python scripts/kb-publication-smoke.py`：启动两套临时 HTTP 服务，覆盖保存、只读预览、实例确认、真实写入读回、重复提交、跨岗位渲染、缺字段、地址来源、源版本冲突、更新、停用与回滚；不运行企微客户端、不发送真实消息。
- CI 独立 PostgreSQL 16 服务执行 `scripts/kb-publication-postgres.py`，真实复现带偏移 datetime 绑定无时区列的失败，并验证修复后发布、重复提交、停用、回滚及审计时间。既有审计列保持 `timestamp without time zone`，统一写入 UTC 无偏移值，接口返回明确 `+00:00`；不依赖只在 SQLite 上通过。

代码部署不自动迁移任何内容。历史 176 条无明确工厂归属的话术仍需逐条核对，不能因为新发布通道上线就视为全库清洗完成。
