# 客户端-服务端链路说明

> 更新：2026-11-04。本文描述当前**实际部署**的架构、配置、启动与排查方法。

## 一、架构总览

```
你的 Windows 电脑（客户端）                         云服务器 119.91.113.100（服务端）
┌──────────────────────────────┐                  ┌────────────────────────────────┐
│ 企业微信 PC 版（已登录）        │                  │ 4222  Node + Vue 配置管理台     │
│   ↑读取本地加密库              │                  │   （SQLite: source/data）       │
│ agent/autopilot.py --watch    │                  │                                │
│   ├ 每 30s 心跳（设备状态）     │──────HTTP──────→ │ 8090  Python FastAPI 后端       │
│   ├ 每 30s 增量上报新消息       │   直连，无隧道    │   （systemd，PG: 5435）         │
│   ├ 拉取待发送指令队列          │                  │   线索判定 / 看板 / 设备管理     │
│   └ 回复内容来自服务器知识库     │                  │   知识库 534 条                 │
│   键鼠模拟发送（8s 冷却）       │                  │ 5435  PostgreSQL（city_recruitment）│
└──────────────────────────────┘                  └────────────────────────────────┘
```

**一个仓库，两处运行**：`agent/`（客户端部分）与 `backend/`（服务端部分）同属
`city-recruitment-mock-service` 仓库 main 分支。客户端只跑采集与发送；数据、判定、看板全在服务器。

## 二、两套系统的分工

| | 4222（Node + Vue） | 8090（Python FastAPI） |
|---|---|---|
| 用途 | 城市/工厂/岗位/话术/**激活模块**配置 | 会话、线索、看板、设备管理 |
| 前端 | `public/` 的 Vue（**唯一前端**） | `/api/v1/leads/board` 单页 |
| 数据库 | SQLite（source/data/app.sqlite） | PostgreSQL 5435（534 条知识库） |
| 常驻方式 | docker 容器 `city-recruitment-app` | systemd `recruit-backend` |
| 账号 | `local-admin` | `admin` |

客户端 autopilot 的**回复内容**和**心跳/上报目标**都是 8090；4222 只是人用的配置界面。

## 四、启动 / 停止

**客户端（你的电脑）**

```
双击  deploy\client\客户端模式.bat        ← 自检配置、查企微、防重复，然后启动
注册  deploy\client\注册开机自启-客户端.bat  ← 开机自动跑（推荐）
```

手动等价命令：

```
cd agent && uv run python autopilot.py --watch
```

**服务器（一般不用动）**

```
sudo systemctl restart recruit-backend      # Python 后端
sudo docker restart city-recruitment-app    # Node 配置台
```

## 五、怎么确认链路是通的

按顺序，任何一步不符合就跳到第七节排查：

```bash
# 1. 服务器可达
curl http://119.91.113.100:8090/healthz            # → {"ok":true,...}

# 2. 设备在线（登录后调）
# 看板 http://119.91.113.100:8090/api/v1/leads/board 里：
#   设备卡显示 online / online，心跳 < 60 秒，顶部无红条

# 3. 本机进程在跑
tasklist | findstr python                          # 有 autopilot 相关进程

# 4. 心跳日志（autopilot 窗口）
#   [心跳] pc-office-01 wecom_state=online 待发 0 → ok=True
```

判定口径：**心跳 ≤ 90 秒**算在线；`wecom_state` 不是 `online` 时客户端会主动停手不发，
看板顶部会出现红条说明原因——这是刻意设计，防止窗口隐藏时还盲点鼠标。

## 六、长任务测试（2026-11-04 实测）

对直连链路连续观测 10 分钟，每 60 秒采样一次：

## 七、故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 看板红条「采集端离线 N 分钟」 | autopilot 没跑 / 网络断 / 服务器挂了 | 先双击客户端模式.bat；再 `curl healthz` |
| 红条「企业微信已退出登录，需扫码」 | 企微被风控踢下线 | 手机扫码登录；**不要让脚本自动重登** |
| 红条「窗口被隐藏，可能已被风控」 | 企微缩到托盘 | 点开企微主窗口；客户端检测到会自动恢复发送 |
| 心跳 ok 但看板 401 | admin 密码不对 | 用本文档第二节的账号 |
| 上报一直 0 条 | 本地库没新消息，或游标已推进 | 正常；新客户发消息后 30s 内会上来 |
| `device_token` 403 | 换过服务器或重置过设备 | 服务器重新注册设备，token 填回 config.json |

## 八、已知边界

1. **8090 是 HTTP 明文**。撞库有 JWT + 随机密码挡着，但长期建议上 443 + 反代。
2. **LLM 未在生产配置**：回复走知识库模板（内容准确、口径统一），配 `APP_LLM_API_KEY` 后自动升级为模型改写。
3. **线索扫描默认关**（`APP_LEAD_WORKER=false`）：到点不自动标「待核实」，开之前先观察判定准确率。
4. **风控是平台级风险**：实测发几条就可能被要求扫码。客户端检测到 `login_required/hidden` 会自动停手，这是保护，不是故障。
