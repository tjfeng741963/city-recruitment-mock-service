# 候选人档案契约（4222 ↔ 8090）

> 目的：把对话里 LLM 抽出的候选人信息，变成前端（4222 Vue）能直接显示的字段。
> **档案必须落到 4222，不是 8090。** 前端使用既有 Vue 产物和 `public/theme/` 扩展，不修改编译 bundle。
> 2026-11-14：正式登记要求同意邀约及城市、工厂、姓名、有效手机齐全；登记摘要同时显示在候选人记录和会话备注。

## 1. 为什么是 4222

| 前端视图 | 读的接口 | 期望字段 |
|---|---|---|
| 对话管理 `/conversations` | `GET /api/v1/agent/conversations` | `name` `phone` `remark` `factory_name` `city` `district` `interview_date` `recruit_status` `state` |
| 候选人员 `/candidates` | `GET /api/v1/agent/candidates` | `name` `phone` `interview_date` `interview_time` `factory_name` `city` `district` `event_type` `status` `registration_text` |

`agent_conversations` 已通过 016/017 迁移保存档案字段；`candidate_events` 保存候选人事件。登记摘要复用现有 JSON 字段，无新增数据库迁移。

## 2. 写入接口（4222 新增）

```
POST /api/v1/agent/profile
{
  "device_code": "pc-office-01",
  "customer_id": "700002",
  "profile": {
    "name": "张三",             // 真实姓名，客户说了才填
    "phone": "13800138000",
    "city": "广州",
    "district": "番禺",
    "gender": "男",             // 男 / 女 / ""
    "age": 32,                  // 没说到就 null
    "record": "无",             // 有 / 无 / ""
    "job_title": "利口福食品厂 普工",
    "factory_name": "利口福食品厂",
    "interview_date": "2026-11-09",   // YYYY-MM-DD，没约就 ""
    "interview_time": "13:00",
    "interview_agreed": true,   // 必须为布尔值；显式 false 优先于 stage
    "stage": "booked",          // asking / offered / collect / booked / interviewed / no_show / gave_up
    "notes": ""                 // 客户原话里的补充（如"要长白班"）
  }
}
→ 200 { "ok": true, "customer_id": "700002", "recruit_status": "invited" }
```

语义：
- 幂等 upsert，同一 `(device_code, customer_id)` 反复调只更新
- `profile` 里缺的键**不覆盖**已有值（部分更新）
- 合并已有资料后，只有同意邀约且 `city/factory_name/name/phone` 齐全才正式登记。手机去除首尾空格后必须匹配 `^1[3-9][0-9]{9}$`。日期不代表同意，也不是登记的必填项。
- 新调用方传布尔 `interview_agreed`；兼容旧调用方在本次请求省略该字段且传 `stage='collect'/'booked'` 时视为已同意。字符串 `"true"` 不算同意，显式 false 优先。后续部分更新保留已保存的同意状态。
- 满足登记条件 → `agent_conversations.recruit_status='invited'`、`state='pending_invite'`，同时 upsert 一条 `candidate_events(event_type='invited')`。重复同步保留事件 id、已有运营标记和其他 JSON 元数据，不重建事件。
- `registration_text` 由 4222 根据合并后的字段生成，格式为 `城市 工厂 姓名 电话`（单个空格分隔），不信任调用方传入的拼接文本。保存在会话 `profile_json.registration_text`、邀约事件 `data_json.registration_text`；GET profile 顶层及候选人列表都会返回它。
- 会话 `remark` 第一行保存自动摘要。再次同步或修改电话时替换原摘要行，保留其余人工备注；`notes/remark` 显式传入时仍按原契约替换人工备注部分，自动摘要只出现一次。未满足登记条件时不新增摘要。
- `stage='collect'` 但资料未齐时仍可保存档案及幂等的 `communicating` 事件；完成登记后该事件置为 `converted`。
- `stage='gave_up'` → `recruit_status='disqualified'`，保存 `candidate_events(event_type='disqualified')`，清除同意标记和会话当前自动摘要。历史邀约事件保留；单独重传旧日期不会恢复登记，重新同意后才可登记。
- `record` 仍表示案底（有/无），禁止复用为登记摘要。
- 会话更新、备注更新、候选人事件 upsert 和沟通中事件转换在同一数据库事务内完成，写入失败整体回滚。

```
GET /api/v1/agent/profile?device_code=&customer_id=
→ { "device_code":..., "customer_id":..., "remark":..., "registration_text":..., "profile": {...}, "updated_at": ... }
```

## 3. 存储

```sql
-- 016_profile.sql
ALTER TABLE agent_conversations ADD COLUMN name TEXT NOT NULL DEFAULT '';
ALTER TABLE agent_conversations ADD COLUMN phone TEXT NOT NULL DEFAULT '';
ALTER TABLE agent_conversations ADD COLUMN remark TEXT NOT NULL DEFAULT '';
ALTER TABLE agent_conversations ADD COLUMN factory_name TEXT NOT NULL DEFAULT '';
ALTER TABLE agent_conversations ADD COLUMN interview_date TEXT NOT NULL DEFAULT '';
ALTER TABLE agent_conversations ADD COLUMN interview_time TEXT NOT NULL DEFAULT '';
ALTER TABLE agent_conversations ADD COLUMN profile_json TEXT NOT NULL DEFAULT '{}';
```

会话列表 `SELECT *` 即可带出这些列，**不改查询也能让前端显示**；`candidate_events` 继续承载候选人员页。

候选人页通过 `public/theme/candidate-registration.js` 扩展原有表格，增加「登记摘要」列；会话页使用已有备注展示，并由 `candidate-registration.css` 支持摘要和人工备注分行阅读。该扩展作为 `public/index.html` 的模块入口，导入现有主 bundle 并同步包装候选人组件，避免独立追加脚本时与首次路由加载竞争。`public/assets/*` 更新后，须同步扩展中的 bundle 文件名及 Vue 导出别名，并回归首次直达、刷新和路由切换。

## 5. 8090 侧职责

- `/api/v1/flow/answer` 每轮额外返回 `profile`（由模型抽取，代码校验：城市/性别/记录只能是白名单值）
- 档案随事件落 `flow_events`（append-only，可回放），`GET /api/v1/flow/state` 能看到
- 由 8090 在流程中把非空 profile 推给 4222 的 `POST /api/v1/agent/profile`（**不依赖客户端改动**）；部分资料也可正常保存，最终建档由 4222 校验。
- `build_profile` 传布尔同意状态；优先读取已选岗位快照，退回时按固定 `position_id` 匹配。无法匹配固定 id 时不猜其他岗位，也不从岗位标题猜厂名。资料不全或未同意时不能只因 book/done 就声明 booked。

- 跟进默认关闭，开启需显式配置
