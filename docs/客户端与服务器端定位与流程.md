# 客户端与服务器端定位与流程

> 更新：2026-11-11
> 适用版本：`feat/kb-align` 分支（flow v2 + 配置分发 + 按设备话术）
> 读对象：新接手的开发 / 运营 / 客户方对接人

---

## 一、一句话定位

| 角色 | 定位 | 部署位置 |
|---|---|---|
| **桌面客户端**（`agent/`） | 企微操作员：用键鼠模拟真人收发消息，本地持有自己那份话术缓存 | 每台跑企微的电脑一台 |
| **业务中枢**（`src/`，4222） | 总库 + 分发 + 对外接口：会话/消息/候选人/设备/话术/城市的唯一存储 | 服务器 Docker |
| **大脑**（`backend/`，8090） | 对话编排 + 知识库 + 档案抽取：决定"回什么、什么时候推进流程" | 服务器 systemd |

三者的关系是**单向依赖**：

```
客户端 ──消息上报/心跳/拉配置──▶ 4222 ◀──档案推送/查岗位── 8090
  ▲                              │
  └────────配置/话术/发送指令────┘
                                   ▲
                     Vue/React 前端─┘（只读 4222，OA 页面）
```

**前端只认 4222**。8090 对前端是隐形的——它所有的产出（档案、候选人事件）都通过 4222 落库后才对前端可见。

## 二、客户端：它是"手"，不是"脑"

### 客户端做什么

| 职责 | 实现位置 | 说明 |
|---|---|---|
| 收消息 | 轮询本地解密库（`collector.py`） | 企微 SQLite 是加密的，本地解密后比对增量 |
| 发消息 | `wecom_io_core/send.py` | 键鼠模拟：Ctrl+F 搜会话 → 清输入框 → 粘贴 → 回车 → 回读校验 |
| 上报 | `autopilot.py` → bridge/ingest | 消息同时报 4222（bridge）和 8090（ingest） |
| 拉配置 | `client.fetch_config` + `remote_config.py` | 心跳周期同步，version 变了热更新 |
| 执行发送指令 | claim → 执行 → receipts | 人工在网页上发的消息也走这条通道 |
| 分批发送 | `parts` 逐条 + 段间 2 秒 | 多段回复（岗位信息/邀约）防折叠防限流 |

### 客户端不做什么（重要边界）

- **不决定回什么**——回复内容全部来自 8090 的 flow 或知识库
- **不存档案**——本地只有 `reply_log.db`（发送记录）和话术缓存，客户档案只在服务器
- **不改发送动作序列**——`wecom_io_core/` 是冻结区，所有可靠性修复都在外层做
- **本地 `config.json` 只是兜底**——服务器下发的配置优先

### 客户端持有的东西

| 文件 | 内容 | 来源 |
|---|---|---|
| `config.json` | 基础参数 + 兜底话术（`pick_reply`） | 人工维护 |
| `config.remote.json` | 服务器下发的参数 + 该设备的话术 | 心跳自动更新 |
| `reply_log.db` | 每条消息的发送状态（sent/failed/skipped/held） | 本地记录 |
| `_decrypted/*.db` | 企微消息解密快照 | 每轮刷新 |

## 三、4222：总库 + 分发 + 对外接口

### 存储（SQLite，全部在这台服务上）

| 表 | 内容 | 谁写入 |
|---|---|---|
| `agent_conversations` | 会话 + 档案列（name/phone/province/city/district/factory_name/interview_date/...） | 客户端上报 + 8090 档案推送 |
| `agent_messages` | 全量聊天记录 | 客户端上报 |
| `candidate_events` | 候选人事件（报名成功/不符合/已签到） | 8090 档案推送（有面试日期时自动建） |
| `bridge_commands` | 待发送指令队列 | 网页人工发送 / 跟进任务 |
| `cities` / `factories` / `service_positions` | 城市（含省）/ 工厂 / 岗位工价吃住 | 运营管理页维护 |
| `device_scripts` | **按设备绑定的话术**（device_code+stage+city 唯一） | React admin 知识库页维护 |
| `unknown_questions` | 客户问了但知识库答不上的问题 | flow 未命中时自动写入 |
| `agent_devices.data_json` | 每台设备的运行参数（interval/cooldown/...） | 网页设备页 |

### 对外接口（按调用方分）

| 调用方 | 接口 | 说明 |
|---|---|---|
| 客户端 | `POST /bridge/devices/:code/{heartbeat,claim,receipts,inbound,outbound}` | 设备 token 鉴权 |
| 客户端 | `GET /bridge/devices/:code/config` | 配置下发，version 热更依据 |
| 前端 | `/agent/*`（conversations/messages/candidates/profile/device-scripts/...） | JWT 鉴权 |
| 8090 | `GET /agent/jobs?city=`（查岗位）、`POST /agent/profile`（推档案）、`POST /agent/unknown-questions`（记未命中） | `X-Profile-Token` 服务间鉴权 |

## 四、8090：大脑——它决定"说什么、何时说"

### 对话流程 v2（地铁账号；工厂账号后续复用同一套）

```
① 加好友 → 问「你投递的是哪个城市」           stage=ask_city
② 说了城市 → 分 2-3 条发岗位信息              stage=send_info
      段1 厂名/工价/班次/年龄/吃住（按城市查真实岗位）
      段2 面试地点 + 时间窗口（默认次日 09:00-11:00）
③ 问「这两天能不能过来面试」                  stage=ask_interview
      答应 → ④  拒绝 → 标记不符合，结束
      插问（体检/住宿/地点）→ 知识库答题，答完继续问
④ 要「姓名 + 手机号」                        stage=collect
      缺一个只追问缺的那个
⑤ 落档案 → 「期待你来面试」                   stage=done
⑥ 之后客户再发消息 → 静默（不再调模型）
```

### 话术三级优先级（防止模型乱说话）

```
1. 设备话术（config.scripts 命中）
   → 占位符 {{factory}} {{wage}} {{place}} {{window}} 由代码替换
   → 整段直发，模型 0 次调用，工价一个字都不会错
2. 知识库 kb_entry（kind='script'）
   → 标题/关键词命中 → 返回话术
   → 未命中 → 兜底「这个我确认一下，稍后回你」+ 记入未知问题
3. 模型生成（DeepSeek）
   → 只负责自然对话、抽取信息、判断意图
   → 三条护栏：不许编工价（数字白名单校验）、槽位没齐不许跳步、
     约面试必须先问过"方便吗"
```

### 会话状态与回放

每轮对话以**事件**形式追加进 `flow_events`（append-only，参考 DeepSeek Harness 的 Session 设计）：
`inbound / reply / slot_set / stage_change / profile / action`。

当前状态（stage、槽位、档案）不是存出来的，是**从头投影**出来的——
出了投诉（"为什么问我两次性别"）可以回放事件看到当时每一步。`reset` 也只是追加一条 reset 事件，历史不删。

## 五、端到端流程（真实场景走一遍）

```
求职者加好友
   │
   ▼
客户："你好"                          ──▶ 8090 flow：ask_city
AI："你好哈，你投递的是哪个城市？"
   │
客户："广州"
   │                                  ──▶ 8090：查城市 → 发岗位（多段）
AI：[1] 联测电子厂在招普工：21元/小时…  ← 4222 jobs 接口返回真实工厂数据
    [2] 面试地点：花都区狮岭镇，明天 09:00-11:00
    [3] 这两天能不能过来面试？
   │
客户："可以，明天上午"
   │                                  ──▶ 8090：ask_interview → collect
AI："好嘞，发一下姓名和手机号，我登记"
   │
客户："王五 13812345678"
   │                                  ──▶ 8090：collect → done（action=book_interview）
AI："登记好了…期待你来面试，到了联系我"
   │
   ├─ 档案推 4222 ──▶ agent_conversations（姓名/电话/省市区/厂/面试时间）
   │                ──▶ candidate_events（报名成功）──▶ OA 候选人员页可见
   ▼
面试日过后
   └─ 跟进任务（reminder-tasks）──▶ 询问工作内容/是否有空（默认关闭，手动触发）
```

## 六、配置与话术：服务器是总库，客户端持有自己的那份

```
运营操作                          服务器                            客户端
────────                        ──────────                       ─────────
管理页录城市/工厂/岗位    ──▶  cities / factories / service_positions
知识库页配设备话术        ──▶  device_scripts(device_code 绑定)
设备页改运行参数          ──▶  agent_devices.data_json
                                  │
                            GET /bridge/devices/:code/config
                            version = 参数与话术的更新时间取新
                                  │
                                  ▼
                        客户端心跳比对 version ──变了──▶ 重拉并热更
                        （interval/cooldown 即时生效，话术即时替换）
```

原则：**服务器优先，本地兜底**。拉取失败客户端照常跑（用上次的缓存或 `config.json`），每次启动只记一行日志，不刷屏。

## 七、当前边界与已知未实现

| 项 | 状态 | 说明 |
|---|---|---|
| 图片/视频发送 | ❌ 占位 | `send.py` 只发文本；方案已定（剪贴板贴图），接口留 `attachments` 恒空 |
| 名单自动发群 | ❌ 未做 | MVP 核心；群聊 `R:` 只上报不处理；等城市简写映射表（深/万/百…）+ 群名 |
| 知识库真实内容 | ⏳ 占位 | 结构全通，话术一条没录；等客户聊天记录 |
| React admin 部署 | ⏳ 未上线 | 本地 build 通过；线上还是旧 Vue 产物 |
| 跟进定时调度 | ⏳ 手动 | `POST /agent/followup/run` 手动触发，无定时器 |
| 两套知识库合并 | ⏳ 一半已完成 | 原版页面读写 `kb_faq` 已在 main（`knowledge-compat.routes.ts`，默认 on，`REA_KB_COMPAT=off` 回落）；剩余：检索优先级统一、存量 `knowledge_items` 迁移后旧表下线 |
