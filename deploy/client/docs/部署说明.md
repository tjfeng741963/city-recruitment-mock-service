# 城市招聘 · Windows 单机版部署说明

适用：一台常开的 Windows 10/11 电脑，后端与企业微信自动回复都跑在本机。
交付目录：`<仓库根>\deploy\client\`。脚本里所有路径都由 `%~dp0` 往上推导到仓库根，**整个仓库目录可以整体搬到别的盘或别的机器**，不需要改脚本。

---

## 1. 前置条件

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 操作系统 | Windows 10 / 11（64 位） | — |
| uv | 已安装且在 PATH | `uv --version` |
| Python | 3.11+（uv 也可以自己准备） | `python --version` |
| 企业微信 PC | 已安装并**已登录** | 手动打开能看到会话列表 |
| 端口 | 8090 空闲 | `netstat -ano \| findstr :8090` |
| 网络 | 能访问 `127.0.0.1:8090`；填了 LLM Key 时能访问模型服务 | — |

安装 uv（任选其一）：

```bat
winget install --id=astral-sh.uv -e
```

或参考 <https://docs.astral.sh/uv/>。装完**重开一个命令行窗口**再执行 `uv --version`。

> 机器不需要公网 IP，也不需要装数据库。数据全在本地 SQLite 文件里。

## 2. 目录结构与数据在哪

```
city-recruitment-mock-service\
├── backend\
│   ├── .env                    ← install.bat 从 config\backend.env.example 生成
│   ├── data\app.db             ← 业务库（客户、会话、线索、设备、知识库）
│   └── .venv\                  ← uv sync 自动创建
├── agent\
│   ├── config.json             ← 手工配置（模板 config.example.json）
│   ├── reply_log.db            ← 回复历史
│   ├── .report_state.json      ← 增量上报游标（删了会重新补最近 24 小时）
│   └── .venv\
├── logs\
│   ├── backend.log             ← 启动脚本写入
│   └── agent.log
└── deploy\client\              ← 本交付包
```

只有两处是「客户数据」，升级时绝对不能删：

- `backend\data\app.db`
- `agent\reply_log.db`

配置也是客户资产：`backend\.env`、`agent\config.json`。

## 3. 安装（只做一次）

1. 双击 `deploy\client\install.bat`。
2. 脚本依次做：
   - `chcp 65001`，避免中文乱码；
   - 检查 `backend\pyproject.toml`、`agent\autopilot.py` 是否存在（确认目录没搬错）；
   - `where uv`，没有就提示装 uv 并退出；
   - 检查 Python ≥ 3.11（PATH 里没有 python 时提示「由 uv 准备」，不算失败）；
   - 检查 8090 是否被占用，被占用直接退出；
   - 在 `backend\` 和 `agent\` 各执行一次 `uv sync`（首次会下载依赖，耐心等）；
   - `backend\.env` 不存在时从 `config\backend.env.example` 复制；已存在则保留；
   - `agent\config.json` 不存在时**只打印待办**，不会生成假 token。
3. 只看检查不装依赖：

```bat
cmd /c install.bat --check-only
```

### 3.1 改管理员与模型 Key

编辑 `backend\.env`：

```ini
APP_SEED_ADMIN_USERNAME=local-admin
APP_SEED_ADMIN_PASSWORD=改成客户自己的密码
APP_LLM_API_KEY=sk-xxxx        # 不填也能跑，会走模板回复
```

- 管理员**只在用户表为空时创建一次**。已经建过号再改这两行不会生效；确需重建，停进程后删 `backend\data\app.db`（会丢业务数据）。
- 密码也可以填 `random`，首次启动会在后端窗口打印随机初始密码。
- 改完必须重启后端。

### 3.2 注册设备、生成 agent\config.json

`agent` 用 `device_token` 向后端证明身份，token 由后端签发，**不能手写**。

**第一步：只启动后端**

```bat
start-all.bat
```

此时 `agent\config.json` 还不存在，脚本只开「后端 :8090」窗口。
等窗口出现 `Uvicorn running on http://127.0.0.1:8090`。

**第二步：换管理员 token**

```bat
curl --noproxy "*" -s -X POST http://127.0.0.1:8090/api/v1/auth/login ^
  -H "Content-Type: application/json" ^
  -d "{\"username\":\"local-admin\",\"password\":\"local-demo-only\"}"
```

返回里的 `access_token` 就是下一步要用的令牌（有效期 8 小时）。

> `--noproxy "*"` 是必须的：本机装了系统代理时，curl 访问 127.0.0.1 也可能被代理接管，导致超时。
> 在 PowerShell 里请写 `curl.exe`（5.1 的 `curl` 是 `Invoke-WebRequest` 的别名），`\"` 转义照旧可用。

**第三步：注册本机设备**

```bat
curl --noproxy "*" -s -X POST http://127.0.0.1:8090/api/v1/devices ^
  -H "Authorization: Bearer 上一步的 access_token" ^
  -H "Content-Type: application/json" ^
  -d "{\"device_code\":\"pc-office-01\",\"name\":\"前台电脑\"}"
```

`device_code` 只能用小写字母、数字、`-`、`_`，重复会返回 409。
返回 JSON 里的 `device_token`（`dt_` 开头）复制出来，只填一次，不要外传。

**第四步：写配置**

```bat
copy agent\config.example.json agent\config.json
```

编辑 `agent\config.json`：

```json
{
  "server": "http://127.0.0.1:8090",
  "device_token": "dt_上一步返回的值",
  "device_code": "pc-office-01",
  "brain": {
    "mode": "kb",
    "base_url": "http://127.0.0.1:8090",
    "username": "local-admin",
    "password": "与 backend/.env 里的管理员密码一致"
  }
}
```

- `device_code` 必须和注册时一致，否则心跳路径对不上。
- `brain.mode`：`kb` 走本地知识库，`fixed` 只用固定文本。
- `tool_path` 只有旧的采集链路（`agent/main.py`）用得到，`autopilot.py` 不读，保持模板值即可。
- 配置里的 `brain.username/password` 是 agent 调后端知识库时登录用的，必须与 `.env` 的管理员一致。

## 4. 启动与验证

```bat
start-all.bat
```

行为：

1. 检查 uv、目录、启动脚本；
2. 8090 已在监听 → 跳过后端，只起自动回复；
3. 否则先开「后端 :8090」窗口，`timeout /t 5` 等它就绪；
4. `agent\config.json` 存在才开「自动回复」窗口；不存在只起后端并提示。

> 两个窗口实际调用仓库根已有的 `start-后端.bat` / `start-自动回复.bat`，没有改动它们；窗口标题和 `logs\` 日志都由这两个脚本负责。

验证清单：

| 检查 | 期望 |
|---|---|
| 两个窗口标题 | `后端 :8090`、`自动回复` |
| `curl --noproxy "*" http://127.0.0.1:8090/healthz` | `{"ok":true,...}` |
| 看板 <http://127.0.0.1:8090/api/v1/leads/board> | 能登录，**顶部没有红色告警条** |
| `agent.log` | 有 `[心跳] ... ok=True` |

看板红条来自后端告警：设备超过 90 秒没心跳就标 `offline` 并出红条。红条消失 = 采集端在线。

停止：

```bat
stop-all.bat
```

先按窗口标题结束两个窗口（连同子进程），再按命令行清理残留的 `autopilot.py` / `app.main:app` python 进程，最后确认 8090 已释放。

### 4.1 状态检查

```bat
status.bat
```

只读，输出四项：8090 监听状态（含 PID）、`python.exe` 进程数、`/healthz` 返回、`logs\` 下两个日志的最后 10 行。

### 4.2 开机自启

右键 `register-autostart.bat` → **以管理员身份运行**。实际执行：

```bat
schtasks /create /tn "城市招聘-自动回复" /tr "\"<...>\start-all.bat\"" /sc onlogon /rl highest /f
```

- 触发条件是**当前用户登录**，不是开机；无人登录的机器不会跑（键鼠模拟必须有桌面会话）。
- `/rl highest` 避免 UAC 拦截；创建任务本身需要管理员权限。
- 取消：右键 `unregister-autostart.bat` → 以管理员身份运行。
- 自启的窗口会留在桌面上，这是正常的；不要最小化「自动回复」窗口。

## 5. 升级

原则：**换代码，不换数据**。

1. `stop-all.bat`；
2. 备份（见第 6 节）；
3. 用新版本覆盖仓库代码，保留：
   - `backend\data\`
   - `backend\.env`
   - `agent\config.json`
   - `agent\reply_log.db`、`agent\.report_state.json`
   - `logs\`（可选）
4. 双击 `install.bat`（重新 `uv sync`，依赖有变化时必需）；
5. `start-all.bat`，按第 4 节验证。

覆盖前建议把旧目录整体改名为 `city-recruitment-mock-service.bak-日期`，出问题能整体退回。

---

## 6. 备份与恢复

**备份**（先 `stop-all.bat`，避免 SQLite 写入中复制）：

```bat
copy backend\data\app.db  D:\backup\app-%DATE%.db
copy agent\reply_log.db   D:\backup\reply_log-%DATE%.db
```

配置一起备份：`backend\.env`、`agent\config.json`。

**恢复**：停进程 → 把文件放回原路径 → `start-all.bat`。

> 不停进程直接复制，可能拿到不完整的库。真要热备份，用 `sqlite3 app.db "VACUUM INTO 'D:/backup/app.db'"`。

---

## 7. 卸载

1. 右键 `unregister-autostart.bat` → 以管理员身份运行（先取消自启）；
2. `stop-all.bat`；
3. 确认没有残留（`status.bat`：0 个 python、8090 未监听）；
4. 删除整个仓库目录。

数据不会留在系统其他地方：库在 `backend\data\` 与 `agent\`，日志在 `logs\`。
如需保留数据，删除前复制第 6 节的两个 `.db`。

## 8. 常见问题

### uv 找不到

脚本报 `PATH 里找不到 uv`。装完 uv 后**必须重开命令行窗口**（PATH 是启动时读取的）。
确认：`where uv` 能输出路径。

### 8090 被占用

```bat
netstat -ano | findstr :8090
taskkill /PID <PID> /F
```

多数情况是上一次的后端没关干净，先跑 `stop-all.bat`。
如果被别的软件占用，改端口需要同时改 `start-后端.bat`、`start-all.bat`、`agent\config.json`、看板地址——不建议现场改，优先腾出 8090。

### 看板红条「采集端离线」

按顺序查：

1. 「自动回复」窗口还在不在？`status.bat` 的 python 进程数是否为 0；
2. `agent\config.json` 的 `device_token` 是否被改过/设备被删（重新注册会换新 token）；
3. `device_code` 与注册时是否一致；
4. `agent.log` 有没有 `[心跳] ... → ok=True`；若全是 `ok=False`，看 `server` 地址和代理设置；
5. 后端是否在跑：`curl --noproxy "*" http://127.0.0.1:8090/healthz`。

心跳失败不会重试，下一轮（30 秒）自动补，恢复后红条会自己消失。

### 企业微信掉线，要扫码

`agent.log` 出现 `[自检] 企微状态 login_required` 或 `not_running`。
手动打开企业微信扫码登录，保持窗口可见。恢复 `online` 后自动继续发送，不用重启 agent。
运行期间不要最小化到托盘、不要锁屏——锁屏后键鼠模拟无法操作桌面。

### 日志中文乱码

用支持 UTF-8 的编辑器打开（VS Code、Notepad++）。
`type` 命令在旧版控制台可能显示乱码，属正常现象，不影响程序。

### 计划任务到点没启动

- `schtasks /query /tn "城市招聘-自动回复"` 看任务是否存在、状态是否 Ready；
- 任务只在**用户登录时**触发，重启后停在登录界面不会跑；
- 目标路径变了（仓库被移动/改名）要重新注册。

### 杀毒软件拦截

agent 会模拟键鼠、读企业微信本地数据，容易被拦。
把整个仓库目录加入杀软白名单，尤其是 `agent\`。

## 9. 已知限制

- **单机单实例**：`backend\data\app.db` 只给本机用，不要两台机器指同一个文件（网络盘更不行）。
- **一个设备一个 token**：换机器要重新注册设备。
- **日志不自动轮转**：长期运行请定期清理 `logs\*.log`；排查完可整目录删掉（会自动重建）。
- **不做授权校验**：本版本没有 License，交付范围靠合同约束。

> 维护提示：本目录的 `.bat` 都是 UTF-8 无 BOM。cmd 解析这种文件时，如果某行以汉字结尾会吞掉下一行，所以这类行末尾统一补了一个空格。手工改脚本时别删它。
