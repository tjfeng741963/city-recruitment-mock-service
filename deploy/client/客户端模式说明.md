# 客户端模式说明

> 适用场景：这台 Windows 电脑只当「客户端」用（跑企业微信 PC 版 + 自动回复采集），
> 后端和数据库都部署在服务器上（`http://119.91.113.100:8090`）。
> 一键启动 = 双击 `客户端模式.bat`。

## 客户端模式 vs 单机模式

| | 客户端模式（推荐） | 单机模式（旧行为） |
|---|---|---|
| 本机跑什么 | 只跑 autopilot（自动回复采集） | 后端 API + 自动回复 |
| 数据在哪 | 全在服务器（119.91.113.100） | 本机 `backend/data/app.db` |
| 看板地址 | http://119.91.113.100:8090/api/v1/leads/board | http://127.0.0.1:8090/api/v1/leads/board |
| 本机 8090 端口 | 空闲，不占用 | 被本地后端占用 |
| 启动脚本 | `客户端模式.bat`（开 1 个窗口） | `start-all.bat`（开 2 个窗口） |

客户端模式的好处：电脑重启后只恢复采集进程，不用管本地数据库迁移和备份；
线上的线索、回复记录天然集中在一台服务器上。

## 首次配置（只做三步）

1. **注册设备**：在服务器管理后台（管理员登录）注册设备，拿到
   `server` / `device_token` / `device_code`。
2. **填 config.json**：把三个字段填进 `agent\config.json`
   （本机已配置：`pc-office-01` 指向 `http://119.91.113.100:8090`，无需再改）。
3. **双击启动**：先登录企业微信 PC 版，再双击 `客户端模式.bat`。

想让开机自动启动：右键「以管理员身份运行」`注册开机自启-客户端.bat`；
反悔就双击 `取消开机自启-客户端.bat`。

## 流水线更新

合并到 `main` 后，GitHub Actions 对同一提交运行测试和 Linux 部署；两者成功后发布该完整提交 SHA 对应的 Windows 客户端包。Win 端不是 Git checkout；已部署的更新器会在 `CloudPilot` 交互登录触发时校验并安装匹配的 Release，然后沿现有隐藏启动器链启动客户端。

更新失败、Release 尚未发布、冻结核心哈希不匹配或机器本地 `login_code.py` 缺失时，更新器停止并且不启动 autopilot。客户配置、回复账本、媒体、日志和解密副本不会随代码包覆盖。

一次性任务迁移见 `bootstrap-client-updater.ps1`；先运行 `-DryRun`，它会显示预期任务动作而不修改任务。当前机器因落点异常处置保持 `CloudPilot` Disabled。bootstrap 保留该状态，合并代码或发布客户端包都不会自动恢复发送任务。

`sync_from_github.py --dry-run` 只保留源码预览；手动 `--apply` 已禁用，客户端写更新由通过 CI 和 Linux 健康检查的 commit Release 负责。

## 怎么验证连上了

1. 浏览器打开看板 <http://119.91.113.100:8090/api/v1/leads/board>，用管理员账号登录。
2. **顶部没有红色「采集端离线」条 = 设备在线**（红条 = 超过 90 秒没收到心跳）。
3. 也可以在服务器侧确认：管理员账号调 `GET /api/v1/devices`，
   应看到 `pc-office-01` 的 `status=online`。

## 常见问题

| 现象 | 处理 |
|---|---|
| 提示连不上服务器 | 先在客户端执行 `curl -s --noproxy * http://119.91.113.100:8090/healthz`，有响应说明网络通，再查 `agent\config.json` 的 `server` 字段 |
| 看板出现红条、消息没人回 | 多半是**企微窗口被隐藏**（最小化到托盘 / 被遮挡后控键失效）。把企业微信窗口点开、保持非最小化，采集会自动恢复 |
| 日志报 token 无效 / 401 | `device_token` 失效了，去服务器重新注册设备，把新的 `device_token` 填回 `config.json`，重新双击启动 |
| 双击后提示「已经在运行」 | 正常防重复保护。想重启采集：关掉「自动回复 · 客户端模式」那个窗口再双击一次 |
| 开机没自动启动 | 检查计划任务：`schtasks /query /tn "城市招聘-客户端" /fo LIST`；重新跑一次注册脚本 |

## 与旧脚本的关系

- `start-all.bat` / `register-autostart.bat`（旧单机模式）**保留可用**，适合没服务器、
  后端也跑在本机的场景。
- 装了客户端模式后，**不要再注册单机模式的「城市招聘-自动回复」计划任务**，
  否则开机会同时拉起本地后端和客户端采集，造成两套数据。
- 如果之前注册过旧任务，用 `unregister-autostart.bat` 取消，再用
  `注册开机自启-客户端.bat` 注册即可。
